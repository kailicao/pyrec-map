Overview

An overview, drafted by Claude from the code (Oct 24, 2026) and revised after the explanations and their review (Oct 25).

What it is. YREC, the Yale Rotating Evolution Code, at the release rp_1: 254 fixed-form Fortran 77 files in src/, about one routine per file. Routines share data through COMMON blocks (243 of them; see the COMMON blocks page) as much as through arguments, so a routine's COMMON blocks matter as much as its calls.

Where to start. main.f is the main program (it has no PROGRAM statement), and its page walks through the whole run. In order, it:

  1. reads the run's settings and tables: PARMIN, then SETUPS;
  2. optionally sets up a Monte Carlo loop over nuclear and solar parameters, and a calibration: of the Sun (SETCAL) or of a star of given $L$ and $T_\mathrm{eff}$ (SETSCAL);
  3. for each "kind card" (one run of the job), reads the starting model (STARIN), writes the headers (WRTHEAD) and sets the first time step (HTIMER);
  4. evolves it model by model. Each step: mass loss (MASSLOSS); mixing, burning and settling (MIX, with KEMCOM and GRSETT); rezoning (HPOINT); the structure, by four levels of the Henyey iteration (CRRECT), where a divergence ends the run (despite a comment about cutting the step, see main.f); convective mixing (MIXCZ); rotation (GETW, FPFT); lithium burning (LIRATE88, LIBURN); the next time step (HTIMER); output (WRTOUT); and the stop conditions;
  5. ends each kind card with PUTSTORE and the calibration checks (CHKCAL, CHKSCAL), and the job with the summaries (WRTMONTE).

What the explanations found. Each page ends with questions for the experts; some are apparent bugs worth reading first, for example: MASSLOSS calls MDOT with one argument too many (BL), so the LMDOT path cannot work as written (massloss.f, mdot.f); the floor on the final step in main.f is $10^{-12}$ of the age, not $10^{-3}$; GRSETT's convergence test ignores negative changes, and its coefficient correction sits one midpoint off; HPOINT keeps the old number of points in MO after rezoning; the opacity margin TOLLAOL (GTLAOL) has no default.

Found in passing. Four files are neither called nor call anything in the code base: blkdta000.f (a BLOCK DATA unit, which sets COMMON blocks' initial values and is linked rather than called), and putyrec7.f, splinnr.f and splnr.f, dead code, to be removed in the overhaul? Two CALLs name routines not in src/: DERIV (most likely a routine passed as an argument) and GETARG (a compiler extension for command-line arguments).

Reading this site. Each routine's section shows the comments above it (YREC's own documentation), its header, its COMMON blocks (each linked to the page that lists every unit sharing it), what it calls and what calls it, and its source with each call linked. Calls are found by reading the code, not by running it. Only src/ is mapped; the .f files under input/, tools for the data tables, are left out. Many files carry changes marked "KC 20…", with the old lines kept as comments beside them; each explanation ends with a "KC's changes" line listing them.

Where the overhaul stands. An overhaul goes in four stages: a documentation site for the old code (this site); the documentation of a new code on the same site, with references to the old one; the new code, with benchmarks (same inputs, same outputs); and a paper. The first stage is complete: every file has an explanation with questions for the code's experts, and every page has been through one round of review and revision. A page's review findings are folded at its end, after the revision they led to; the findings that concern no single page are on the reviews page. The second stage is drafted (Oct 25), and its pages are drafts: the new design in modern Fortran, a first sketch reviewed once and now split into one page per component, and its parallel in Python, pyrec, stubs for the target framework with the plan that leads to it.

Reviews: each group of pages reviewed, with the findings that concern no single page; each page's own are folded at its end.

COMMON blocks: the data the units share (243 blocks).

README

YREC is a modern & efficient public stellar evolution code delivering fast, precise models across a wide spectrum of initial conditions and physical prescriptions. Stellar evolution calculations from YREC have been used to study the physics of solar analogs, evolved giants, low-mass stars, rapidly rotators, and magnetically-active stars. With modern microphysics and prescriptions for rotation, surface magnetism, composition, and mixing, YREC provides a versatile foundation for tackling many different astrophysical problems. In the era of precision stellar astrophysics, YREC offers an open, performant, and lightweight alternative to existing codes.

To get started using YREC, consult the documentation. Try the quick start guide or dive into the interactive YREC web interface.
