The COMMON-block map

In Python: pyrec.

6.4 What replaces the COMMON blocks

Each block's contents go to the type that owns them, grouped by physics. Settings go into Config's parts, state into the objects of Section 3, and the work arrays of one method become private components of its type. Mutable settings change owner: a switch that a routine turns off in the middle of a run (LDIFY, LPTIME, KTTAU) becomes state of the object that turns it off, so Config stays as read. Every one of rp_1's 243 blocks appears once below.

The development branch has already removed the blocks of the options it dropped, consolidated others, and made each remaining block a module (87 …_MOD modules; no COMMON statement is left, its issue 37; Section 7.3). That is the first half of this map: a module per block makes the data explicit but still global. The second half, done type by type in Section 7.2, moves each module's variables into the derived type above and deletes the module.
