Explanation

Purpose. Gets the OPAL95 opacity from the full set of tables (MHP 7/98): a four-dimensional interpolation in $Z$, $X$, $\log T$ and $\log R$ ($R = \rho/T_6^3$). It is the general case, used when the point's composition matches neither pre-interpolated table.

How it fits.

  • Inputs: the full set in /LLOT95A/: the grids TGR, XXG, R0GR, ZZG, the opacities CAPPA2(126,70,19), and for each $Z$ the offset of its first table NZ and its number of $X$ tables NUMXM (loaded by LL95TBL); the indices and weights from GETOPAL95 in /OP95INDX/, /OP95FACT/ (BZ, BX(K,·)) and /OP95EXT/.
  • Who calls it: GETOPAL95, when the point's $Z$ differs from the table's ZTAB, and always when the acoustic depth is computed (LADON and LACOUT; GETOPAL95's comment, JVS 04/11).
  • Outputs: $\kappa$, $\log\kappa$, QOD, QOT, as in OP952D.

The method. For each of the four nearest $Z$ (table offset NZ(JZ+K-1)) and, within it, the four nearest $X$ (JX(K,J), which may differ between $Z$ values since high-$Z$ sets lack some $X$ tables), the $\log R$ and $\log T$ interpolation of OP952D; then four-point interpolation in $X$ (weights BX(K,·)) and in $Z$ (weights BZ), and the conversion of $\partial\log\kappa/\partial\log T$ to constant $\rho$.

Table layout. The header explains it: "tables are incremented in sets of NZ*NX", so the tables of the third metal abundance ($3\times10^{-4}$) are numbers 21–30; at high $Z$ some $X$ tables are missing ($X < 0.9$ for $Z = 0.1$). The offsets NZ (0, 10, …, 100, 109, 118, in LL95TBL) give $Z = 0.06$ and $0.08$ nine slots each and $Z = 0.1$ eight.

Questions for the experts

  1. Tables stored over others? In LL95TBL each table goes to slot NZ(IZ)+IX. For $Z = 0.06$ and $0.08$, which lack table 9 ($X = 0.95$), table 10 ($X = 1 - Z$) then goes to NZ(IZ)+10, which is the first slot of the next $Z$: slot 110 ($Z = 0.08$, $X = 0$) and slot 119 ($Z = 0.1$, $X = 0$). The tables are read with $X$ in the outer loop, so these $X = 0$ tables are read first and overwritten later, while slots 109 and 118 stay empty. This routine reads CAPPA2(JX(K,J)+IZ,…) with the same indexing, so the interpolation is self-consistent for $X = 1 - Z$ but takes $X = 0$ at $Z = 0.08$ and $0.1$ from the wrong table. Is this so, and should table 10 at these $Z$ go to NZ(IZ)+9?

Review (round 1)
  1. Unclear. "as its comment says (JVS 04/11)": the comment is in GETOPAL95, not here. Fix: name GETOPAL95 and the flags LADON, LACOUT; add the general condition ($Z \ne$ ZTAB).
  2. Missing question (apparent bug, in LL95TBL). LL95TBL stores each table at NZ(IZ)+IX, with NZ = 0, 10, …, 100, 109, 118. At $Z = 0.06$ and $0.08$ (no table 9), table 10 goes to NZ(IZ)+10, which is the first slot of the next $Z$: slots 110 and 119, the $X = 0$ tables of $Z = 0.08$ and $0.1$. These are read earlier (the file runs with $X$ outer, as LL95TBL's header check enforces) and so are overwritten; slots 109 and 118 stay empty. OP954D reads with the same indexing, so $X = 0$ at $Z = 0.08$, $0.1$ is wrong in every 4D interpolation that reaches it. Fix: add a question; report to the LL95TBL page's group.
