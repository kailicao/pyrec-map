Explanation

Purpose. PARMIN reads a run's parameters and sets up its input and output. It holds the defaults of nearly every user parameter (in DATA statements), reads the two namelist files (CONTROL, usually yrec8.nml1, and PHYSICS, usually yrec8.nml2), derives some parameters from others, opens most output files and several tables, writes a summary of the run's settings to the .short file, and interprets the "run cards" (the sequence of evolve and rescale steps). It is the code's single place of configuration.

How it fits.

  • Inputs: the two namelist files, named on the command line (GETARG(1) and GETARG(2); JVS 02/11) or defaulting to yrec8.nml1 and yrec8.nml2.
  • Who calls it: the main program in main.f, once, first.
  • What it calls: REMAP, which maps the newer, "more intuitively named" parameters (MHP 6/14, 10/14: TIME_…, TOL_…, FLAG_…) onto the older vectors ATIME, HPTTOL and the like.
  • Outputs:
  • Arguments: 27 table file names (FALEX06, FATM, FMHD1–FMHD8, OPECALEX, …), which the main program passes on to SETUPS and other set-up routines. Since MHP 8/25, file names travel as arguments rather than in COMMON blocks, "as character strings in common blocks can cause problems".
  • COMMON blocks: about 90, almost every parameter block of the code (the site lists them on PARMIN's page). The main ones by topic: input and output (/LUOUT/, /LUNUM/, /CCOUT/, /CCOUT1/, /CCOUT2/); numerics (/CTOL/, /CTLIM/, /INTATM/, /INTENV/, /BURTOL/, /NEWPARAM/); composition (/COMP/, /NEWCMP/, /NEWMX/, /LABEL/, /NEWXYM/); convection and overshoot (/DPMIX/, /CONST3/); settling (/GRAVST/, /GRAVS2/–/GRAVS4/, /CMIXING/); rotation and winds (/ROT/, /VMULT/, /VMULT2/, /SBROT/, /DISK/, /CWIND/, /PMMWIND/, /OVRTRN/, /MAG/); microphysics (/OPALEOS/, /SCVEOS/, /MHD/, /NEWOPAC/, /NWLAOL/, /DEBHU/, /NULOSS/, /CROSS/, /NEWCROSS/, /XSECT/, /BURNSCS/, /WEAK/); atmospheres (/ATMOS/, /ATMOS2/, /ATMOS2C/, /ALATM03/); mass loss (/MASSCHG/); calibration (/CALS2/, /CALSTAR/); the run cards (/CKIND/, /SETT/); and diagnostics (/ACDPTH/, /PULSE/, /PO/, /MONTE/).
  • Files opened: the .short diagnostic file (ISHORT, unit 20), the stored models (ISTOR, with a header if LSTORE), the first model (IFIRST, read), the last model (ILAST), the per-shell file (IMODPT), and as switched on: the track, solar neutrinos, debugging, Milne variables (appended), pulsation files, Monte Carlo files, the conductive opacities, the isochrone file, the OPAL EOS table (one of three) and the acoustic-depth file (…calcad, named after the .short file).
  • Unit numbers: fixed here, from IOWR = 6 (the screen or status file) to 90 (IALEX06); for example the MHD tables are 40–47 and the OPAL EOS table 49.

What it does, in order.

  1. Defaults (DATA). Among them, as their comments state: the cross sections of Solar Fusion II (Adelberger et al. 2011) and their derivatives (S0_…, S0P_…, S0PP_…); Li and Be destruction cross sections (Fowler et al. 1967, Rolfs & Kavanagh 1986, Fowler 1988); the GS98 CNO fractions and $Z/X = 0.02292$ and the Lodders et al. (2021) isotope ratios and light-element abundances; alternative mixtures AAG21, M22P, M22M (Asplund et al. 2021; Magg et al., given as 2021 in the comment); a G&N93 mixture VNEW for the envelope; $L_\odot = 3.8515\times10^{33}$ erg s⁻¹ and $R_\odot = 6.9598\times10^{10}$ cm; the mixing length CMIXL $=1.4$; the burning cutoffs TCUT.
  2. Namelists. Both files are read, then REMAP is called, and both namelists are written to ISHORT.
  3. Derived settings.
  4. Li/Be cross sections given by the user (LXLI6 and so on) become scale factors relative to the defaults, e.g. SLI6 = XSLI6/5.5D3.
  5. Only one OPAL EOS and one low-temperature opacity are kept: a newer one switches the older ones off (2006 over 2001 over the original; Alexander 2006 over Alexander 1995 over Kurucz 1990).
  6. Semiconvection together with any overshoot stops the run.
  7. $T_\mathrm{env} = \tfrac12(T_\mathrm{env,0} + T_\mathrm{env,1})$.
  8. Rotation (LROT): WALPCZ is limited to $[-2, 0]$; LSOLID forces IMPJMOD = 1. For the old wind law (LMWIND false), from the index $\alpha$ (ALFA), as the comments derive: $$\dot J = f_K\, 2.036\times10^{33}\,(1.452\times10^{9})^{\alpha}\left(\frac{\dot M}{10^{-14}}\right)^{1-2\alpha/3}\Omega^{1+4\alpha/3}\left(\frac{R}{R_\odot}\right)^{2-\alpha}\left(\frac{M}{M_\odot}\right)^{-\alpha/3}.$$ For the Matt et al. law (LMWIND), the indices $a, b, c, d, m$ (PMMA…PMMM), preset by AWIND ('K97': Krishnamurthi 1997, $m = \alpha/3$; 'V13': van Saders & Pinsonneault 2013, $m = 0.22$; 'CUS': from the namelist), give the exponents of $\dot J$, each quantity relative to the Sun: $$a_\Omega = 1 + a - 2am + 4mb,\quad a_R = 2 + 5m - 4mc,\quad a_M = -m,\quad a_L = 1 - 2m,\quad a_P = 2md,\quad e_\mathrm{cen} = md,$$ with $a_\tau = 0$ (the $\tau_\mathrm{cz}$ term is now applied in MWIND), $c_2 = 0.0506$, CONSTFACTOR $= f_K\,J_\odot/\Omega_\odot^{a_\Omega}$, and, if WMAX_SUN $< 1000$, the saturation threshold $\Omega_\mathrm{sat} = $ WMAX_SUN $\times\,\Omega_\odot$.
  9. Composition changes: a single species to rescale (LNEWCP, ANEWCP), a CNO mixture (ISETMIX, AMIX, with checks on a custom one) and isotope ratios (ISETISO, AISO), all applied later to the starting model by STARIN.
  10. Settling switches: LDIFZ turns on LDIFY and LTHOUL; LDIFLI turns on LNEWDIF, LDIFY, LDIFZ, LTHOUL, turns off LTHOULFIT, and sets ILAMBDA = 4.
  11. Summary. Tables of "standard" and "current" values, the atmosphere choice (KTTAU 0–5), and the run's description.
  12. Run cards (NUMRUN cards, at most 50): KINDRN = 1 evolves NMODLS models (to an age, a central D, X or Y, or with a fixed time step); 2 rescales the model (mass, $X$, $Z$, core mass) and relaxes it; 3 rescales and evolves.

Design. PARMIN is a 1,461-line routine that is mostly declarations and data. Many parameters live in two places: the namelist, and a COMMON block that other routines read. Several namelist entries are no longer used (see question 6).

KC's changes. 2025-05-30: the elements of /NULOSS/, /OPALEOS/, /NEWPARAM/, /ACDPTH/, /PMMWIND/ and /MAG/ reordered (logical and character variables moved to the end; the same order is used in every routine that shares them), and /MASSCHG3/ commented out (see question 6).

Questions for the experts

  1. The namelist dump is written before ISHORT is opened. WRITE(ISHORT,NML=PHYSICS) and WRITE(ISHORT,NML=CONTROL) come right after the reads, but OPEN(ISHORT,FILE=FSHORT…) and REWIND(ISHORT) come about 100 lines later. The dump probably lands in a default file (fort.20 with gfortran) and is missing from the .short file. Move the dump after the OPEN?
  2. ZENV set from every run card. The last line of the card loop, IF(RESCAL(3,NKIND).GE.0.0D0) ZENV=RESCAL(3,NKIND), runs for every card, including evolve cards, where RESCAL is never set (zero), and for rescale cards with the default RSCLZ = 0 ("0 = use current value"). So ZENV is usually set to 0 here. Is it always reset later (for example ZENV = ZNEW in STARIN), or is this a bug?
  3. A printing slip. WRITE(ISHORT,45) TRIDT,TRIDL/TRIDT/TRIDL evaluates TRIDL/TRIDT/TRIDL $= 1/$TRIDT, so the "current" TRIDL printed is wrong. Probably TRIDT,TRIDL was meant.
  4. Stale "standard" values. Several summary lines print standard values that differ from the DATA defaults (for example ACFPFT "1.000E-20" against $10^{-36}$, ITFP1 "2" against 5, and the line labels repeat). Should they be generated from the defaults, or dropped?
  5. Rescale-and-evolve message. Card type 3 with a previous model prints format 451 ("rescale the previous run's last model"); its own format 551 is commented out.
  6. Unused namelist entries. LPMM, PMMWMAX, ZOPAL952 and ZALEX2 are read from the namelist but are local variables used nowhere else. LSOLWIND is read too, but since /MASSCHG3/ is commented out here it no longer reaches MDOT, which still declares /MASSCHG3/ (DMSUN, DMWSUN, DMWMAX, LSOLWIND); nothing else sets that block, so MDOT's scaled solar wind (MHP 8/10) can no longer be switched on, and its constants (the old DATA line is commented out too) are never set. Intended? DTDIF, DTWIND, HPTTOL and ATIME are superseded by REMAP's new parameters when those are used. Can the old entries be removed, or kept with a warning?
  7. GETARG. It is a compiler extension; Fortran 2003 has GET_COMMAND_ARGUMENT. Minor.
  8. The mixtures' names. The comment cites 'M22M' and 'M22P' as "Magg et al. 2021 (met, phot) A&A 661,140", while the names suggest 2022, and the comment's list of supported mixtures writes M22M',M22P' with a quote missing. Which year is right?
  9. The exponent of $R$ in the Matt et al. law. The comment's derivation gives $\dot J \propto R^{2+5m+4mbc}$, but the code (after JvS 09/25, "removed typo") uses $a_R = 2 + 5m - 4mc$. For 'V13' ($c = 0$) the two agree. For 'K97' ($b = 1$, $c = 2$, $m = \alpha/3$) the code gives $2 - 3m = 2 - \alpha$, the exponent of the old law, while the comment would give $2 + 13m$. The code looks right and the comment stale; confirm, and update the comment?
