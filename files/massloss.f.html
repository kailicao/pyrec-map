Explanation

Purpose. MASSLOSS is the driver for mass loss or accretion in a step (MHP 10/01). It sets the rate $\dot M$ (constant, or from a Reimers formula), computes quantities of the convective envelope and of accreted matter, and calls MDOT to change the model's mass. Sign convention: $\dot M > 0$ is a mass gain (accretion), $\dot M < 0$ a loss. Its header comment: "This is experimental code and valid for Allard atmospheres only" (llp 06/15/2009).

How it fits.

  • Who calls it: the main program, main.f, in a step when LAGE is true (main.f:581–591), before the lithium burning of LIBURN; the main program sets LNEWFIT false just before the call.
  • Inputs: BL ($\log L/L_\odot$), DAGE (Gyr), DELTS (s), the model (HCOMP, HD, HP, HR, HS, HS1, HS2, HT, HJM, OMEGA, M), HSTOT (log of the total mass in g), SMASS (mass in $M_\odot$), TEFFL, JENV (the base of the surface convection zone).
  • Outputs: LNEWFIT, set true only for accretion; the main program then calls GETNEWENV to restore the earlier fitting point (main.f:896). Through MDOT: the changed model, DELTS, SMASS, HSTOT, LNEW, SENVOLD. In COMMON MASSCHG2: SACC and SCEN (MDOT reads SCEN; COEFFT reads only DLOGT and DLOGP, which MDOT sets). In DEUTER: JCZ, the base of the convective envelope (or M if there is none).
  • Calls: ALSURFP (surface pressure from Allard atmospheres), EQSTAT (twice), MDOT.
  • COMMON blocks: MASSCHG (DMDT0, CREIM, LREIMER, LMDOT, COMPACC; set in PARMIN, defaults DMDT0 = −1e−14 $M_\odot$/yr, CREIM = −4e−13, LMDOT and LREIMER false), MASSCHG2, ATMPRT (the surface point from ALSURFP), OVRTRN (TAUCZ, the convective turnover time; the comment at line 60 says it is computed in MIXCZ, but it is now set in TAUCAL and TAUINT), DEUTER, SCRTCH, and the constants CONST, CONST1, CONST2, CONST3.

The method.

  1. If mass change is off (LMDOT false), set LNEWFIT false and return. Otherwise $\dot M$ = DMDT0 (in $M_\odot$/yr, as MDOT converts it).
  2. Radius from $L = 4\pi R^2\sigma T_\mathrm{eff}^4$: $\log R = \tfrac12(\log L - \log 4\pi\sigma - 4\log T_\mathrm{eff})$, with $L$ in erg/s.
  3. Reimers (LREIMER): $\dot M = \eta\,L/(g R)$ with $\eta$ = CREIM and $g = GM/R^2$, all in cgs (see question 3 on the units).
  4. If there is a convective envelope (JENV < M), print TAUCZ (in years) and $R/R_\odot$, and set JCZ = JENV; otherwise set TAUCZ = 0 (in the shared block) and JCZ = M. The envelope's mass $M_\mathrm{cz}$ = SUMDM $= \sum_{j=\mathrm{JENV}}^{M}$ HS2(j).
  5. If $\dot M > 0$ (accretion), set LNEWFIT true, and with $e_\mathrm{acc} = f\,GM/R$ (EACC0; $f$ = FACC = 1), which the comments describe as the kinetic energy per gram of accreted matter (from the virial theorem):
  6. over the convective envelope, the mass-weighted means of $e_\mathrm{acc}[1 + \tfrac12(R/r - 1)]$ (this mean overwrites EACC), of the thermal energy $P\beta/\rho$ (ETHAV), and of the entropy-like quantity $$s = \frac{P\beta}{\rho T}\left(\tfrac32\ln T - \ln\rho\right),\qquad \beta = 1 - \frac{aT^4}{3P}$$ (SCEN; $a/3$ = CA3; $P\beta/(\rho T)$ = RMU is the gas constant over the mean molecular weight);
  7. at the photosphere from ALSURFP and the EOS: SACC, the same $s$;
  8. an alternative surface state "from Stahler 1988", with $\dot M$ in g/s: $P = \frac{\dot M}{4\pi}\sqrt{2f\,g/R^3}$, $T = \big(\tfrac34\,\dot M\,e_\mathrm{acc}/(4\pi R^2\sigma)\big)^{1/4}$ (with EACC0), its $s$ in SACC2;
  9. finally SCEN is set to 0.
  10. Call MDOT with $\dot M$, the mean $e_\mathrm{acc}$, the mean thermal energy, $M_\mathrm{cz}$ and RMU.

Design. It writes TAUCZ (in years) and $R/R_\odot$ to the terminal on every call with a convective envelope. Its locals are SAVEd.

Questions for the experts

  1. Results that are thrown away. SCEN is computed as the envelope's mean entropy and then set to 0 in both branches; SACC2 is computed and not used (the lines using it are commented out); LAlFail from ALSURFP is not checked. What is the intended state?
  2. Allard atmospheres only. ALSURFP is called whatever atmosphere the run uses. Should the routine check the atmosphere choice, or stop otherwise?
  3. Units of the Reimers rate (apparent bug). CREIM multiplies $L/(gR) = LR/(GM)$ in cgs, which is in g/s: for the Sun $L_\odot R_\odot/(GM_\odot) \approx 2.0\times10^{18}$ g/s. MDOT reads the result as $M_\odot$/yr. With the default CREIM = −4e−13 (Reimers' coefficient for $L$, $R$, $M$ in solar units and $\dot M$ in $M_\odot$/yr), the Sun would lose about $8\times10^{5}\,M_\odot$/yr. Should $L$, $R$, $M$ be in solar units here, or CREIM include the conversion?
  4. A debug line. The unconditional WRITE(*,*) TAUCZ/CSECYR, RTOT/CRSUN looks like debugging output.
  5. Arguments with no effect. MDOT never uses the RMU it receives (it recomputes it at JENV), and uses EACC and ETHAV only for ETHNEW and FAC, which it does not use. For a loss the three are stale values from an earlier call (SAVE), or undefined on a first call. Can they be dropped from the interface?
  6. The call to MDOT. It passes 24 arguments starting with BL, while MDOT takes 23 starting with DELTS; so it has been since the repository's first commit. See mdot.f, question 1.
  7. MASSCHG2 names swapped. Here the block ends …, DLOGT, DLOGP; in MDOT and COEFFT it ends …, DLOGP, DLOGT. MASSLOSS does not use the two, so it does no harm now, but a later use here would read the wrong one.

Review (round 1)
  1. Wrong. Output: "LNEWFIT (true when mass changes)". The routine sets LNEWFIT true only when DMDT > 0 (a mass gain, massloss.f:85–86); for a loss it leaves the value the main program set (false, main.f:588). Fix: "true only for accretion; the main program then calls GETNEWENV to restore the earlier fitting point (main.f:896)".
  2. Wrong. "in COMMON MASSCHG2, the entropies SACC, SCEN (read by COEFFT and MDOT)". COEFFT reads only DLOGT and DLOGP from that block (and uses SCEN only in a commented-out line); MDOT reads SCEN. Fix accordingly.
  3. Wrong. "TAUCZ, the convective turnover time, computed in MIXCZ". The comment at line 60 says so, but MIXCZ no longer computes it (its own comment, mixcz.f:101); it is set in TAUCAL and TAUINT. MASSLOSS only prints it, and sets it to 0 in the shared block when there is no convective envelope. Fix: say so.
  4. Wrong. SENVOLD listed as an input; it is an output (set by MDOT, then used by GETNEWENV). Fix.
  5. Missing. The default values (PARMIN): DMDT0 = −1e−14 (a loss; $\dot M > 0$ is a gain), CREIM = −4e−13, LMDOT and LREIMER false. And when it is called: only when LAGE is true (main.f:581–591). Fix: add.
  6. Missing (apparent bug, sharpens question 3). The Reimers branch applies CREIM to $L/(gR)$ in cgs, which for the Sun is $L_\odot R_\odot/(GM_\odot) \approx 2.0\times10^{18}$ g/s, and MDOT reads the result as $M_\odot$/yr. With the default CREIM = −4e−13 (Reimers' coefficient in solar units and $M_\odot$/yr), the Sun would lose about $8\times10^{5}\,M_\odot$/yr. Fix: rewrite question 3 with these numbers.
  7. Wrong (question 5). "Does MDOT use RMU only for accretion?" MDOT never uses the RMU it receives: it recomputes it at JENV before use. Likewise EACC and ETHAV feed only ETHNEW and FAC, which MDOT does not use. For a loss these three are stale (SAVE) or, on a first call, undefined, which is then harmless. Fix: replace question 5 by this point.
  8. Unclear. Step 4's "virial-type energy per gram"; the code's comment speaks of the kinetic energy per gram of accreted matter. Also EACC is overwritten by the envelope mean, while the Stahler temperature uses the first value (EACC0). Fix: use the comment's words; name EACC0.
  9. Unclear (question 6). Fine as is, but say the argument list has been shifted since the repository's first commit (checked: 6cd5673). Fix: one clause.
