Explanation

Purpose. Reads the opacity tables chosen for the run and sets up their interpolation. Its comment: "THIS SUBROUTINE READS IN SPECIFIED OPACITY TABLES AND SET UP SPLINES FOR THE TABLES. WHEN LZRAMP=T OR LDIFZ=T THEN READ IN SECOND SET OF OPACITY TABLES AT DIFFERENT Z."

How it fits.

  • Who calls it: SETUPS, once per run; the file names are passed through (MHP 8/25).
  • What it calls, by the switches in /NEWOPAC/:
  • interior tables: OPAL95, LL95TBL then OP95XTAB (LOPAL95); OPAL92, SETLLO then LL4TH (LOPAL92); LAOL89, RDLAOL then SULAOL (LLAOL89); the pure-Z LAOL table, RDZLAOL then ZSULAOL (LPUREZ, in /NWLAOL/);
  • low-temperature tables, one of: Ferguson et al. 2005, READALEX06 (LALEX06); Alexander 1995, ALXTBL then ALX8TH (LALEX95); Kurucz, SETKRZ (LKUR90).
  • Inputs: XENV (the envelope's $X$, for the tables built at fixed composition) and the file names. Sets L2Z = LZRAMP or LDIFZ (/ZRAMP/, /GRAVS3/) in /NEWOPAC/, which the readers use to decide whether to read a second table.
  • Output: the argument V (the LAOL mix, from RDLAOL), and the tables in the COMMON blocks of the routines called. They are used at run time by GETOPAC.

Questions for the experts

  1. Several interior tables at once. The interior switches are independent IFs, so more than one table can be read (for example OPAL95 and LAOL89). Is that intended, with GETOPAC choosing among them, or should they exclude each other like the low-temperature ones?
