*An overview, drafted by Claude from the code (Oct 24, 2026), revised after the explanations and their review (Oct 25), and moved to the development branch (Oct 27).*

**What it is.** YREC, the Yale Rotating Evolution Code, at its development branch's commit 09c3b9b (Oct 20, 2026): 284 fixed-form Fortran files in `src/`, about one routine per file. 87 of them are modules (`*_mod.f`), which replaced the COMMON blocks of the release `rp_1` (where this site began): routines share data through the modules they `USE` (see the Modules page) as much as through arguments, so a routine's modules matter as much as its calls. Since `rp_1`, the development branch has also removed legacy options (the MHD equation of state, the OPAL 1995 and 2001 equations of state, the Kurucz 1990, LAOL89, Alexander 1995 and OPAL92 opacities, and the Monte Carlo loop), with 58 files, and fixed a number of bugs; each page's explanation ends with a "Changed since `rp_1`" line.

**Where to start.** [main.f](yrec-map/main.f.html) is the main program (it has no PROGRAM statement), and its page walks through the whole run. In order, it:

1. reads the run's settings and tables: [PARMIN](yrec-map/parmin.f.html), then [SETUPS](yrec-map/setups.f.html);
2. optionally sets up a calibration: of the Sun ([SETCAL](yrec-map/setcal.f.html)) or of a star of given $L$ and $T_\mathrm{eff}$ ([SETSCAL](yrec-map/setscal.f.html));
3. for each "kind card" (one run of the job), reads the starting model ([STARIN](yrec-map/starin.f.html)), writes the headers ([WRTHEAD](yrec-map/wrthead.f.html)) and sets the first time step ([HTIMER](yrec-map/htimer.f.html));
4. evolves it model by model. Each step: mass loss ([MASSLOSS](yrec-map/massloss.f.html)); mixing, burning and settling ([MIX](yrec-map/mix.f.html), with [KEMCOM](yrec-map/kemcom.f.html) and [GRSETT](yrec-map/grsett.f.html)); rezoning ([HPOINT](yrec-map/hpoint.f.html)); the structure, by four levels of the Henyey iteration ([CRRECT](yrec-map/crrect.f.html)), where a divergence ends the run (despite a comment about cutting the step, see main.f); convective mixing ([MIXCZ](yrec-map/mixcz.f.html)); rotation ([GETW](yrec-map/getw.f.html), [FPFT](yrec-map/fpft.f.html)); lithium burning ([LIRATE88](yrec-map/lirate88.f.html), [LIBURN](yrec-map/liburn.f.html)); the next time step (HTIMER); output ([WRTOUT](yrec-map/wrtout.f.html)); and the stop conditions;
5. ends each kind card with [PUTSTORE](yrec-map/putstore.f.html) and the calibration checks ([CHKCAL](yrec-map/chkcal.f.html), [CHKSCAL](yrec-map/chkscal.f.html)).

**What the explanations found.** Each page ends with questions for the experts; some are apparent bugs worth reading first. The development branch has already fixed several found at `rp_1` (for example, `MASSLOSS` called `MDOT` with one argument too many, and `SECULR`'s whole-domain option was never switched on). Some that remain: GRSETT's convergence test ignores negative changes, and its coefficient correction sits one midpoint off; in SNEUT, `cap-cap` stands where `cap*cap` is expected; VCIRC's restored μ-current option divides by the speed of light `CC`, which is never set; and the acoustic-depth output (CALCAD) never runs, since nothing sets its switch `LACOUT` (see `ACDPTH_MOD`).

**Found in passing.** Four CALLs name routines not in `src/`: `DERIV` (in MMID, a routine passed as an argument, QENV or QATM) and, in PARMIN, `GETARG`, `GETENV` and `SYSTEM` (compiler extensions for the command line, the environment and the shell).

**Reading this site.** Each routine's section shows the comments above it (YREC's own documentation), its header, the modules it uses (each linked to the module's page, which lists every unit using it), what it calls and what calls it, its source with each call linked, and its Python translation, folded, beside the Fortran. Calls are found by reading the code, not by running it. Only `src/` is mapped; the `.f` files under `input/`, tools for the data tables, are left out. Many files carry changes marked "KC 20…", with the old lines kept as comments beside them; each explanation lists them in a "KC's changes" line.

**Where the overhaul stands.** An overhaul goes in four stages: a documentation site for the old code (this part of the site); the documentation of a new code on the same site, with references to the old one; the new code, with benchmarks (same inputs, same outputs); and a paper. The first stage is complete for `rp_1`, where every file had an explanation with questions for the code's experts and every page went through one round of review and revision; a page's review findings, folded at its end, refer to `rp_1`. On Oct 27 every page was moved to 09c3b9b, each with its Python translation in the current structure (the [pyrec](https://github.com/kailicao/pyrec) repository): the translation is checked only by compiling it, and is to be tested routine by routine against the Fortran. The second stage is drafted, and its pages are drafts: the [new structure](pyrec-map/overview.html), one page per component with its modern-Fortran design and its Python stubs.
