## Explanation

**Purpose.** `NMLPAR_MOD` holds the run's settings that the physics routines read: the 235 members of the `CONTROL` and `PHYSICS` namelists (and a few quantities PARMIN derives from them), shared by 103 routines. It replaces `COMMON/NMLPAR/` (MHP via Claude, 10/14/26), which had gathered, in two steps, the 35 COMMON blocks whose members were all namelist variables (`/ALATM03/`, `/BURNSCS/` … `/WEAK/`) and the namelist members of 27 blocks that also held working variables (such as `/CTOL/`, `/DISK/`, `/DPMIX/`, `/DEBHU/`, `/NEWOPAC/`, `/CWIND/`); those blocks keep only their other members, now in their own modules (such as [`CTOL_MOD`](ctol_mod.f.md#ctol_mod)). The derivation-only namelist variables went to [`NMLBYPASS_MOD`](nmlbypass_mod.f.md#nmlbypass_mod) instead.

**What its variables hold, who sets them, who reads them.** What each member means, with its default, is on YREC's [Control](https://yrec.readthedocs.io/en/latest/namelist_control.html) and [Physics](https://yrec.readthedocs.io/en/latest/namelist_physics.html) namelist pages; this page groups the members by topic and says where they go. [`PARMIN`](parmin.f.md#parmin) reads the namelists into them (`CONTROL` from unit `ISTAND`, `PHYSICS` from `IRUN`); 203 members carry initial values, the namelists' defaults, moved from PARMIN's `DATA` statements. Each member's readers are on the routine pages, and the site's module list names the files that use the module. By topic:
- **Runs and output** (`CONTROL`): the number of runs `NUMRUN` and, per run (arrays of 50), the models `NMODLS`, ages `ENDAGE`, steps `SETDT`, stopping values `END_DCEN`, `END_XCEN`, `END_YCEN`, compositions `XENV0A`, `ZENV0A`, `CMIXLA`, envelope fitting points `LSENV0A`, `SENV0A`, rescalings `RSCLZC`, `RSCLZM1`, `RSCLZM2`, `LFIRST`; the switch `L_ZERODT_PREMS` (default false), which lets a rescale card relax a pre-main-sequence model without ageing it (read by the [main program](main.f.md#file-level)); the output switches (`LSTORE`, `LSTATM`, `LSTENV`, `LSTMOD`, `LSTPHYS`, `LSTROT`, `LSTCH`, `LTRACK`, `LMILNE`, `LPULSE`, `LPOUT`, `ITRVER`, `IPVER`, `NPRTMOD`, `NPRTPT`, `NPOINT`); and the calibration to the Sun or a target (`LCALS`, `LCALST`, `CALSOLZX`, `CALSOLAGE`, `TOLL`, `TOLR`, `TOLZ`, `XLS`, `XLSTOL`, `STEFF`, `SR`, `LTEFF`), which [`SETCAL`](setcal.f.md#setcal), [`SETSCAL`](setscal.f.md#setscal), [`CHKCAL`](chkcal.f.md#chkcal) and [`CHKSCAL`](chkscal.f.md#chkscal) change between runs.
- **Numerics:** the Henyey tolerances and iteration limits (`HTOLER(5,2)`, `FCORR0`, `FCORRI`, `NITER1`–`NITER4`, `LCORR`), the mesh tolerances `HPTTOL(12)`, the time-step controls `ATIME(14)`, `LPTIME`, `TRIDT`, `TRIDL`, `LNEWS`, the integration of the atmosphere and envelope (`ATMERR`, `ATMD0`, `ATMBEG`, `ATMMIN`, `ATMMAX`, `ENV…`, `ATMSTP`, `ENVSTP`, `TENV0`, `TENV1`), the burning network (`CMIN`, `ABSTOL`, `RELTOL`, `KEMMAX`) and the temperature cuts `TCUT(5)`, `TSCUT`, `TGCUT`.
- **Physics:** the opacities (`LOPAL95`, `LALEX06`, `LPUREZ`, `LCONDOPACP`, `ZOPAL951`, `TMOLMIN`, `TMOLMAX`, `OPTOL`, `TOLLAOL`, `LZRAMP`), the equation of state (`LOPALE06`, `LSCV`, `LNUMDERIV`, `LDH`, `ETADH0`, `ETADH1`), the atmosphere (`KTTAU`, `ALATM_FeH`, `ALATM_Alpha`, `LALTPTau100`, `SPOTF`, `SPOTX`, `LSDEPTH`), nuclear rates (`SSTANDARD(17)`, `SLI6`…`SBE93`, `WEAKSCREENING`, `LSNU`, `LNULOS1`), convection and overshoot (`DPENV`, `ALPHAC`, `ALPHAE`, `ALPHAM`, `BETAC`, `LOVSTC`, `LOVSTE`, `LOVSTM`, `LSEMIC`, `LADOV`, `LOVMAX`), diffusion and settling (`LDIFY`, `LDIFZ`, `LDIFLI`, `LTHOUL`, `LTHOULFIT`, `LNEWDIF`, `FGRY`, `FGRZ`, `GRTOL`, `NITER_GS`, `DT_GS`, `XMIN`, `YMIN`, `ILAMBDA`, `CSTMIXING`, `CSTDIFFMIX`), mass loss and accretion (`LMDOT`, `DMDT0`, `FCZDMDT`, `FTOTDMDT`, `COMPACC(15)`, `LREIMER`, `CREIM`, `LSOLWIND`), the starting composition (`VNEW(12)`, `FRAC_C`, `FRAC_N`, `FRAC_O`, `R12_13`, `R16_18` (whose default looks swapped with `R16_17`'s: [starin.f, suspected bug 3](starin.f.md#b3)), `XH2_INI`…`XBE9_INI`), and the helium flash (`LKUTHE`).
- **Rotation:** the switches `LROT`, `LINSTB`, `LSOLID`, `IMPJMOD`, `LNOJ`, `LJDOT0`, `LDIFAD`, `LVFC`, `LWNEW`, `WNEW`, `WALPCZ`, the transport factors (`FW`, `FC`, `FES`, `FGSF`, `FMU`, `FSS`, `RCRIT`, `FESC`, `FSSC`, `FGSFC`, `IES`, `IGSF`, `IMU`, `CODM`, `LCODM`), the diffusion steps (`DTWIND`, `DTDIF`, `DJOK`, `ITDIF1`, `ITDIF2`, `LEXCOM`, `LTRIST`), the moment of inertia (`ACFPFT`, `ITFP1`, `ITFP2`), disk locking (`LDISK`, `TDISK`, `PDISK`) and the wind laws (`WMAX`, `PMMSOLP`, `PMMSOLW`, `PMMSOLTAU`, `LMWIND`, `LROSSBY`, `LBSCALE`).
- **Derived by PARMIN** (in no input namelist; written in its output-only `DERIVED` namelist): the wind law's exponents and factor (`EXMD`, `EXW`, `EXTAU`, `EXR`, `EXM`, `EXL`, `EXPR`, `CONSTFACTOR`, `EXCEN`), `INEWCP`, `LREL`, `KTTAU0`, `LTTAU`, `LMIXTURE`, `LISOTOPE`.
- **Changed during a run**, despite being inputs: [`REMAP`](remap.f.md#remap) overwrites `HPTTOL`, `ATIME`, `LPTIME`, `DTWIND`, `DTDIF` (with `LNEWVARS`) and `SSTANDARD` (with `LNEWNUC`); the calibration routines the per-run arrays; [`CALCAD`](calcad.f.md#calcad), [`STITCH`](stitch.f.md#stitch), [`WRTMOD`](wrtmod.f.md#wrtmod), [`GETNEWENV`](getnewenv.f.md#getnewenv) and [`STARIN`](starin.f.md#starin) the integration steps `ATM…`, `ENV…`; [`ENVINT`](envint.f.md#envint) and [`SURFBC`](surfbc.f.md#surfbc) `KTTAU`, `LTTAU`, `LSTATM`; [`MDOT`](mdot.f.md#mdot) `LMDOT`; [`MIX`](mix.f.md#mix) and [`ROTMIX`](rotmix.f.md#rotmix) `LDIFY`; [`CHECKJ`](checkj.f.md#checkj) `ACFPFT` (temporarily); STARIN `MCORE`, `FCORE`; the [main program](main.f.md#file-level) `ITDIF1`, `LPULSE`, `END_DCEN`, `END_YCEN`.

**Members without an initial value.** [Where Namelist Variables Live](https://yrec.readthedocs.io/en/latest/namelist_modules.html) describes the namelists' defaults as the module's initializers; 32 of the 235 members have none. 15 are derived by PARMIN (above); the other 17 are inputs: the per-run `XENV0A`, `ZENV0A`, `CMIXLA` (PARMIN stops the run if a `CMIXLA` it uses is not positive), the calibration targets `XLS`, `XLSTOL`, `STEFF`, `SR`, the output switches `LSTATM`, `LSTENV`, `LSTMOD`, `LSTPHYS`, `LSTROT`, the Allard atmosphere's `ALATM_FeH`, `ALATM_Alpha`, `LALTPTau100`, and the opacity settings `LOPAL95`, `ZOPAL951`. Unless the namelist sets them, they start at whatever the compiler gives a saved variable, in practice zero or false. The module's header still counts "202 of the 234 members" ([line 19](https://github.com/yreclab/yrec/blob/7be4133/src/nmlpar_mod.f#L19)), from before `L_ZERODT_PREMS`.

> **Question** ([lines 37–39](https://github.com/yreclab/yrec/blob/7be4133/src/nmlpar_mod.f#L37-L39), [lines 116–118](https://github.com/yreclab/yrec/blob/7be4133/src/nmlpar_mod.f#L116-L118), [lines 155–158](https://github.com/yreclab/yrec/blob/7be4133/src/nmlpar_mod.f#L155-L158), [lines 162–166](https://github.com/yreclab/yrec/blob/7be4133/src/nmlpar_mod.f#L162-L166), [line 238](https://github.com/yreclab/yrec/blob/7be4133/src/nmlpar_mod.f#L238), [line 243](https://github.com/yreclab/yrec/blob/7be4133/src/nmlpar_mod.f#L243)). **Inputs without defaults.** The 17 input members listed above (among them `LOPAL95`, which the documentation recommends, and the output switches `LSTATM`, `LSTENV`) have no initializer, so an unset one relies on the compiler zeroing static storage, which Fortran does not guarantee. Should they get explicit initializers (`.FALSE.`, `0.0D0`), as the documentation's description of the module implies, or are they meant to be required in every namelist? With gfortran, ifort, and ifx (the compilers `src/Makefile` names), saved module data without an initializer sits in zero-filled static storage, so each reads as `.FALSE.` or 0 today; a list of which of the 17 are read in a run whose namelists do not set them, and of what each one's intended default is, would settle whether any is a bug (only one whose intended default is not zero or false).

**Design.** A blanket `USE NMLPAR_MOD` in each of the 103 routines, so every routine sees all 235 settings; the module makes the namelists global state by design. The header says the initializers' literals are copied verbatim from the `DATA` statements (single-precision ones such as `CSTMIXING = 1.0` included), so that no stored value changes.

**Changed since `rp_1`.** New file: the namelist members of 62 COMMON blocks as one module, with their defaults moved from PARMIN's `DATA` statements.

**Changed since `09c3b9b`.** One new `CONTROL` member, `L_ZERODT_PREMS` (now 235 members, 203 with initial values), read in main.f.

**Changed since `a8a5950`.** `LOVMAX` now defaults to `.TRUE.` (it is read only when `LOVSTC` is true), so core overshoot is capped by `BETAC` of the core's size unless a deck turns the cap off.
