## Explanation

**Purpose.** `PARMIN` reads a run's parameters and sets up its input and output. It holds the defaults of a few user parameters (most defaults are now initializers in the modules), reads the two namelist files (`CONTROL`, usually `yrec8.nml1`, and `PHYSICS`, usually `yrec8.nml2`), expands placeholders in file names, derives some parameters from others, opens most output files and several tables, writes the run's settings to the `.short` file, and interprets the "run cards" (the sequence of evolve and rescale steps). It is the code's single place of configuration.

**How it fits.**
- **Inputs:** the two namelist files, named on the command line (`GETARG(1)` and `GETARG(2)`; JVS 02/11) or defaulting to `yrec8.nml1` and `yrec8.nml2`; the code's version and git hash, `YRECVER` and `GITHASH` (arguments, from [[version.f#SETVERSION|SETVERSION]] through the main program; formerly `/VERSION/`); the environment variables `YREC_INPUT`, `YREC_START` and `YREC_OUTPUT`, if set.
- **Who calls it:** the main program in [[main.f|main.f]], once, first.
- **What it calls:** [[#EXPAND_VALUE|EXPAND_VALUE]] (in this file), the shell through `system` (`mkdir -p` for the output folder), and [[remap.f#REMAP|REMAP]], which maps the newer, "more intuitively named" parameters (MHP 6/14, 10/14: `TIME_…`, `TOL_…`, `FLAG_…`) onto the older vectors `ATIME`, `HPTTOL` and the like.
- **Outputs:**
  - **Arguments:** 12 table file names (`FALEX06`, `FALLARD`, `FATM`, `FFERMI`, `FLIV95`, `FPATM`, `FPENV`, `FPMOD`, `FPUREZ`, `FSCVH`, `FSCVHE`, `FSCVZ`), which the main program passes on to [[setups.f#SETUPS|SETUPS]] and other set-up routines. Since MHP 8/25, file names travel as arguments rather than in COMMON blocks, "as character strings in common blocks can cause problems".
  - **Modules:** 11, almost all of them for the run's parameters. The namelists read straight into module variables: `NMLPAR_MOD` holds those the physics routines read, `NMLBYPASS_MOD` those that only set others (the cross sections, the `TIME_…` and `TOL_…` parameters for `REMAP`, the wind-law indices), and `CONSTANTS_MOD` (`CLSUN`, `CRSUN`, and `CLN`, `CC13`, `CC23`, `C_2` set here) and `INTPAR_MOD` (`STOLR0`, `IMAX`, `NUSE`) a few more. The others: `IOUNITS_MOD` (every unit number), `RUNLOOP_MOD` (the run cards: `RESCAL`, `IRESCA`, `LENDAG`, `LSETDT`), `COMP_MOD` (`ZENV`), `CCOUT_MOD` (`LPHHD`), `ACDPTH_MOD` (`LACOUT`), `LABEL_MOD` and `NEWOPAC_MOD`. The site's `modules.html` lists every module and its users.
  - **Files opened:** the `.short` diagnostic file (`ISHORT`, unit 20), the stored models (`ISTOR`, with a header if `LSTORE`), the first model (`IFIRST`, read), the last model (`ILAST`), the per-shell file (`IMODPT`), and as switched on: the track, solar neutrinos, debugging, Milne variables (appended), pulsation files, the conductive opacities, the OPAL 2006 EOS table, the acoustic-depth file (`…calcad`, named after the `.short` file) and, always, the sound-speed file `FSOUND` (default `Csound.dat`, unit `ISOUND`), which WRTMOD writes when `LSOUND` is on. Before that it creates the output folder, the path of `FTRACK` up to its last `/`.
  - **Unit numbers:** fixed here, from `IOWR = 6` (the screen or status file) to 90 (`IALEX06`); for example the OPAL EOS table is 49, and `ISOUND` is 500.

**What it does, in order.**
1. **Defaults.** Most are now initializers in the modules (`NMLPAR_MOD`, `NMLBYPASS_MOD`, `CONSTANTS_MOD`, `INTPAR_MOD`); `PARMIN`'s own `DATA` keep those of the run cards, the mixture table, `ALFA`, `FK`, `WMAX_SUN`, `AWIND`, `FSOUND` and blank file names. Among the defaults, as their comments state: the cross sections of Solar Fusion II (Adelberger et al. 2011) and their derivatives (`S0_…`, `S0P_…`, `S0PP_…`); Li and Be destruction cross sections (Fowler et al. 1967, Rolfs & Kavanagh 1986, Fowler 1988); the GS98 CNO fractions and $Z/X = 0.02292$ and the Lodders et al. (2021) isotope ratios and light-element abundances; alternative mixtures `AAG21`, `M22P`, `M22M` (Asplund et al. 2021; Magg et al., given as 2021 in the comment); a G&N93 mixture `VNEW` for the envelope; $L_\odot = 3.8515\times10^{33}$ erg s⁻¹ and $R_\odot = 6.9598\times10^{10}$ cm; the burning cutoffs `TCUT`. The mixing length has no default any more: the old `CMIXL` $=1.4$ never reached the run, which takes `CMIXL = CMIXLA(NK)` in the main program for each run card.
2. **Namelists.** Both files are read and `REMAP` is called. Then `EXPAND_VALUE` expands a leading placeholder in each file name, and the output folder is created.
3. **Derived settings.**
   - Li/Be cross sections given by the user (`LXLI6` and so on) become scale factors relative to the defaults, e.g. `SLI6 = XSLI6/5.5D3`.
   - Semiconvection together with any overshoot stops the run.
   - **Rotation** (`LROT`): `WALPCZ` is limited to $[-2, 0]$; `LSOLID` forces `IMPJMOD = 1`. For the old wind law (`LMWIND` false), from the index $\alpha$ (`ALFA`), as the comments derive:
$$\dot J = f_K\, 2.036\times10^{33}\,(1.452\times10^{9})^{\alpha}\left(\frac{\dot M}{10^{-14}}\right)^{1-2\alpha/3}\Omega^{1+4\alpha/3}\left(\frac{R}{R_\odot}\right)^{2-\alpha}\left(\frac{M}{M_\odot}\right)^{-\alpha/3}.$$
     For the Matt et al. law (`LMWIND`), the indices $a, b, c, d, m$ (`PMMA`…`PMMM`), preset by `AWIND` ('K97': Krishnamurthi 1997, $m = \alpha/3$; 'V13': van Saders & Pinsonneault 2013, $m = 0.22$; 'CUS': from the namelist), give the exponents of $\dot J$, each quantity relative to the Sun:
$$a_\Omega = 1 + a - 2am + 4mb,\quad a_R = 2 + 5m - 4mc,\quad a_M = -m,\quad a_L = 1 - 2m,\quad a_P = 2md,\quad e_\mathrm{cen} = md,$$
     with $a_\tau = 0$ (the $\tau_\mathrm{cz}$ term is now applied in [[mwind.f#MWIND|MWIND]]), $c_2 = 0.0506$, `CONSTFACTOR` $= f_K\,J_\odot/\Omega_\odot^{a_\Omega}$, and, if `WMAX_SUN` $< 1000$, the saturation threshold $\Omega_\mathrm{sat} = $ `WMAX_SUN` $\times\,\Omega_\odot$.
   - **Composition changes:** a single species to rescale (`LNEWCP`, `ANEWCP`), a CNO mixture (`ISETMIX`, `AMIX`, with checks on a custom one) and isotope ratios (`ISETISO`, `AISO`), all applied later to the starting model by [[starin.f#STARIN|STARIN]].
   - **Settling switches:** `LDIFZ` turns on `LDIFY` and `LTHOUL`; `LDIFLI` turns on `LNEWDIF`, `LDIFY`, `LDIFZ`, `LTHOUL`, turns off `LTHOULFIT`, and sets `ILAMBDA = 4`.
4. **Summary.** A line of tolerances and rotation settings is written first, right after the semiconvection check. After the derived settings, the `PHYSICS` and `CONTROL` namelists are written to `ISHORT` as read, and the output-only namelist `DERIVED` with the values derived above (the wind-law exponents, the settling switches, the mixture, `LREL`, …). Then the mixing lengths are checked: each `CMIXLA` entry the run uses (only `CMIXLA(1)` under solar calibration, `LCALS`, otherwise the first `NUMRUN`, at most 50) must be positive, or the run stops. Then the atmosphere choice (`KTTAU` 0–5), and the run's description with the version line (`# YREC v…`, also written at the head of the `.store` file and the track).
5. **Run cards** (`NUMRUN` cards, at most 50): `KINDRN = 1` evolves `NMODLS` models (to an age, a central D, X or Y, or with a fixed time step); `2` rescales the model (mass, $X$, $Z$, core mass) and relaxes it; `3` rescales and evolves.

**Design.** `PARMIN` is a 1,508-line routine that is mostly comments, declarations and data. A parameter now lives in one place, the module variable the namelist reads into. A few namelist entries are still unused (see question 3).

**KC's changes.** 2025-05-30: the elements of `/NULOSS/`, `/OPALEOS/`, `/NEWPARAM/`, `/ACDPTH/`, `/PMMWIND/` and `/MAG/` reordered (logical and character variables moved to the end; the same order is used in every routine that shares them), and `/MASSCHG3/` commented out (see question 3). These blocks have since become modules or been removed.

**Changed since `rp_1`.** The namelists read into modules (`NMLPAR_MOD`, `NMLBYPASS_MOD`), where most defaults now are; the removed options are gone (the MHD and OPAL 1995/2001 equations of state, the OPAL92, Kurucz 1990, LAOL89 and Alexander 1995 opacities, Monte Carlo, isochrones), and with them 15 file-name arguments; `YRECVER` and `GITHASH` are new arguments, printed and written as a version line; file names may start with a placeholder (`EXPAND_VALUE`, new), and the output folder is created; the sound-speed file is opened here; the hand-written summary tables are replaced by namelist echoes after `ISHORT` is opened, with a new `DERIVED` namelist; `TENV` is no longer set (ENVINT computes it); the default `CMIXL` is removed and `CMIXLA` is checked; `PMMM = 0.22` and `C_2 = 0.0506` are now double-precision constants; `LPMM`, `PMMWMAX`, `ZOPAL952` and `ZALEX2` are no longer namelist entries. Settled: the namelist dump before `OPEN(ISHORT)`, the printing slip in `TRIDT`, `TRIDL` and the stale "standard" values (old questions 1, 3, 4), and part of old question 6 (the unused entries; `LSOLWIND` now reaches MDOT).

## Questions for the experts

1. **`ZENV` set from every run card.** The last line of the card loop, `IF(RESCAL(3,NKIND).GE.0.0D0) ZENV=RESCAL(3,NKIND)`, runs for every card, including evolve cards, where `RESCAL` is never set (zero), and for rescale cards with the default `RSCLZ = 0` ("0 = use current value"). So `ZENV` is usually set to 0 here. Is it always reset later (for example `ZENV = ZNEW` in `STARIN`), or is this a bug?
2. **Rescale-and-evolve message.** Card type 3 with a previous model prints format 451 ("rescale the previous run's last model"); its own format 551 is commented out.
3. **Unused namelist entries.** `DTDIF`, `DTWIND`, `HPTTOL` and `ATIME` are superseded by `REMAP`'s new parameters when those are used. Can the old entries be removed, or kept with a warning? (`LSOLWIND` now reaches [[mdot.f#MDOT|MDOT]] through `NMLPAR_MOD`, but MDOT's scaled solar wind stays inert: its constants `DMSUN`, `DMWSUN`, `DMWMAX` are zero, and a guard skips the branch; MDOT's page.)
4. **`GETARG`.** It is a compiler extension; Fortran 2003 has `GET_COMMAND_ARGUMENT`. Minor.
5. **The mixtures' names.** The comment cites `'M22M'` and `'M22P'` as "Magg et al. 2021 (met, phot) A&A 661,140", while the names suggest 2022, and the comment's list of supported mixtures writes `M22M',M22P'` with a quote missing. Which year is right?
6. **The exponent of $R$ in the Matt et al. law.** The comment's derivation gives $\dot J \propto R^{2+5m+4mbc}$, but the code (after JvS 09/25, "removed typo") uses $a_R = 2 + 5m - 4mc$. For 'V13' ($c = 0$) the two agree. For 'K97' ($b = 1$, $c = 2$, $m = \alpha/3$) the code gives $2 - 3m = 2 - \alpha$, the exponent of the old law, while the comment would give $2 + 13m$. The code looks right and the comment stale; confirm, and update the comment?
7. **The output folder.** The loop that finds the last `/` in `FTRACK` leaves `LAST_SLASH_IDX` unset when there is none (a saved local, so it keeps a value from before, or its initial one), and `mkdir -p` runs even when `LTRACK` is off and no track is written. Should a name without a folder mean the current folder, explicitly? `system` and `getenv` are compiler extensions too (see question 4).

### EXPAND_VALUE

Replaces a placeholder at the start of a file name, `{YREC_INPUT}`, `{YREC_START}` or `{YREC_OUTPUT}`, by the value of the environment variable of that name, or, if it is not set, by a default: `../../input`, `../../startmodels` or `output`. A placeholder elsewhere in the name is left as it is.
