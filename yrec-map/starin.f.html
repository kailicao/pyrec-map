Purpose

STARIN provides the starting model of each run of a job: it reads the initial stellar model from a file, or keeps the one in memory, then prepares it for evolution. Along the way it can change the model's composition, extend the model toward the centre, rescale it, move the envelope's fitting point, and it computes the shell masses, the rotation quantities, the surface composition and the first convection-zone quantities.

How it fits

  • Inputs: the model file on the unit IFIRST (IOUNITS_MOD), opened by the set-up routines; its first four characters say its format, NMOD (YREC7) or MOD2 (MODEL2). The run's mixing length CMIXL is an argument, and COMPMIX (the initial model's composition code, set by the readers) is passed through to them. The run's settings come through modules filled by PARMIN and SETUPS: NMLPAR_MOD (the namelist: LFIRST, LCORE, MCORE, FCORE, the mixture controls, LROT, LWNEW, WNEW, HPTTOL, the spot parameters, VNEW, LSCV, LDH and others), RUNLOOP_MOD (IRESCA, per run NK), CENV_MOD (LSENV0, SENV0), NEWOPAC_MOD (LLAOL).
  • Who calls it: the main program, main.f, at the start of each run (two calls).
  • What it calls: the readers GETYREC7 and GETMODEL2; RSCALE (rescaling); for a new envelope base, the physics EQSTAT, GETOPAC, TPGRAD and the envelope integration ENVINT; for rotation, FPFT and MOMI; then SURFOPAC, SETSCV, PHYSIC, OVROT and GETTAU.
  • Outputs: the model in the arguments (HS, HR, HL, HP, HT, HD, HCOMP, LC, OMEGA, M and the rest), and many modules: the surface composition in COMP_MOD and COMP2_MOD (XENV, ZENV, ZENVM, AMUENV, FXENV, YENV, Y3ENV), read by the equation of state and opacity routines; the previous model in OLDMOD_MOD (HPO, HTO, HRO, HLO, TEFFLO, the surface luminosity HLSURO), read by HTIMER and others to limit the time step, and the starting model's rotation convective flags LCZO, read by CRRECT; OLDROT_MOD (WOLD); and OVRTRN_MOD (TAUCZ0, PPHOT0, FRACSTEP).
  • Modules: 16 of them; besides those above, CONSTANTS_MOD, DEBHU_MOD (the Debye–Hückel composition), DPMIX_MOD (IOVIM), NMLBYPASS_MOD, JSON from DIMENSIONS_MOD, and the envelope's ENVSTRUCT_MOD (filled by ENVINT, shared with STITCH, GETTAU, TAUINT and others).

The method, in order.

  1. Stop on failure. If LARGE is set (the previous model failed to converge), the run stops (exit status 1).

  2. Read or keep. If LFIRST(NK) is false, the model in memory is kept, and the reading, the mixture change, and the core extension are skipped (the model is rescaled at step 5). Otherwise the format keyword decides the reader; another keyword stops the run (exit status 3). After reading: $\Delta t$ in seconds, DELTS = CSECYR*DDAGE (the step DDAGE is in years); for an evolved model (MODEL > 0), a warning if the model's mixing length differs from the run's by $2\times10^{-3}$ or more, or its "extended composition" switch differs (the run is no longer stopped, since 1/92; the warning prints an unset variable for the model's switch, bug 5). The envelope is always recomputed (LNEW = .TRUE.). If LWNEW, the model is set to solid-body rotation at WNEW; without rotation, the distortion factors FP, FT are 1.

    Question 1 (lines 316–337↗). The mixing-length check. A mismatch of mixing length or composition switch now only warns. Should the run still stop, as the commented-out STOP did?

  3. Change the mixture (MHP 10/24), only for a model read from file, and only if it is chemically homogeneous (every species within $10^{-6}$ of its central value). With LMIXTURE, the C, N and O isotopes are scaled so that each element's share of $Z$ (HCOMP(3,·)) becomes FRAC_C, FRAC_N, FRAC_O: $$X_i \to X_i\,\frac{f_\mathrm{C}}{(X_{^{12}\mathrm{C}} + X_{^{13}\mathrm{C}})/Z}\quad (i = {}^{12}\mathrm{C}, {}^{13}\mathrm{C}),$$ and likewise for N (indices 7–8) and O (9–11). With LISOTOPE, the ratios $^{12}$C/$^{13}$C = R12_13 and $^{16}$O/$^{18}$O = R16_18 are imposed at fixed sums, and $^3$He, $^2$H, $^6$Li, $^7$Li and $^9$Be are set to their …_INI values (the default R16_18: bug 3). R14_15, R16_17, XB10_INI and XB11_INI (in NMLBYPASS_MOD) are not applied: "AT PRESENT B10,B11,N15,O17 ARE NOT USED AND THUS NOT ALTERED" (line 439↗; unused?), and the documentation calls them placeholders. (The order of HCOMP's 15 species, from the printed labels: X, Y, Z, $^3$He, $^{12}$C, $^{13}$C, $^{14}$N, $^{15}$N, $^{16}$O, $^{17}$O, $^{18}$O, $^2$H, $^6$Li, $^7$Li, $^9$Be.)

  4. Extend the core (LCORE, for a model read from file; MHP 9/98, 9/14). If the extended model would exceed JSON points, the run stops (exit status 3). MCORE points are added inside the innermost shell (the old points are shifted outward, but not their densities: bug 1), spaced by HPTTOL(2) in $\log m$, with MCORE = INT(DLOG10(FCORE)/HPTTOL(2))+1; FCORE (a namelist variable) is then overwritten with MCORE*HPTTOL(2), a log offset rather than the factor it was. Inward, at constant density $\rho_c$ (HD(1)), constant energy generation and constant $\nabla$: $$\log r = \tfrac13\left(\log m - \log\tfrac{4\pi}{3} - \log\rho_c\right),\qquad L = L_1\,\frac{m}{m_1},$$ $$\frac{d\ln P}{d\ln m} = -\frac{G m^2}{4\pi r^4 P},\qquad \Delta\log T = \nabla\,\Delta\log P,$$ with the pressure step taken at the midpoint (two evaluations), $\nabla$ from the first two old points (0/0 when MCORE = 1: bug 4), and the density from $\log\rho = \log P - \log T - $ const (FACD, fixed at the first old point; MHP 4/12 replaced a "broken" EOS call).
  5. Rescale with RSCALE if IRESCA(NK) ≠ 1.

  6. Move the envelope's fitting point (LSENV0), to SENV0, the log of the fitting point's mass fraction, $\log_{10}(m_\mathrm{fit}/M_\star)$ (as SENV = HS(M) - HSTOT): a small negative number, at most $-10^{-12}$ ("τ = 2/3"; a positive value is made negative, lines 587–591↗), which puts the fitting point a fraction $\approx 2\times10^{-12}$ of the mass below the surface. Nothing is done when the current SENV matches SENV0 to within SENVTOL $= 100\,\epsilon\,|\texttt{HSTOT}|$ (100 units in the last place of HSTOT, about $7\times10^{-13}$, below the $10^{-12}$ minimum), since SENV, a difference of two log masses near 33, carries roundoff of order $10^{-14}$. For a deeper point, shells beyond it are dropped and the new last shell is interpolated linearly in $\log m$; if it lies between a convective and a radiative shell, the physics routines (EQSTAT, GETOPAC, TPGRAD) decide whether it is convective. For a shallower point (bug 2 for the interpolated last shell), an envelope is integrated with ENVINT from the surface (at the model's $L$ and $T_\mathrm{eff}$, or the spotted star's ambient temperature, below), shifted to match the last interior point, and its points down to the new fitting mass become interior shells (constant $L$), each with its envelope point's convective flag. With rotation the new shells rotate at the old surface rate, with $j = \tfrac23\,\Omega r^2$.

  7. Shell masses. With $m_i = 10^{\texttt{HS}(i)}$ (HS1), each shell's mass HS2 is $$\Delta m_i = \tfrac12\,(m_{i+1} - m_{i-1}),\quad \Delta m_1 = \tfrac12\,(m_2 + m_1),\quad \Delta m_M = M_\star - \tfrac12\,(m_{M-1} + m_M).$$

  8. Rotation. FPFT and MOMI give the distortion and moments of inertia $I_i$; then $J_i = \Omega_i I_i$, $j_i = J_i/\Delta m_i$ (HJM), $K_i = \tfrac12 \Omega_i J_i$ (HKEROT), and the totals SJTOT, SKEROT, printed beside the previous ones.

  9. Surface composition (first run only, NK = 1): from the relative mass fractions V of 12 elements (VNEW from the parameters unless the old LLAOL opacities are used), with H and He set from $X$ and $Y$, the number fractions $f_k = (V_k/A_k)/\sum_l (V_l/A_l)$ (FXENV, atomic weights ATOMWT), and $Z$ without C, N and O (ZENVM). With the mass fractions $X_k$ of all 12 elements, H and He included, $$\texttt{AMUENV} = \sum_{k=1}^{12} \frac{X_k}{A_k},$$ the inverse mean atomic weight per ion (as CHECKC's comment says; STARIN's own comment, line 920↗, calls it the "MEAN ATOMIC WEIGHT OF SURFACE Z," which the code does not compute, lines 932–937↗). Then the surface opacity tables (SURFOPAC) and, with LSCV, the SCV equation of state (SETSCV).

    Question 3 (line 904↗). The surface composition only for the first run. This step, up to SURFOPAC, is skipped when NK > 1 (GOTO 630), so a later run that reads a new model from file (or changes the mixture) keeps the first run's XENV, ZENV, FXENV. Intended?

  10. Save the old model in OLDMOD_MOD/OLDROT_MOD (TEFFLO = TEFFL and HLSURO = HL(M) are set inside the loop over the shells, lines 956–969↗, to the same effect as once before it), then compute the physics of all shells (PHYSIC), the convection and overshoot zones (OVROT, whose rotation convective flags LCZ are kept as LCZO for CRRECT, as HPOINT keeps them after each rezone) and the convective turnover time and photospheric pressure (GETTAU), kept as TAUCZ0, PPHOT0; FRACSTEP = 0.5.

Spots (G. Somers 10/14). For a spotted star (SPOTF the covering fraction, SPOTX the spot-to-ambient temperature ratio), the envelope is integrated at the ambient temperature $$\log T_\mathrm{amb} = \log T_\mathrm{eff} - \tfrac14 \log_{10}\!\left(f\,x^4 + 1 - f\right).$$

Design

Many paths print to the screen (WRITE(*,…)) as well as to ISHORT. Errors end the run with STOP 1 (a failed model), STOP 3 (bad input), or the bare STOP 9999 or STOP 9998 (too many points, coincident masses). A large commented-out block (G. Somers 8/17) computed the gradients of every shell; PHYSIC does that now. FCORE and MCORE, which the core extension overwrites, are namelist variables in NMLPAR_MOD.

The starting models (from YREC's User Guide). The model read from FFIRST comes from a library of converged models, since YREC, a relaxation code, cannot start from nothing: seed models, the legacy pre-main-sequence models high on the Hayashi track (those ending in .pms far above the birthline, good for perturbing to new conditions; those in .ahbl at the deuterium-burning birthline, good for rotating models); start models, made from the seeds with the GS98 mixture, the OPAL 2006 equation of state, a gray atmosphere and OP with Alexander (2006) opacities, densely for solar metallicity (0.03 to 25 $M_\odot$) and sparsely for $Z$ = 0.001 to 0.06, the place to start for a large change of mass or composition; and dbl models, run to the deuterium-burning birthline (central D down by 1%), the recommended start for most work; a few terminal-age main-sequence models serve the test suite. The User Guide notes that the seeds' CNO abundances follow GS98 and must be adjusted by hand for another mixture; step 3 (the mixture controls) is the code's way to do it. With LSENV0A, the fitting point is moved to SENV0A, $\log_{10}$ of the mass fraction below it: $-10^{-4}$ is standard, $-10^{-7}$ a thin envelope (see the question at step 6).

From YREC's documentation

Control Options (Mixtures) explains the composition controls that STARIN applies, only to a starting model read from FFIRST (LFIRST): ISETMIX = 0 leaves the CNO mixture alone, 1 uses the preset AMIX (GS98, AAG21, M22P, M22M; it is recommended to match the mixture of the opacity tables), 2 a custom one from FRAC_C, FRAC_N, FRAC_O (the fractions of the metals by mass in C, N, O; GS98: 0.172148, 0.050426, 0.468195). ISETISO does the same for the isotope ratios R12_13 (C12/C13), R16_18 (O16/O18) and the initial mass fractions XH2_INI, XHE3_INI, XLI6_INI, XLI7_INI, XBE9_INI of D, He3, Li6, Li7 and Be9, with AISO = 'L21' (Lodders 2021, the only preset); R14_15, R16_17, XB10_INI, XB11_INI are placeholders (N15, O17, B10, B11 are not followed). Physics Options adds: LCORE moves the central fitting point inward by a Taylor expansion, by the factor FCORE in mass; MCORE is obsolete as an input (STARIN computes it from FCORE); LWNEW turns a non-rotating model into one rotating uniformly at WNEW (rad/s; with disk locking it should equal the disk's rate, PDISK).

1. (harmless in the runs) The densities are not shifted in the core extension.

(lines 499–510↗, line 518↗) The loop that shifts the old points outward by MCORE moves HS, HR, HL, HP, HT, LC, HCOMP and OMEGA, but not HD. After it, HD(MP1)…HD(M) hold the densities of the old points of the same index, not of the points now stored there, and HD(M+1)…HD(MN) are never set. FACD = HP(MP1)-HD(MP1)-HT(MP1) then mixes the pressure and temperature of the old first point with the density of old point MP1, and every new core density (line 561↗) inherits the error; HD(M), now unset, is read again when the fitting point is moved (line 625↗, line 741↗, line 785↗), and PHYSIC passes each HD on to EQSTAT (physic.f, line 94↗). Taken whenever LCORE is true for a model read from file (default false; set in 110 of the repository's namelists, such as testsuite/Test_solarGS98_base.nml2).

How the code itself shows it. The comments state what DEL is: "MARCH INWARD IN MASS FROM THE INNERMOST MODEL POINT.", "ASSUME EPSILON=CONSTANT AND DEL=CONSTANT" (lines 512–513↗), and "ASSUME DEL= CONSTANT IN THE CORE" (lines 533–534↗), so DEL is the gradient at the old innermost point. After the shift that point sits at MP1 (line 511↗), and most lines of the block read it there: FACD from HP(MP1) and HT(MP1) (line 518↗), HS(MP1) for the luminosity (line 524↗), and LC(MP1), OMEGA(MP1), and HCOMP(J,MP1) (line 532↗, line 536↗, line 539↗). The changes since rp_1

Changed since rp_1. Changed since 09c3b9b. The fitting point is left alone when the requested SENV0 equals the current SENV to within roundoff (SENVTOL, new), not only when the two are exactly equal: before, a request that differed by roundoff took the shallower-envelope branch, added a point with FX = 0 (a copy of point M), and SPLINT stopped on the duplicate abscissa (the authors' fix).

Changed since a8a5950. QDT and QDP are no longer arguments (now locals; MAIN only passed them on to CRRECT); a kept model is rescaled once, not twice (the RSCALE call before the jump to label 3000 is gone); a core extension past JSON now stops the run, which settles former question 1, so former questions 2–12 are now 1–11; the shift of the new envelope points now moves their convective flags LCENV too, which were read one point off; the saved point count MO is replaced by the surface luminosity HLSURO, for ENTIME's limit on the motion in the HR diagram; the starting model's rotation convective flags are saved in LCZO for CRRECT's call to GETROT; the stops now exit with status 1 (failed model) or 3 (bad input) (KNOWN_ISSUES.md, issue 38).

61def _e(x, w, d):
62    # Fortran's 0PEw.d: a mantissa in [0.1, 1).
63    if x == 0.0:
64        return f"{'0.' + '0' * d + 'E+00':>{w}}"
65    e = math.floor(math.log10(abs(x))) + 1
66    mant = x / 10.0**e
67    if round(abs(mant), d) >= 1.0:
68        mant /= 10.0
69        e += 1
70    s = ("-" if x < 0 else "") + "0" + f"{abs(mant):.{d}f}"[1:]
71    return f"{s + f'E{e:+03d}':>{w}}"
