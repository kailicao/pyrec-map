Purpose

WRTMOD writes extra profiles of one model: with LSOUND, a sound-speed and structure table (to the units IMODPT and ISOUND, the file Csound.dat); with LSTATM, LSTENV or LPULSE, an envelope integrated again for printing; and with LPULSE, a model for pulsation codes on IOPMOD, in one of three versions (IPVER).

How it fits

  • Inputs: the model (arguments: M, JENV, HCOMP, HS1, $\log\rho$, $L$, $\log P$, $\log r$, $\log T$, MODEL, $\log L$, $\log T_\mathrm{eff}$, FP, FT, $\log m$ HS, the age, the mixing length CMIXL and the star's mass XMSOL, a snapshot of SMASS taken by the main program), and through modules the per-shell physics: $\Gamma_1$ and the switch LSOUND (SOUND_MOD), the pulsation derivatives PQDP, PQDT, … (PULSE1_MOD), energy rates, opacity and gradients (SCRTCH_MOD), STOTAL (COMP_MOD), and the namelist switches and integration steps (LSTORE, LSTATM, LSTENV, LPULSE, IPVER, SPOTF, SPOTX, ATMSTP, ENVSTP, … in NMLPAR_MOD; formerly CCOUT, PULSE, SPOTS, ENVGEN, INTATM, INTENV).
  • Who calls it: PUTSTORE (when the atmosphere or envelope is stored) and WRTOUT (for pulsation output between stored models).
  • What it calls: ENVINT, which itself prints the envelope and atmosphere (and the pulsation envelope with LPULPT).
  • Outputs: IMODPT, ISOUND (the file FSOUND, Csound.dat by default, opened once by PARMIN), IOPMOD, and the envelope printed by ENVINT.

The method

  1. Sound speed (LSOUND). For each shell, with $V = G m \rho/(P r)$ and $U = 4\pi\rho r^3/m$: $r/R_\odot$, $m/M_\odot$, $m/r^3$ (solar units), $V/\Gamma_1$, $\Gamma_1$, $$A = -V/\Gamma_1 + V\left(\frac{\partial\ln\rho}{\partial\ln P} + \nabla\,\frac{\partial\ln\rho}{\partial\ln T}\right)$$ (the code's XX4; probably the buoyancy term, by its form), $U$, and $c_s = \sqrt{\Gamma_1 P/\rho}$ in km/s. Between shells it also writes $dP/dr$-like and $d\rho/dr$-like terms (QPR, QDR) and their differences scaled by $\Gamma_1 P\,\Delta r$ and $\rho\,\Delta r$.

    Question 1 (line 138↗; line 140↗). Csound.dat's header. The header line is written again at every call to the file PARMIN opened once, so a run that writes several models repeats it between their tables, with no model number or age. Is the repeated header meant to separate the models, and should it say which model follows?

  2. Envelope. The integration steps are set to the output steps, ENVINT integrates from the surface to the last shell's pressure (for a spotted star at the ambient temperature, as in starin.f), and the steps are restored afterwards.

  3. Pulsation model (LPULSE). A header (LPULSE alone), then, only when both LPULSE and LSTORE are set, for each shell in the list ID(1..IDM): $\log r$, $m/M$, $L$, $\log T$, $\log\rho$, $\log P$, $\epsilon$, $\kappa$ and the derivatives, in format 1, 2 or 3 (version 3 adds three columns for the MLT quantities, written as zeros).

For users (from YREC's Quick Start). With LPULSE, the pulsation output: the interior model on IOPMOD (.pmod, written here) and the envelope and atmosphere on IOPENV and IOPATM (.penv, .patm, written by ENVINT when called from here); the Quick Start names the last .atm, the test suite's namelists .patm. IMODPT is the .full file (FMODPT).

Question 2 (line 152↗; line 171↗). The deprecated .full file. YREC's Quick Start lists .full (FMODPT) as a deprecated output, and the test suite's namelists say "No longer used," but PARMIN still opens it (and writes the run's description to it), and WRTMOD (with LSOUND), CHECKJ and SECULR still write to it. Should these writes be removed, or should the documentation say what the file now holds?

2. (wrong output) Checked by KC (Nov 10, 2026) The pulsation model's shell list is never set.

(line 51↗; lines 255–256↗; lines 265–266↗) IDM and ID(J) are locals, never assigned (the "long block" removed by G. Change log

The changes since rp_1

Changed since rp_1. CMIXL and XMSOL are now arguments (CMIXL is passed on to ENVINT); the sound-speed file is written to the unit ISOUND, opened once by PARMIN, instead of being opened on unit 500 at each call, which settles part of question 1; declarations: COMMON blocks to modules, IMPLICIT NONE.

Changed since a8a5950. Version 3 of the pulsation model writes literal zeros in its three mixing-length columns, which held PUALPHA_MOD's always-zero VALFMLT, VPHMLT, and VCMXMLT (now removed), so that readers of IPVER = 3 see the same layout; PUALPHA_MOD is no longer used here.

41def _e0(x: float, w: int, d: int) -> str:
42    """Fortran's 0PEw.d: a mantissa in [0.1, 1), e.g. 0.12345678E+01."""
43
44    if x == 0.0:
45        return f"{'0.' + '0' * d + 'E+00':>{w}}"
46    e = math.floor(math.log10(abs(x))) + 1
47    m = x / 10.0**e
48    if round(abs(m), d) >= 1.0:  # rounding carried into the next decade
49        m /= 10.0
50        e += 1
51    s = f"{abs(m):.{d}f}"[1:]  # drop the leading zero, as Fortran does
52    sign = "-" if x < 0 else ""
53    return f"{sign + '0' + s + f'E{e:+03d}':>{w}}"

56def _records(values: list, per_line: tuple, w: int, d: int) -> str:
57    """Values in 0PEw.d, per_line[k] of them on record k (FORMATs 5052,
58    6052, 6053); the last record stops when the values run out."""
59
60    lines = []
61    k = 0
62    for count in per_line:
63        chunk = values[k:k + count]
64        if not chunk:
65            break
66        lines.append("".join(_e0(v, w, d) for v in chunk))
67        k += count
68    return "\n".join(lines)
