Purpose

GETOPAC is YREC's opacity routine: for a given $\rho$, $T$, $X$, $Z$ it combines the low-temperature (molecular) table and the interior table, ramps between them, handles metal-rich helium-burning cores, and adds conductive opacity. It returns $\kappa$ and its logarithmic derivatives.

How it fits

  • Who calls it: seven routines: COEFFT, ENVINT, PHYSIC, QATM, QENV, SCONVEC and STARIN.

  • Inputs: DL, TL ($\log\rho$, $\log T$), X, Z, and FXION (ionization fractions, passed on to the conductive opacity).

    Question 1 (line 192↗; lines 32–40↗). FXION used only by conduction. Fine, but its meaning differs by equation of state (EQSAHA versus SCV); does CONDOPACPINT depend on which one supplied it?

  • What it calls: the low-temperature table GETALEX06 (the low-temperature tables of Ferguson et al. 2005, the code's ALEX06); the interior table GETOPAL95 (OPAL 1995); GTPURZ (pure-metal table); and CONDOPACPINT (Potekhin conductive opacity).

  • Outputs: O ($\kappa$), OL ($\log\kappa$), QOD $=\partial\log\kappa/\partial\log\rho$, QOT $=\partial\log\kappa/\partial\log T$.
  • Modules: NMLPAR_MOD (the namelist switches LALEX06, LOPAL95, LPUREZ, LcondOpacP, the ramp limits TMOLMIN, TMOLMAX, and the tolerance OPTOL, read by PARMIN); NEWOPAC_MOD (L2Z, set by SETUPOPAC from LZRAMP or LDIFZ); COMP_MOD (ZENV); IOUNITS_MOD (ISHORT, for the error messages).

The method

  1. Molecular opacity for $\log T \le$ TMOLMAX, from the Ferguson et al. (2005) tables (LALEX06); if they are not switched on, the run stops ("NO MOLECULAR OPACITY TABLE CHOSEN").
  2. Interior opacity, unless $\log T <$ TMOLMIN (where the molecular value is used alone):
  3. for $Z > 0.1$ and $\log T > 7.0$ (helium-burning cores), linear interpolation in $Z$ between OPAL 1995 at $Z_\mathrm{tab} = 0.1$ and the pure-metal table at $Z = 1$: $\log\kappa = \log\kappa_{Z=1} + (Z-1)\,\dfrac{\log\kappa_\mathrm{tab} - \log\kappa_{Z=1}}{Z_\mathrm{tab} - 1}$, and the derivatives likewise; the run stops if no pure-$Z$ table is loaded (LPUREZ) or if OPAL 1995 is not switched on;
  4. the run stops if $Z > 0.12$ below that temperature, or if $Z$ differs from the envelope's ZENV beyond OPTOL with a single-$Z$ table (neither L2Z nor OPAL 1995, which interpolates in $Z$ itself; bug 2 below);
  5. otherwise OPAL 1995; if it is not switched on, the run stops ("NO OPACITY TABLE CHOSEN").
  6. Ramp for TMOLMIN ≤ $\log T \le$ TMOLMAX: with $w = (\log T - \mathrm{TMOLMIN})/(\mathrm{TMOLMAX} - \mathrm{TMOLMIN})$, $\kappa = w\,\kappa_\mathrm{int} + (1-w)\,\kappa_\mathrm{mol}$, and the derivatives likewise. The ramp is linear in $\kappa$, while the derivatives (of $\log\kappa$) are averaged with the same weights, so they are not exactly those of the ramped $\kappa$: The weights should be $w\,\kappa_\mathrm{int}/\kappa$ and $(1-w)\,\kappa_\mathrm{mol}/\kappa$, and the term $(\partial w/\partial\log T)(\kappa_\mathrm{int} - \kappa_\mathrm{mol})/\kappa$ is dropped. This is known, and affects the Jacobian only (settled from YREC's notes, Nov 9, 2026: KNOWN_ISSUES.md, issue 40, "Opacity ramp derivatives"; lines 177–181↗).

  7. Conduction. Potekhin's opacity if LcondOpacP is set and it succeeds; otherwise, for $\log T \ge 4.2$ and $\log\rho \ge 2\log T - 13$, the fit to Hubbard & Lampe (1969) as coded (the code names no source for the fit; see the question below): $$\log\kappa_c = \log(1 - 0.6X) - 14.6196 - (3.5853 + 0.1386\log\rho)\log\rho + (5.1324 - 0.3219\log T)\log T + 0.3901\log\rho\log T.$$ The two cuts leave out cool gas and gas of low density for its temperature ($\rho < 10^{-13}T^2$). The derivatives QODC, QOTC it receives from Potekhin's fit carry CONDOPACPINT's suspected bugs 1 and 2, and its extrapolation below $\log\rho = -6$ bugs 3 and 4.

    Question 2 (lines 200–211↗). The conductive fit's source. The fallback fit to Hubbard & Lampe (1969) has no reference in the code. Whose fit is it, and what range of $\rho$, $T$ was it made for? Are the cuts ($\log T \ge 4.2$, $\rho \ge 10^{-13}T^2$) meant to leave out gas where the electrons are far from degenerate and conduction is negligible next to radiation?

    Question 3 (lines 190–199↗). Conduction where no table applies. Below $\log T = 4.2$ or at low density the routine returns without conduction, which is fine; but when Potekhin is enabled and fails, Hubbard–Lampe is used without a message. Should the fallback be reported?

  8. Combination: $1/\kappa = 1/\kappa_\mathrm{rad} + 1/\kappa_c$, and $$\frac{\partial\log\kappa}{\partial\log\rho} = \frac{\kappa_c\,\partial\log\kappa_\mathrm{rad} + \kappa_\mathrm{rad}\,\partial\log\kappa_c}{\kappa_\mathrm{rad} + \kappa_c},$$ and the same in $\log T$.

The tables' mixtures. Each table is computed for one heavy-element mixture, named in its file (FLIV95, FALEX06): in the test suite GS98.OP17 (OP, Grevesse & Sauval 1998, the YREC paper's base mixture), GN93hz, AAG2021zx0.0187.tab or Magg22_met_zx0.0226.tab, and alexmol06gs98.tab for the molecular table. The run's XENV, ZENV (and the equation of state's mixture) should match the tables', since the code only interpolates in $X$ and $Z$; the documentation (Control Options) recommends tying the CNO abundances "to preset mixtures used in opacity tables". The pure-metal table (FPUREZ) is input/opacity/lanl/PURECO.DBGLAOL, the table the User Guide names for helium burning ("Helium burning uses a different type of atomic opacity table"); so in a helium-burning core the step-2 interpolation runs from OPAL at $Z = 0.1$ to this table at $Z = 1$ (what mixture it holds is the question below).

Question 4 (lines 109–138↗). OPAL's C/O-rich tables. The YREC paper (§2.3.2) says OPAL's tables for carbon- and oxygen-rich mixtures (Iglesias & Rogers 1993) are used in helium-burning regions; the code instead interpolates in $Z$ between OPAL at $Z = 0.1$ and the table PURECO.DBGLAOL (step 2), which the tables' README describes as interpolating "between helium and a c/o mixture" (input/opacity/atomic/README, line 1): With what C/O ratio, and how does it interpolate between helium and C/O? Is the paper describing the older scheme, or is the C/O table meant to stand for it? A reader would ask how large the error in the core opacity of horizontal-branch and AGB models is when the C/O ratio of the core differs from the table's, and when $0.1 < Z < 1$ is reached by a straight line in $\log\kappa$.

From YREC's documentation

Control Options (Input files) and Physics Options (Opacity options): LALEX06 uses the molecular opacities of Ferguson et al. (2005) and LOPAL95 the atomic opacities in OP/OPAL format (both recommended); LPUREZ adds the pure Y/Z table (FPUREZ); LCONDOPACP uses the updated conductive opacities. Below $\log T$ = TMOLMIN (default 4.0) only the molecular opacities are used, above TMOLMAX (4.1) only the atomic ones, with a ramp between. The code builds a 2D table for the surface abundances, useful in outer convection zones and the envelope, and switches to the full 3D/4D interpolation when $X$ or $Z$ differ from it by more than OPTOL (1.0D-8). LOPAL95 has no default in NMLPAR_MOD (nor has ZOPAL951); the User Guide asks the user to set LOPAL95 = .TRUE. with the table's path; a namelist that omits it leaves it to the compiler (usually false), and the run then stops at a trap with status 3 (settled from the code and the documentation, Nov 9, 2026: docs/source/userguide.md, line 34; line 243↗; lines 126–130↗, lines 162–166↗).

Change log

The changes since rp_1

Changed since rp_1. The Alexander 1995, Kurucz 1990, OPAL 1992 and LAOL 1989 tables were removed, so OPAL 1995 is the only interior table and the Ferguson et al. (2005) tables (ALEX06) the only molecular ones; their two-$Z$ interpolations went with them, and so did the Kurucz failure path (the alternate return to label 100). New traps stop the run when no molecular table is chosen below TMOLMAX, and when no interior table is chosen in the helium-burning branch; this settles question 1 of rp_1 (ZIT undefined in that branch), which is removed. The helium-burning branch now starts at $\log T > 7.0$ instead of 7.7 ("JCZ 211125", for semiconvection and overshoot horizontal-branch models), and the message for $Z > 0.12$ says $10^7$ K. COMMON blocks became modules (NEWOPAC, NWLAOL and MISCOPAC to NMLPAR_MOD and NEWOPAC_MOD; OPTAB removed), IMPLICIT NONE.

Changed since a8a5950. The stops now exit with a nonzero status instead of a bare STOP (KNOWN_ISSUES.md, issue 38): status 3, the code for input errors, when no molecular or interior table is chosen (three traps), and status 1, the code for run-time errors, when a helium-burning core needs the missing pure-$Z$ table and when $Z > 0.12$ or $Z$ leaves a single-$Z$ table.
