Purpose

Decides when to write a model for pulsation calculations: it "calculates the distance the star has travelled in the HR diagram; if far enough, output pulsation model." When the accumulated distance passes a threshold, it opens three new output files named after the run and the model number, and sets LPULSE so that the output routines write the model to them.

How it fits

  • Inputs: the previous point (POL1 $=\log L$, POT1 $=\log T_\mathrm{eff}$, POA1 = age) and the running total POLEN; the current BL ($\log L/L_\odot$), TEFFL, MODELN, the run index NK and the age DAGE (arguments); the weights POA, POB, POC and the threshold POMAX in NMLPAR_MOD (namelist CONTROL, read by PARMIN); the base file names FPMOD, FPENV, FPATM (arguments, since MHP 8/25).
  • Who calls it: the main program in main.f, after each model when LPOUT is set.

  • Outputs: POLEN and the previous point updated; LPULSE in NMLPAR_MOD; the units IOPMOD, IOPENV, IOPATM (from IOUNITS_MOD) opened as <FPMOD>NN_MMMM and so on, with NN = NK (the main program's loop over runs, DO 200 NK = 1, NUMRUN) and MMMM the model number; a line to IOWR and ISHORT. While LPULSE is true, WRTMOD writes the model to IOPMOD and passes LPULPT on to ENVINT, which writes the atmosphere and envelope to IOPATM and IOPENV from the points QATM and QENV store.

    Question 1 (line 94↗; line 103↗; line 112↗). STATUS='NEW'. The files are opened as new, so rerunning a model sequence in the same directory stops at the first existing pulsation file. Is the stop meant to protect earlier pulsation files, or should they be opened with STATUS='UNKNOWN' (and rewound), as PARMIN opens the other outputs?

The method

The squared step in the HR diagram and in age, with weights $a, b, c$, is accumulated: $$\ell^2 \mathrel{+}= (a\,\Delta\log L)^2 + (b\,\Delta\log T_\mathrm{eff})^2 + (c\,\Delta t)^2 .$$ When $\ell^2 \ge$ POMAX, the files are opened and $\ell^2$ is reset to zero; otherwise the three units are closed and LPULSE is set false.

POMAX bounds a squared distance. POLEN adds the squares of the weighted steps, $(\mathtt{POA}\,\Delta\log L)^2 + (\mathtt{POB}\,\Delta\log T_\mathrm{eff})^2 + (\mathtt{POC}\,\Delta\mathrm{age})^2$ (lines 76–79↗; printed as "LEN SQ"), and is compared with POMAX (line 83↗), so the default POMAX = 0.1 means a distance of about 0.32. YREC's documentation describes none of POMAX, POA, POB, and POC; it could say that the threshold is a squared distance.

From YREC's documentation

Control Options (Output): LPULSE writes pulsation output, to FPMOD (the interior), FPENV (the envelope) and FPATM (the atmosphere), and needs LSTATM and LSTENV for the outer two; IPVER chooses its format.

Suspected bugs, checked by running the code

1. (not reached) Two different lines under the same labels.

(lines 119–122↗) The same format writes the step's differences (TM1–TM3) to IOWR but their weighted squares (TMP1–TMP3) to ISHORT, under the same labels "D L," "D Te," "D AGE," so the two files disagree and the ISHORT line is mislabeled. Only with LPOUT (off by default).

A possible fix: a choice for the developers: write the same quantities to both units, or give the weighted squares their own labels.

Checked by running YREC (Nov 9, 2026; a line added at each suspected path counted how often it was taken, the outputs otherwise unchanged): Not reached in any of 34 runs: 26 of YREC's cases, from a 0.04 $M_\odot$ brown dwarf and the solar models to 9 $M_\odot$, rotation, and helium burning, and 8 made-up ones. PDIST runs only with LPOUT on; its default is false, no case sets it, and no document offers it. LPOUT is in the namelist group that PARMIN reads (parmin.f, line 355↗), so any case with it on reaches this line at every model. The fix (measurement only: the differences written to ISHORT as well) was not run. Intent: none found.

19    """The file name <base>NN_MMMM (or NN_MMMMM from model 10000 on).
20
21    base is a CHARACTER*256 in Fortran, padded with blanks: the name ends
22    at its first blank, INDEX(base, ' ') - 1. A Python string has no

26    """

28    ioccol = base.find(" ") if " " in base else len(base)

36def pdist(pol1: float, pot1: float, poa1: float, polen: float, bl: float, teffl: float, modeln: int, nk: int,
37          fpatm: str, fpenv: str, fpmod: str, dage: float) -> tuple[float, float, float, float]:
38    """Accumulate the squared distance the star has moved in the HR diagram
39    and in age since the last pulsation model; when it reaches POMAX, open
40    three new pulsation output files and set LPULSE, otherwise close them
41    and clear LPULSE.
42
43    Translates: pdist.f#PDIST (7be4133)
44
45    Arguments: pol1, pot1, poa1 (log L, log Teff and age at the previous
46    model), polen (the accumulated squared distance); bl, teffl, the
47    model number modeln, the run index nk and the age dage now; the base
48    file names fpatm, fpenv, fpmod.
49
50    Returns (pol1, pot1, poa1, polen), updated. Sets nmlpar_mod.lpulse.
51
52    """
53
54    # The step and its weighted squares, accumulated (Fortran lines 73–82).
55    # Question (see the page): POMAX is compared with a squared distance.
56    tm1 = bl - pol1
57    tm2 = teffl - pot1
58    tm3 = dage - poa1
59    tmp1 = nmlpar_mod.poa * tm1 * nmlpar_mod.poa * tm1
60    tmp2 = nmlpar_mod.pob * tm2 * nmlpar_mod.pob * tm2
61    tmp3 = nmlpar_mod.poc * tm3 * nmlpar_mod.poc * tm3
62    polen = polen + tmp1 + tmp2 + tmp3
63    pol1 = bl
64    pot1 = teffl
65    poa1 = dage
66
67    # Far enough: open the three pulsation files and set LPULSE; otherwise
68    # close them (Fortran lines 83–118). Question (see the page):
69    # STATUS='NEW' stops if the file exists.
70    if polen >= nmlpar_mod.pomax:
71        nmlpar_mod.lpulse = True
72        polen = 0.0
73        iounits_mod.open(iounits_mod.iopmod, _pulse_name(fpmod, nk, modeln),
74                         status="new")
75        iounits_mod.open(iounits_mod.iopenv, _pulse_name(fpenv, nk, modeln),
76                         status="new")
77        iounits_mod.open(iounits_mod.iopatm, _pulse_name(fpatm, nk, modeln),
78                         status="new")
79    else:
80        iounits_mod.close(iounits_mod.iopmod)
81        iounits_mod.close(iounits_mod.iopenv)
82        iounits_mod.close(iounits_mod.iopatm)
83        nmlpar_mod.lpulse = False
84
85    # The step, to IOWR and ISHORT (Fortran lines 119–122). Suspected bug
86    # (see the page): the differences go to IOWR, their weighted squares
87    # to ISHORT, under the same labels.
88    iounits_mod.write(iounits_mod.iowr, _fmt276(polen, tm1, tm2, tm3))
89    iounits_mod.write(iounits_mod.ishort, _fmt276(polen, tmp1, tmp2, tmp3))
90
91    return pol1, pot1, poa1, polen
