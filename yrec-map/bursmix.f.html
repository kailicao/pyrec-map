Purpose

This file evolves the abundances over one time step when rotational mixing and nuclear burning act together. In its own words, it alternates "between nuclear burning plus gravitational settling and mixing in a series of progressively smaller timesteps, extrapolating to the answer for zero timestep". The diffusion coefficients, structure and reaction rates are held fixed during the step.

How it fits

  • Inputs: the arguments, the model (HD, HL, HP, HR, HS, HS1, HS2, HT, HV), the mixing coefficients COD2, the time step DELTS, the zones (MRZONE, MXZONE, NRZONE, NZONE, LCZ); LEXCOM from NMLPAR_MOD (whether the extended set of 15 species, with the light elements, is followed); HCOMPP in OLDMOD_MOD, the composition at the start of the step.
  • Who calls it: GETW, the rotation step, only when LINSTB is true, LALLCZ false and LBURS true (lines 455–460↗). GETW sets its local LBURS to false on every call and never changes it (line 140↗), so at 7be4133 BURSMIX is never called, nor BSROTMIX through it: unused?
  • What it calls: ROTMIX (burning, by its header with KEMCOM in radiative regions), NDIFCOM (mixing by angular-momentum transport), LIBURN2 (light-element burning, if LEXCOM), and BSROTMIX (the extrapolation).
  • Outputs: HCOMP, the abundances at the end of the step. If LEXCOM, it copies the new lithium and beryllium rates (NEWRAT_MOD) into the old ones (OLDRAT_MOD), and sets JENV0 = JENV1, PSCAL0 = PSCAL1 (LIOV_MOD).
  • Modules: OLDMOD_MOD (18 units, among them CRRECT, KEMCOM, LIBURN); NEWRAT_MOD, OLDRAT_MOD, LIOV_MOD (GETW, LIBURN, LIBURN2, LIRATE88); NMLPAR_MOD.

The method

  1. Save the composition at the start of the step (HCOMPP), and $X$, $Y$, $Z$ of the input HCOMP, which the caller's full step has already produced (lines 75–82↗).
  2. Pass the composition of the full step, already computed by the caller, to BSROTMIX as sequence 1.

  3. For sequences $k = 2, \dots, 11$, with $n_k$ = 2, 4, 6, …, 20 substeps of $\Delta t/n_k$: reset the composition, then for each substep burn and, if LDIFY, settle (ROTMIX, which calls MICRODIFF or GRSETT), mix (NDIFCOM) and, if LEXCOM, burn the light elements (LIBURN2); the end of each substep becomes the start of the next (HCOMPP, which KEMCOM reads as the start-of-step state). Then call BSROTMIX; stop when it reports convergence (lines 87–126↗). On convergence HCOMPP is set to the end-of-step composition (lines 118–123↗), and otherwise it is left there by the last substep, though the comment says it is overwritten "temporarily" (lines 72–74↗); GETW does the same on its other path, copying the end-of-step composition into HCOMPP when LBURS is false (lines 372–377↗), so it is the start of the next step (settled from the code, Nov 9, 2026).

    Question 1 (line 52↗; lines 95–96↗). Two NSEQ sequences. NSEQ here starts 1, 2, 4, 6, … (step by 2), while BSSTEP uses 2, 4, 6, 8, 12, … Is the choice deliberate?

  4. If no sequence converges, print a warning and keep the composition of the last (finest) sequence.

  5. Restore $X$ and $Z$ to their input values (those of the caller's full step, not those at the start of the time step), and set $Y = 1 - X - Z - X_3$ (lines 131–136↗).

    Question 2 (lines 132–136↗). $X$ and $Z$ restored. After the extrapolation, $X$ and $Z$ are reset to their values on entry (HKEEP), that is, to the caller's full step, so the burning and mixing of hydrogen computed in the substeps are discarded, and $Y$ absorbs the difference. Is this reset meant?

Only species 4 onward (from $^3$He) are extrapolated (JBEG = 4).

Suspected bugs, by priority

(a) may give wrong results; (b) may crash; (c) misbehaves silently (a wrong message, an ignored setting); (d) fragile: correct today, but breaks on a change or an unusual input.

  1. (d) NDIFCOM gets a region never set when LOK is false. (lines 28–31↗; lines 46–49↗; lines 103–106↗) IBEG, IEND, ECOD2 and EM are locals of BURSMIX, listed as input variables but set nowhere in it; only NDIFCOM sets them, through MIXGRID, and only when LOK is true. With LOK false, NDIFCOM passes them straight to MIXCOM (lines 64–66↗). GETW passes the LOK that SECULR returns, which is false when SECULR finds no instability and leaves early (line 202↗, line 289↗). What follows: On the first such call IBEG = IEND = 0 if the compiler zeroes saved locals, and MIXCOM reads HCOMP(J,0), out of bounds (line 61↗), before finding nothing to do; after an earlier call with LOK true, MIXCOM mixes again the last region of that call, with its old coefficients, in a model SECULR found stable. Not reached at 7be4133, since LBURS is false (line 140↗). Read from the code, not run. A possible fix:
