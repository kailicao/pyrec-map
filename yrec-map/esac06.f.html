Purpose

ESAC06 is ESAC (removed since rp_1) for the OPAL 2006 equation-of-state tables: it interpolates them in $X$, $T_6$ and $\rho$ and returns nine thermodynamic quantities (EOS has room for ten). It is a copy of ESAC01 (removed since rp_1) adapted to the larger 2006 table. The file also holds SETEOS06, the tables' one-time setup.

How it fits

  • Who calls it: OEQOS06 (called from EQSTAT2 when LOPALE06 is set), RHOOFP06, and CALCAD, which calls it directly for every point of the model and envelope (with IORDER = 9, IRAD = 1) when LOPALE06 is set; its call for the atmosphere points is commented out.
  • Who calls SETEOS06: SETUPS, once, when LOPALE06 is set (the table file is opened by PARMIN).
  • What it calls: QUADEOS06, T6RINTEOS06, GMASS06 and RADSUB06; SETEOS06 calls READCOEOS06.
  • Outputs: in EOS06MISC_MOD's EOS: EOS(1) $P$, (2) $E$, (3) $S$, (4) $\partial E/\partial\rho|_T$, (5) $c_V$, (6) $\partial\ln P/\partial\ln\rho$, (7) $\partial\ln P/\partial\ln T$, (8) $\Gamma_1$, (9) $\Gamma_2/(\Gamma_2-1)$; (10), $\Gamma_3-1$ by the commented-out line of radsub06.f, line 102↗, is never computed: The table file holds nine quantities (readcoeos06.f, lines 124–126↗), no caller asks for more than nine, and EOS(10) keeps the 1 that READCOEOS06 sets (readcoeos06.f, lines 89–91↗); nothing reads it (settled from the code, Nov 9, 2026).
  • Modules: AEOS06_MOD (the tables XZ, the grids T6LIST, RHO, T6A, XA, the X index MF and workspace; its member M is now MIDX), shared with READCOEOS06, T6RINTEOS06, RHOOFP06 and EQBOUND06; EEEOS06_MOD (workspace EPL, XX), with READCOEOS06 and T6RINTEOS06; EOS06MISC_MOD, which merges the former /EEOS06/ (the output EOS, ESACT), /AAEOS06/ (workspace), /BEOS06/ (ZZ, IRI, INDEX, NTA, NRA) and /BBEOS06/ (the indices L1…K4, IP, IQ), with OEQOS06, RADSUB06, READCOEOS06, RHOOFP06, T6RINTEOS06, CALCAD and EQBOUND06 (which reads NTA, NRA and starts its search from K3, L2); IOUNITS_MOD (ISHORT).

The table. 169 densities and 197 temperatures. Two DATA statements, now in EOS06MISC_MOD (with INDEX; XA is in AEOS06_MOD), describe its irregular edge: NTA(l), the lowest temperature index for each density, and NRA(k), the highest density index for each temperature.

Question 1 (eos06misc_mod.f, lines 61–70↗). Edge tables in two places. NTA and NRA are hard-coded (in EOS06MISC_MOD); if the table file changes, they must change too. READCOEOS06 already reads, for each density, the number of temperatures in the file (ICYCUSE, readcoeos06.f, lines 105–118↗), and stops if it is below NTA. Could READCOEOS06 derive them from the file?

The method

As ESAC01 and ESAC, whose steps were:

  1. The tables are read once, before the first call, by SETEOS06 (it maps INDEX into IRI, copies XA into XX and calls READCOEOS06); each call takes $Z$ from ZZ(1). The run stops if the tables' $Z$ values differ (the check before label 66, and label 66 itself); only the two cases below use the alternate return.
  2. Out of table (alternate return, label 62) if $T_6$ or $\rho$ is outside the grid. (The copies XXI and RI of the arguments, lines 237–238↗, are not used: unused?)
  3. Bisection for the indices in $X$ (MF…MI), $\rho$ (L1…L4) and $T_6$ (K1…K4).
  4. Check that the stencil avoids the table's empty region, where XZ holds values above $10^{30}$, and choose a 3×3 or 4×4 stencil (IP, IQ). If the 3×3 stencil reaches the empty region but the 2×2 one does not, the stencil is moved back by one in both $T_6$ and $\rho$ and used as 3×3, without a new check; otherwise the routine returns "empty region" (label 65).

  5. For each quantity, interpolate in $X$ with a quadratic through three tables (QUADEOS06; its first argument IS is 0 on the first point, so that it computes its abscissa factors, and 1 afterwards); between two overlapping quadratics, blend them linearly: $$E = E_{\mathrm{low}}\,w + E_{\mathrm{high}}(1-w), \qquad w = (X_{MH} - X)/(X_{MH} - X_{MG}).$$ Then T6RINTEOS06 interpolates in $T_6$ and $\rho$.

  6. Pressure and energy are tabulated scaled: $P = \mathrm{EOS}(1)\cdot T_6\rho$ and $E = \mathrm{EOS}(2)\cdot T_6$. Without radiation, $c_V$, EOS(5), is scaled by $n\,R/m$, with $R = 83.14511$ (the gas constant in units of $10^{12}$ erg per mole per $10^6$ K) and the moles $n$ and mass $m$ from GMASS06; with radiation, RADSUB06 (which takes IRAD as an argument) adds the radiation terms. Since RADSUB06 is called only when IRAD = 1 (lines 481–485↗), its argument is always 1, and its own branch for IRAD = 0 never runs (unused?; radsub06.f, lines 74–103↗). The error messages print their indices.

Suspected bugs, checked by running the code

Each bug is marked by what running the code showed: (changes results, large) or (small), the fix moving a run clearly beyond a null change; (stops the run); (wrong output), the fix changing only what is written; (harmless in the runs), within the noise; (never occurred), the code ran but the fault did not; (not reached); (cannot be reached), a guard prevents it; (withdrawn), the suspicion was wrong.

1. (harmless in the runs) EOS(2) and EOS(5) rescaled again on every call with IORDER < 5.

(line 408↗; lines 477–485↗) The loop over the quantities sets EOS(1..IORDER) only, but the scaling after it multiplies EOS(IRI(2)) by $T_6$ and, without radiation, EOS(IRI(5)) by MOLES*APROP/TMASS (about 140 for an ionized mixture with $X = 0.7$) whatever IORDER is. RHOOFP06 calls ESAC06 with IORDER = 1 and IRAD = 0, up to 13 times per density (rhoofp06.f, lines 91–115↗), so each of these calls multiplies the value of EOS(5) left by an earlier call by that factor again. Only a call with IORDER = 9 resets it (OEQOS06 after a density is found, oeqos06.f, line 102↗, and CALCAD); when RHOOFP06 fails, OEQOS06 returns at once (oeqos06.f, lines 95–97↗), so the growth carries on across calls, and after about 140 such calls EOS(5) overflows. With the developers' build options (-ffpe-trap=invalid,zero,overflow, src/Makefile, line 61) the run stops; in a release build the value becomes infinite and is overwritten by the next call with IORDER = 9, so the results are not changed. This matches the comment in RHOOFP06 that its tolerance was loosened "to prevent array value eos(5) from growing without bound and crashing the program" (rhoofp06.f, lines 117–119↗). Only with LOPALE06 (off by default, nmlpar_mod.f, line 122↗; on in most of the test suite).

Change log

The changes since rp_1

Changed since rp_1. The one-time work (the ITIME switch in /LREADCO/, the table read, the INDEX/XX setup) moved to the new SETEOS06, called from SETUPS; the first-call check $X + Z \le 1$ (label 61) is dropped; the DATA for XA, INDEX, NTA, NRA moved into the modules; COMMON blocks to modules (four small ones merged into EOS06MISC_MOD, M renamed MIDX), IMPLICIT NONE. The question on the shared ITIME flag is settled (the flag is gone), and those on ESAC that applied here are now stated on this page.

222        # A quadratic through the tables mf, mg, mh (Fortran lines 426–444).
223        is_ = 0
224        iw = 1
225        for ir in range(l1, l1 + iq + 1):
226            for it in range(k1, k1 + ip + 1):
227                if mf2 == 1:
228                    a.esk[it, ir] = e.epl[mf, it, ir]
229                    continue                       # go to 46
230                a.esk[it, ir] = quadeos06(
231                    is_, iw, xh, e.epl[mf, it, ir], e.epl[mg, it, ir],
232                    e.epl[mh, it, ir], e.xx[mf], e.xx[mg], e.xx[mh])
233                if a.esk[it, ir] > 1.0e20:
234                    io.write(io.ishort, f"{ID} problem it,ir,l3,k3,iq,ip="
235                             f"{it:5d}{ir:5d}{m.l3:5d}{m.k3:5d}"
236                             f"{iq:5d}{ip:5d}")
237                    io.write(io.ishort, "".join(
238                        f"{e.epl[ms, it, ir]:12.4e}"
239                        for ms in range(mf, mf + 3)))
240                is_ = 1
241
242        # A second quadratic through mg, mh, mi, blended linearly (Fortran
243        # lines 446–465).
244        if mi == mf2:
245            is_ = 0
246            iw = 1
247            dixr = (e.xx[mh] - xh) * a.dfsx[mh]
248            for ir in range(l1, l1 + iq + 1):          # loop 47
249                for it in range(k1, k1 + ip + 1):
250                    a.esk2[it, ir] = quadeos06(
251                        is_, iw, xh, e.epl[mg, it, ir], e.epl[mh, it, ir],
252                        e.epl[mi, it, ir], e.xx[mg], e.xx[mh], e.xx[mi])
253                    # Suspected bug (see the page): tests esk, not esk2.
254                    if a.esk[it, ir] > 1.0e20:
255                        io.write(io.ishort, f"{ID} problem it,ir,l3,k3,iq,ip="
256                                 f"{it:5d}{ir:5d}{m.l3:5d}{m.k3:5d}"
257                                 f"{iq:5d}{ip:5d}")
258                        io.write(io.ishort, "".join(
259                            f"{e.epl[ms, it, ir]:12.4e}"
260                            for ms in range(mg, mg + 3)))
261                    a.esk[it, ir] = (a.esk[it, ir] * dixr
262                                     + a.esk2[it, ir] * (1.0 - dixr))
263                    is_ = 1
264
265        # Interpolate in T6 and rho (overlapping quadratics on 4x4)
266        # (Fortran lines 467–475).
267        is_ = 0
268        t6rinteos06(slr, slt)
269        m.eos[iv] = m.esact
270
271    # Unscale: P was tabulated as P/(T6 rho), E as E/T6; then c_V, or the
272    # radiation (Fortran lines 477–486).
273    # Suspected bug (see the page): with iorder < 5, eos(2) and eos(5) are
274    # left from an earlier call, and are rescaled again here.
275    p0 = t6 * r
276    m.eos[m.iri[1]] = m.eos[m.iri[1]] * p0
277    m.eos[m.iri[2]] = m.eos[m.iri[2]] * t6
278    tmass, moles, eground, fracz = gmass06(xh, z, moles, 0.0, 0.0, frac)
279    if irad == 1:
280        radsub06(irad, t6, r, moles, tmass)
281    else:
282        m.eos[m.iri[5]] = m.eos[m.iri[5]] * moles * APROP / tmass
283    return False
