Purpose

This file finds the convective and radiative regions of a model: the boundaries of each convection zone, without and with overshoot, the edge of the convective core (JCORE) and the base of the convective envelope (JENV), and the radiative regions between them. Its header stresses that overshoot here means "overmixing": overshoot shells are mixed with the convection zone but keep the radiative temperature gradient.

How it fits

  • Inputs: the arguments LC (convective or not, per shell, from COEFFT via the structure solution; set by the Schwarzschild test $\nabla_\mathrm{rad} > \nabla_\mathrm{ad}$ in TPGRAD, so composition gradients play no part in the zone edges unless semiconvection, LSEMIC in SCONVEC, is on), M, and the model (HCOMP, HD, HP, HR, HS, HT), which only OVERSH uses; the overshoot switches LOVSTC, LOVSTE, LOVSTM (core, envelope, intermediate zones) in NMLPAR_MOD; the unit ISHORT from IOUNITS_MOD.
  • Who calls it: the main program (main.f), MIX, GETW and OVROT.
  • What it calls: OVERSH, which moves the zone edges outward by the overshoot distance.
  • Outputs: MXZON0, NZONE0 (the zones without overshoot), MXZONE, NZONE (with overshoot, after merging zones that overlap), MRZONE, NRZONE (the radiative regions), JCORE, JENV (both before overshoot). MIX uses the zones to treat burning in radiative and convective regions differently; OVROT (which sets the flags LCZ from them), ROTMIX and MIDMOD also loop over the radiative regions; JENV is used throughout the code. The callers take the zones with overshoot, MXZONE, for burning and mixing; MXZON0 (the formal zones) serves only inside, in OVERSH (its printout, and the LINSTB test of whether overshoot moved an edge), and JCORE, JENV are the formal edges.

The method

  1. Scan the shells for runs of convective shells; a run of a single shell is ignored (the test I1.NE.I-1). At most 11 zones: as soon as the 11th is stored, the routine prints "TOO MANY MIX ZONES" (whether or not more follow) and stops the scan.

    Question 1 (lines 96–103↗). One-shell zones. A single convective shell is treated as radiative (the test I1.NE.I-1). Is this a deliberate filter against noise in LC? 2. No zone: JCORE = 1, JENV = M, one radiative region. One zone covering the whole star: fully convective, JCORE = JENV = 1, NRZONE = 0 (MRZONE is left as it was; every reader loops from 1 to NRZONE, so none reads it), and overshoot and merging are skipped. 3. JCORE is the top of a zone starting at shell 1; JENV the bottom of a zone ending at shell M.

    The header names the zones in the reverse order. It says JCORE and JENV are "THE EDGES OF THE SURFACE AND CENTRAL CONVECTION ZONES RESPECTIVELY" (lines 67–69↗), but the code makes JCORE the core's outer edge, from MXZONE(1,2), and JENV the envelope's base, from MXZONE(NZONE,1) (lines 129–150↗), so the header should say "central and surface." 4. If any overshoot switch is on, call OVERSH, then merge zones whose (overshot) edges now meet, with a message to ISHORT. 5. The radiative regions: below the first zone, between zones, above the last (but see bug 1).

Suspected bugs, checked by running the code

Each bug is marked by what running the code showed: (changes results, large) or (small), the fix moving a run clearly beyond a null change; (stops the run); (wrong output), the fix changing only what is written; (harmless in the runs), within the noise; (never occurred), the code ran but the fault did not; (not reached); (cannot be reached), a guard prevents it; (withdrawn), the suspicion was wrong.

1. (harmless in the runs) The upper edge of the last radiative region is written to the first.

(lines 200–205↗) For a radiative region above the last convection zone, the code sets MRZONE(1,2) = M instead of MRZONE(NRZONE,2) = M. When that region is the only one (a convective core under a radiative envelope), the two are the same element and nothing goes wrong. When it is the second or a later one (a radiative surface and at least two radiative regions, for example a radiative core, a thin convection zone, and a radiative surface, or a convective core, an intermediate convection zone, and a radiative surface), the top region's upper edge keeps an old value and the first region's upper edge becomes M. What follows: MIX then burns the shells of the convection zones above the first region one by one, as radiative (up to the TCUT(1) cutoff, mix.f, lines 249–261↗), before it treats each zone as a unit, which recomputes those shells from the start of the step (see below); ROTMIX and MIDMOD treat those shells as radiative too (OVROT sets the convective flags after the radiative ones, so its LCZ comes out right). On the default path whenever a model has a radiative surface and two or more radiative regions.

76        mxzon0[i, 1] = mxzone[i, 1]
77        mxzon0[i, 2] = mxzone[i, 2]
78    nzone0 = nzone
79
80    # The outer edge of the convective core (JCORE) and the inner edge of
81    # the convective envelope (JENV), before overshoot (Fortran lines
82    # 129–150).
83    if mxzone[1, 1] == 1:
84        if mxzone[1, 2] == m:
85            # A fully convective star (MRZONE is left as it was).
86            jcore = 1
87            jenv = 1
88            nrzone = 0
89            return jcore, jenv, nrzone, nzone, nzone0  # GOTO 9999
90        else:
91            jcore = mxzone[1, 2]
92    else:
93        jcore = 1
94    if mxzone[nzone, 2] == m:
95        jenv = mxzone[nzone, 1]
96    else:
97        jenv = m
98
99    # Overshoot, if any switch is on: oversh moves the edges in mxzone;
100    # then merge zones whose edges now meet (Fortran lines 151–182).
101    if n.lovstc or n.lovste or n.lovstm:
102        oversh(hcomp, hd, hp, hr, hs, ht, m, mxzone, mxzon0, nzone)
103        if nzone != 1:
104            j = 1
105            while True:  # label 85
106                if mxzone[j, 2] >= mxzone[j + 1, 1]:
107                    # Two convection zones have merged.
108                    iounits_mod.write(
109                        iounits_mod.ishort,
110                        '  CONVECTION ZONES MERGED DUE TO OVERSHOOT\n'
111                        f'  OLD[{mxzone[j, 1]:3d}-{mxzone[j, 2]:3d}]'
112                        f'[{mxzone[j + 1, 1]:3d}-{mxzone[j + 1, 2]:3d}]'
113                        f' NEW[{mxzone[j, 1]:3d}-{mxzone[j + 1, 2]:3d}]')
114                    mxzone[j + 1, 1] = mxzone[j, 1]
115                    for k in range(j, nzone):
116                        for j2 in range(1, 3):
117                            mxzone[k, j2] = mxzone[k + 1, j2]
118                    nzone = nzone - 1
119                    if j <= nzone - 1:
120                        continue  # GOTO 85
121                    break  # GOTO 100
122                j = j + 1
123                if j <= nzone - 1:
124                    continue  # GOTO 85
125                break
126
127    # label 100: the radiative regions (Fortran lines 183–205).
128    # Below the first convection zone.
129    if mxzone[1, 1] > 1:
130        nrzone = 1
131        mrzone[1, 1] = 1
132        mrzone[1, 2] = mxzone[1, 1] - 1
133    else:
134        nrzone = 0
135    # Between convection zones.
136    if nzone > 1:
137        for i in range(1, nzone):
138            nrzone = nrzone + 1
139            mrzone[nrzone, 1] = mxzone[i, 2] + 1
140            mrzone[nrzone, 2] = mxzone[i + 1, 1] - 1
141    # Above the last convection zone.
142    if mxzone[nzone, 2] < m:
143        nrzone = nrzone + 1
144        mrzone[nrzone, 1] = mxzone[nzone, 2] + 1
145        # Suspected bug (see the page): MRZONE(1,2), not MRZONE(NRZONE,2).
146        mrzone[1, 2] = m
147
148    # label 9999
149    return jcore, jenv, nrzone, nzone, nzone0
