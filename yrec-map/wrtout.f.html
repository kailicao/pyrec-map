Purpose

WRTOUT writes the output of each converged model: a summary block in the short output, one line (or block) per model in the track file, the last model for restarting, and, at the chosen intervals, the detailed profiles (through PUTSTORE, which also calls STITCH, and WRTMOD). On the way it computes the summary quantities: convection-zone masses and the zone's base, the central conditions, the radius and gravity, neutrino capture rates, moments of inertia and rotation period.

How it fits

  • Inputs: the model and its run data through arguments (from the main program; CMIXL, XMSOL and COMPMIX are only passed on), and through modules: the per-shell physics (SCRTCH_MOD), the neutrino fluxes (FLUXES_MOD, from ENGEB), the output switches and options (NMLPAR_MOD: LTRACK, ITRVER, LSTORE, NPRTMOD, LPULSE, LMILNE, LROT, LSNU, LKUTHE; ACDPTH_MOD: LACOUT, LADON, LJLAST), the composition (COMP_MOD, LABEL_MOD), the constants (CONSTANTS_MOD), $\tau_\mathrm{cz}$ and $P_\mathrm{phot}$ (OVRTRN_MOD).
  • Who calls it: the main program, main.f, after each model.
  • What it calls: EQSTAT (central conditions), GETTAU (track version 0), WRTLST (the last model, ILAST; also IJLAST), PUTSTORE, WRTMIL, WRTMOD and CALCAD (acoustic depths).
  • Outputs: ISHORT (summary block), ITRACK (track; the header comes from WRTHEAD), and the files written by the routines it calls. In CENT_MOD, it stores $\log T_c$, $\log P_c$, $\log\rho_c$ and the convection zone's base (CZsurf_M, CZsurf_R, formerly ENVLM, ENVR), read by the main program for its ISNU output (WRTMONTE, which also read them, removed since rp_1); in FLUXES_MOD, the Cl and Ga rates CLSNU, GASNU; in OVRTRN_MOD, TAUCZ0 and PPHOT0.

The method

  1. Luminosity terms TLUMX (pp I–III, CNO, triple-α, He–C, gravity, neutrinos) are rescaled so that they sum to the surface luminosity (not during the helium flash). The factor, $L$ divided by the unscaled sum, is not written out. (LTSCAL, set to false at line 176↗, is never read: unused?)

    Question 1 (lines 177–185↗). The unscaled luminosity sum. The rescaling of TLUMX hides the mismatch between the sum of the sources and the surface luminosity. Is that mismatch the numerical error of the energy equation, or does it include terms the sum leaves out? How large is it typically, and could the factor be written to the track or the short output as a check of energy conservation?

  2. Radius and gravity: $\log R = \tfrac12(\log L + \log L_\odot - \log 4\pi - \log\sigma - 4\log T_\mathrm{eff})$, $\log g = \log G + \log M - 2\log R$; $M_\mathrm{bol} = $ CMBOL $- 2.5\log(L/L_\odot)$. So $R$ is the radius that $L$ and $T_\mathrm{eff}$ define through $L = 4\pi R^2\sigma T_\mathrm{eff}^4$, not the outermost model point, which lies at the envelope's fitting point (HR(M)). $\log M$ here is STOTAL, the copy of HSTOT in COMP_MOD.

    Question 2 (line 223↗). CMBOL = 4.79. SETUPS sets $M_{\mathrm{bol},\odot} = 4.79$; the IAU 2015 Resolution B2 nominal value is 4.74 (for $L_\odot = 3.828\times10^{33}$ erg/s), and with the code's own $L_\odot$ (CLSUN = $3.8515\times10^{33}$ erg/s) that zero point gives about 4.73. Is 4.79 an intended older convention, and should it follow the solar luminosity in use?

  3. Central conditions, extrapolated from shell 1 (mass $m_1$, radius $r_1$ from $m_1 = \tfrac{4\pi}{3}\rho_1 r_1^3$): $$P_c = P_1 + \tfrac12\,\frac{G m_1 \rho_1}{r_1},\qquad \log T_c = \log T_1 + \log\!\left(1 + \nabla_1\,\frac{P_c - P_1}{P_1}\right),$$ then the equation of state (EQSTAT, with the Debye–Hückel composition set first when LDH) gives $\beta$, $\eta$ there. Its argument KSAHA, a counter that EQSAHA increments (eqsaha.f, line 95↗), is passed unset; WRTOUT never reads it back, so its value does not matter (settled from the code, Nov 9, 2026: lines 251–253↗).

  4. Base of the surface convection zone: where $\nabla_\mathrm{rad} - \nabla_\mathrm{ad}$ (SDEL(1) − SDEL(3)) changes sign between shells JENV-1 and JENV, by linear interpolation; its mass above (CZsurf_M, $M_\odot$), radius (CZsurf_R, $R_\odot$), $T$, $\rho$, $P$, $\kappa$ (the locals CZsurf_T, CZsurf_D, CZsurf_P, CZsurf_O). The convective core's radius CORER (JVS 10/11, lines 212–221↗) is computed and never used (unused?, with FX2 and CORERL): FX2 is always 1 (or 0/0), and the radius is interpolated with FX, left at that point from the previous model's step 4.

  5. Hydrogen shell (LSHELL): masses at its middle, its total and the helium core's, and the temperature maximum (for the helium flash, the first maximum above $\log T = 7.98$).

    Question 3 (lines 382–384↗). The helium flash's threshold. The temperature maximum during the helium flash is the first one above $\log T = 7.98$, a hard-coded value. Where does it come from, and should it be a setting?

  6. Neutrino detectors: capture rates as linear combinations of the eight fluxes (pp, pep, hep, $^7$Be, $^8$B, $^{13}$N, $^{15}$O, $^{17}$F) with cross sections (from Bahcall's book, p. 207, table 8.2, by the comment) for $^7$Li, $^{37}$Cl, $^{71}$Ga, $^{81}$Br, $^{98}$Mo, $^{115}$In; and for the track, Cl and Ga in SNU with a second table (CLSNUF, GASNUF, "Neutrino Astrophysics p. 207," with $^{37}$Cl changes after Bahcall & Pinsonneault). The summary's labels give these rates and the fluxes in erg (bug 2).

    Question 4 (lines 404–413↗; lines 165–171↗). Two tables of cross sections. The $^{37}$Cl rate printed in the summary uses 1.09×10⁴ for $^8$B (FL37CL), the track's CLSNU 1.14×10⁴; the Ga values differ too (for example $^7$Be: 73.2 against 71.7). Which are current?

  7. Track (LTRACK): the total moment of inertia (with rotation $\sum I_j$, otherwise $\sum \tfrac23 \Delta m_j r_j^2$), the surface zone's, the rotation period $P = 2\pi/\Omega_s$ in days and $v = \Omega_s R$ in km/s; then, by ITRVER, one line per model (0, after calling GETTAU for $\tau_\mathrm{cz}$ and $P_\mathrm{phot}$), or several lines (1, 2), or a short line (3). For version 0 without LSNU, the fluxes FLUXTOT are set to zero (lines 459–463↗); without LSNU they are never accumulated (coefft.f, lines 150–155↗; coefft.f, lines 304–309↗), and their other reader, the main program's ISNU output, runs only with LSNU (main.f, line 1195↗), so this changes nothing read later (settled from the code, Nov 9, 2026). The headers that WRTHEAD writes for versions 1–3 do not match these lines (wrthead.f, suspected bug 1).

    Question 5 (line 470↗; lines 596–598↗). The period's cap. Version 0 still caps the rotation period at 9999 days, while versions 1 and 2 no longer do (MHP 8/25). Should version 0 follow?

  8. Model files: the last model to ILAST every time; the detailed output through PUTSTORE every NPRTMOD models if LSTORE (with LSTCH, PUTSTORE also writes the stitched profile); otherwise, with LPULSE, WRTMIL and WRTMOD; with LACOUT, acoustic depths through CALCAD and a second track line (format 1800). LACOUT is in no namelist and nothing sets it, so this last branch never runs (see ACDPTH_MOD).

    Question 6 (lines 696–725↗). The acoustic-depth line. If LACOUT is turned on, each model with ITRVER = 0 writes a format-1499 line and a format-1800 line to ITRACK, with different columns (1800 has acoustic quantities in place of rotation ones, and ICHECK); the 1800 line writes CLSNU, GASNU, SSS1–RRR3 and TAUCZ, which are set only with LTRACK (lines 431–644↗); and CZsurf_RL, passed to CALCAD, is set only when the base of the convection zone is inside the model (lines 262–278↗). Without these, the values come from earlier models. Is the acoustic line meant for a separate file, and should these values be computed for it?

For users (from YREC's Quick Start, Understanding the output). The .track file is the run's history: one line per model of its global properties (age, luminosity, effective temperature, central temperature and pressure, and so on), not its interior structure, which goes to .store; ITRVER = 0, one line per model, is the format the test suite uses. The .short file holds the numerical details of each model (with LRWSH, the main program rewinds it so that only the last model's remain). The .last file, rewritten after every model, is the last converged model, readable by YREC as a starting model. The documentation's two deprecated outputs, .full and .excomp, are not written here: the light-element history that .excomp held is now in the track.

From YREC's documentation

Control Options (Output): NPRTMOD writes the detailed structure every NPRTMOD models (negative: none of the intermediate ones, though the final model can still be written with LSTPCH); LTRACK writes the global properties to the .track file ("should almost always be on"); ITRVER chooses the track format, and the documentation strongly recommends 0 (one line per model), while the default is 1; LRWSH keeps only the last model's details in the .short file.

50def _e(v, w, d, e=2, scale=1):
51    """Fortran Ew.d (Ee) under the scale factor 1P (scale=1: d.ddd) or 0P
52    (scale=0: 0.ddd). With e = 2 an exponent beyond 99 drops the 'E', as
53    Fortran does; a field too narrow is filled with '*'."""
54
55    digits = d + 1 if scale == 1 else d
56    m, x = f"{v:.{digits - 1}E}".split('E')
57    x = int(x)
58    if scale == 0:
59        sign = '-' if m.startswith('-') else ''
60        m = sign + '0.' + m.lstrip('-').replace('.', '')
61        x = 0 if v == 0 else x + 1
62    if e == 2 and abs(x) > 99:
63        text = f"{m}{x:+04d}"
64    else:
65        text = f"{m}E{x:+0{e + 1}d}"
66    return text.rjust(w) if len(text) <= w else '*' * w

69def _es(values, w, d, e=2, scale=1):
70    """A repeated E descriptor."""
71
72    return ''.join(_e(v, w, d, e, scale) for v in values)

77
78    text = f"{v:.{d}f}" + ('.' if d == 0 else '')
79    return text.rjust(w) if len(text) <= w else '*' * w
