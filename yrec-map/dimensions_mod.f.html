Explanation

Purpose. DIMENSIONS_MOD holds JSON = 5000, the maximum number of shells in a model, the one structural array dimension shared by the whole code (MHP via Claude, 10/15/26). It replaces the statement PARAMETER(JSON=5000) that 108 files repeated at rp_1; it is not a COMMON block.

Who uses it. 144 files: the routines that dimension arrays by the number of shells, and, since 10/20/26, the 36 block modules sized on JSON (such as DEUTER_MOD), which used to declare private copies. The module must be compiled before them (the Makefile says so).

Design. The header explains what stays out: the dimensions of the input tables (such as NUMT, 70 for the OPAL95 opacities and 85 for Alexander 2006) differ between tables and stay PRIVATE in each table's module, and scratch bounds such as NMAX stay local to their routines. A file that gains USE DIMENSIONS_MOD must drop its own PARAMETER(JSON=5000).

Changed since rp_1. New file: the repeated PARAMETER(JSON=5000) as a module.

code changed to hold the code's own structural array dimensions in
one place, replacing a PARAMETER statement repeated in every file
that needed it.

JSON is the maximum number of shells.  It is a property of the
code's own arrays, not of any input data file, so one global value
is correct by construction: there is no table that could want a
different JSON.  It was declared identically as PARAMETER(JSON=5000)
in 108 files.

This module deliberately holds ONLY dimensions of that kind.  The
input-table dimensions do NOT belong here, because the same name
carries different values for different tables: NUMT is 70 for the
OPAL95 opacities and 85 for Alexander 2006, NT is 57 for the
surface-pressure tables and 197 for the OPAL06 equation of state,
and NTA/NGA differ between the old and current Allard formats.  One
module cannot hold NUMT twice.  Each table module declares its own
PRIVATE copy instead, so those values coexist by scope with no
renaming -- see KNOWN_ISSUES.md issue 26.

Per-routine scratch bounds are excluded for the same reason: NMAX is
15, 42, 100 and 8000 in five different routines, sizing local
workspace.

PUBLIC, since exporting it is the entire point.  A file gaining
USE DIMENSIONS_MOD must drop its own PARAMETER(JSON=5000): keeping
both is a conflict error.
10/20/26 MHP via Claude
code changed to note that the 36 block modules dimensioned on JSON
now USE this module too, in place of their own PRIVATE copies, so
every module that needs JSON is compiled after this one (Makefile).
