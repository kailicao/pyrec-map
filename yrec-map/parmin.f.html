Purpose

PARMIN reads a run's parameters and sets up its input and output. It holds the defaults of a few user parameters (most defaults are now initializers in the modules), reads the two namelist files (CONTROL, usually yrec8.nml1, and PHYSICS, usually yrec8.nml2), expands placeholders in file names, derives some parameters from others, opens most output files and several tables, writes the run's settings to the .short file, and interprets the "run cards" (the sequence of evolve and rescale steps). It is the code's single place of configuration.

How it fits

  • Inputs: the two namelist files, named on the command line (GETARG(1) and GETARG(2); JVS 02/11) or defaulting to yrec8.nml1 and yrec8.nml2; the code's version and git hash, YRECVER and GITHASH (arguments, from SETVERSION through the main program; formerly /VERSION/); the environment variables YREC_INPUT, YREC_START and YREC_OUTPUT, if set. GETARG, getenv and system (line 758↗, line 1527↗, line 828↗) are compiler extensions; standard Fortran has GET_COMMAND_ARGUMENT, GET_ENVIRONMENT_VARIABLE and EXECUTE_COMMAND_LINE.
  • Who calls it: the main program in main.f, once, first.
  • What it calls: EXPAND_VALUE (in this file), the shell through system (mkdir -p for the output folder), and REMAP, which maps the newer, "more intuitively named" parameters (MHP 6/14, 10/14: TIME_…, TOL_…, FLAG_…) onto the older vectors ATIME, HPTTOL and the like.
  • Outputs:
  • Arguments: 12 table file names (FALEX06, FALLARD, FATM, FFERMI, FLIV95, FPATM, FPENV, FPMOD, FPUREZ, FSCVH, FSCVHE, FSCVZ), which the main program passes on to SETUPS and other set-up routines. Since MHP 8/25, file names travel as arguments rather than in COMMON blocks, "as character strings in common blocks can cause problems".
  • Modules: 11, almost all of them for the run's parameters. The namelists read straight into module variables: NMLPAR_MOD holds those the physics routines read, NMLBYPASS_MOD those that only set others (the cross sections, the TIME_… and TOL_… parameters for REMAP, the wind-law indices), and CONSTANTS_MOD (CLSUN, CRSUN, and CLN, CC13, CC23, C_2 set here) and INTPAR_MOD (STOLR0, IMAX, NUSE) a few more. The others: IOUNITS_MOD (every unit number), RUNLOOP_MOD (the run cards: RESCAL, IRESCA, LENDAG, LSETDT), COMP_MOD (ZENV, bug 3), CCOUT_MOD (LPHHD), ACDPTH_MOD (LACOUT), LABEL_MOD and NEWOPAC_MOD. The site's modules.html lists every module and its users.
  • Files opened: the .short diagnostic file (ISHORT, unit 20), the stored models (ISTOR, with a header if LSTORE), the first model (IFIRST, read), the last model (ILAST), the per-shell file (IMODPT), and as switched on: the track, solar neutrinos, debugging, Milne variables (appended), pulsation files, the conductive opacities, the OPAL 2006 EOS table, the acoustic-depth file (…calcad, named after the .short file) and, always, the sound-speed file FSOUND (default Csound.dat, unit ISOUND), which WRTMOD writes when LSOUND is on. Before that it creates the output folder, the path of FTRACK up to its last /.
  • Unit numbers: fixed here, from IOWR = 6 (the screen or status file) to 90 (IALEX06); for example the OPAL EOS table is 49, and ISOUND is 500.

What it does, in order.

  1. Defaults. Most are now initializers in the modules (NMLPAR_MOD, NMLBYPASS_MOD, CONSTANTS_MOD, INTPAR_MOD); PARMIN's own DATA keep those of the run cards, the mixture table, ALFA, FK, WMAX_SUN, AWIND, FSOUND and blank file names. Among the defaults, as their comments state: the cross sections of Solar Fusion II (Adelberger et al. 2011) and their derivatives (S0_…, S0P_…, S0PP_…); Li and Be destruction cross sections (Fowler et al. 1967, Rolfs & Kavanagh 1986, Fowler 1988); the GS98 CNO fractions and $Z/X = 0.02292$ and the Lodders et al. (2021) isotope ratios and light-element abundances; alternative mixtures AAG21, M22P, M22M (Asplund et al. 2021; Magg et al., given as 2021 in the comment); a G&N93 mixture VNEW for the envelope; $L_\odot = 3.8515\times10^{33}$ erg s⁻¹ and $R_\odot = 6.9598\times10^{10}$ cm; the burning cutoffs TCUT. The mixing length has no default any more: the old CMIXL $=1.4$ never reached the run, which takes CMIXL = CMIXLA(NK) in the main program for each run card.

  2. Namelists. Both files are read and REMAP is called. Then EXPAND_VALUE expands a leading placeholder in each file name (bug 5), and the output folder is created (bug 4).

    Question 2 (line 380↗, line 382↗, line 387↗, line 775↗). Old entries that REMAP overwrites. DTDIF, DTWIND, HPTTOL and ATIME are superseded by REMAP's new parameters when those are used (LNEWVARS). Can the old entries be removed, or kept with a warning? (LSOLWIND now reaches MDOT through NMLPAR_MOD, but MDOT's scaled solar wind stays inert: its constants DMSUN, DMWSUN, DMWMAX are zero, and a guard skips the branch; MDOT's page.)

  3. Derived settings.

  4. Li/Be cross sections given by the user (LXLI6 and so on) become scale factors relative to the defaults, e.g. SLI6 = XSLI6/5.5D3.

  5. Semiconvection together with any overshoot stops the run. Rotation (LROT) with the advection-diffusion transport of angular momentum (LDIFAD) stops it too: as the code's comment says, DADCOEFT rebuilds its coefficients from equal-grid arrays that no routine sets, so the option is not implemented.

    Question 3 (lines 980–989↗). Semiconvection with overshoot stops the run. LSEMIC with any of LOVSTC, LOVSTE, LOVSTM prints "SEMI-CONVECTION AND OVERSHOOT FLAGS BOTH TURNED ON" and stops. Both act at the edge of a convective core, and a student would expect them to be combined (overshoot beyond a semiconvective zone). Is it that OVERSH and SCONVEC both rewrite the same boundary zone? A comment in GETOPAC (JCZ 211125) mentions "semiconvection+overshoot HB models", which this check forbids: is a combined treatment planned, or does that comment refer to another code?

  6. Rotation (LROT): WALPCZ is limited to $[-2, 0]$; LSOLID forces IMPJMOD = 1. For the old wind law (LMWIND false), from the index $\alpha$ (ALFA), as the comments derive: $$\dot J = f_K\, 2.036\times10^{33}\,(1.452\times10^{9})^{\alpha}\left(\frac{\dot M}{10^{-14}}\right)^{1-2\alpha/3}\Omega^{1+4\alpha/3}\left(\frac{R}{R_\odot}\right)^{2-\alpha}\left(\frac{M}{M_\odot}\right)^{-\alpha/3}.$$ This is the Kawaler (1988) law (as the documentation names it); $\dot M$ is "in solar masses per year" (fixed at $2\times10^{-14}$ in COWIND and WIND) and $M$, $R$ relative to the Sun's, as their comments say.

    Question 4 (lines 1028–1040↗). The units of the old wind law. The comments give $\dot M$ in $M_\odot\,\mathrm{yr}^{-1}$ and $M$, $R$ in solar units, but not the units of $\Omega$ and $\dot J$. The rest of the code works in cgs, which suggests $\Omega$ in rad s⁻¹ and $\dot J$ in g cm² s⁻² (COWIND and WIND multiply by the step DT, so that they return a change of $J$ in g cm² s⁻¹): is that right?

    For the Matt et al. law (LMWIND), the indices $a, b, c, d, m$ (PMMA…PMMM), preset by AWIND ('K97': Krishnamurthi 1997, $m = \alpha/3$; 'V13': van Saders & Pinsonneault 2013, $m = 0.22$; 'CUS': from the namelist), give the exponents of $\dot J$, each quantity relative to the Sun: $$a_\Omega = 1 + a - 2am + 4mb,\quad a_R = 2 + 5m - 4mc,\quad a_M = -m,\quad a_L = 1 - 2m,\quad a_P = 2md,\quad e_\mathrm{cen} = md,$$ with $a_\tau = 0$ (the $\tau_\mathrm{cz}$ term is now applied in MWIND), $c_2 = 0.0506$, CONSTFACTOR $= f_K\,J_\odot/\Omega_\odot^{a_\Omega}$, and, if WMAX_SUN $< 1000$, the saturation threshold $\Omega_\mathrm{sat} = $ WMAX_SUN $\times\,\Omega_\odot$.

    Question 5 (lines 1062–1073↗, lines 1097–1098↗). The exponent of $R$ in the Matt et al. law. The comment's derivation gives $\dot J \propto R^{2+5m+4mbc}$, but the code (after JvS 09/25, "removed typo", which dropped a factor $b$) uses $a_R = 2 + 5m - 4mc$. For 'V13' ($c = 0$) the two agree. For 'K97' ($b = 1$, $c = 2$, $m = \alpha/3$) the code gives $2 - 3m = 2 - \alpha$, the exponent of the old law, while the comment would give $2 + 13m$; a custom law ('CUS') with $c \ne 0$ depends on the choice, and with $b \ne 1$ also on the dropped factor. Is the code's exponent the intended one, so that only the comment is stale?

  7. Composition changes: a single species to rescale (LNEWCP, ANEWCP), a CNO mixture (ISETMIX, AMIX, with checks on a custom one) and isotope ratios (ISETISO, AISO), all applied later to the starting model by STARIN (the documentation's value 2 for a custom mixture does nothing: bug 2).

  8. Settling switches: LDIFZ turns on LDIFY and LTHOUL; LDIFLI turns on LNEWDIF, LDIFY, LDIFZ, LTHOUL, turns off LTHOULFIT, and sets ILAMBDA = 4.
  9. Summary. A line of tolerances and rotation settings is written first, right after the semiconvection and LDIFAD checks. After the derived settings, the PHYSICS and CONTROL namelists are written to ISHORT as read, and the output-only namelist DERIVED with the values derived above (the wind-law exponents, the settling switches, the mixture, LREL, …). Then the mixing lengths are checked: each CMIXLA entry the run uses (only CMIXLA(1) under solar calibration, LCALS, otherwise the first NUMRUN, at most 50) must be positive, or the run stops; so must the envelope triangle's size, TRIDT and TRIDL. Then the atmosphere choice (KTTAU 0–5), and the run's description with the version line (# YREC v…, also written at the head of the .store file and the track).
  10. Run cards (NUMRUN cards, at most 50): KINDRN = 1 evolves NMODLS models (to an age, a central D, X or Y, or with a fixed time step); 2 rescales the model (mass, $X$, $Z$, core mass) and relaxes it; 3 rescales and evolves. LENDAG and LSETDT are set only for evolve cards (lines 1396–1406↗), so the stop conditions (ENDAGE, END_XCEN, END_YCEN, …) are ignored on a rescale-and-evolve run: suspected bug 1, whose fix belongs here. The message of a rescale-and-evolve card is that of a rescale card (bug 1), and each card sets ZENV (bug 3).

Design

PARMIN is a 1,508-line routine that is mostly comments, declarations and data. A parameter now lives in one place, the module variable the namelist reads into. A few namelist entries are still unused (see the question at step 2).

From YREC's documentation

Control Options:

  • Placeholders. {YREC_INPUT}, {YREC_START}, {YREC_OUTPUT} at the start of a path in the CONTROL namelist are replaced by the environment variable of that name, or by a default: the documentation gives ../../input, ../../input/models and output (in the working directory). PARMIN uses ../../startmodels for {YREC_START} (lines 1515–1516↗), and the repository keeps its starting models in startmodels/ (there is no input/models/), so the documentation's default and the "input/models" of the User Guide and the Quick Start are out of date (settled from the code and the repository, Nov 9, 2026).
  • File names. FFIRST the starting model, FLAST the last converged model, FSTOR the snapshots, FTRACK global quantities against time, FSHORT the numerics of the run; FMODPT, FSNU, FSCOMP are "no longer used" (light elements are now in the track). Two of them are still opened and written: FSNU (opened with LSNU, lines 946–950↗) by the main program (lines 1209–1229↗), and FMODPT (always opened, line 965↗) by PARMIN's description of the run (line 1364↗), line 152↗ and lines 486–498↗ (settled from the code, Nov 9, 2026). Table paths are on the pages of the routines that read them.
  • Read here only. KINDRN, RSCLM, RSCLX, RSCLZ, RSCLCM (the run cards, below); AMIX, AISO, ISETMIX, ISETISO (the mixture, STARIN's page); AWIND, FK, ALFA, WMAX_SUN (the wind law, MWIND's page; the Physics page lists ALFA as "Not used. Legacy exponent for Kawaler (1988) wind law", namelist_physics.md line 311, and the modules page calls ALFA and FK exponents, but ALFA, default 1.5, sets the old law's exponents and CONSTFACTOR when LMWIND is off, and PMMM = ALFA/3 for AWIND = 'K97', the default, lines 1036–1040↗, line 1077↗; FK is a scale factor); LXLI6…LXBE93 with XSLI6…XSBE93, manually set p+⁶Li, p+⁷Li and the three p+⁹Be cross sections (keV b; the documentation labels LXBE92 and LXBE93 as p+⁶Li channels, a slip for ⁹Be).

  • Run cards (Run parameters & Kind cards): each card is a phase, KINDRN(i) = 1 evolve, 2 rescale (zero time step, main sequence or core helium burning), 3 rescale and evolve (pre-main sequence, which has no zero-time-step solution); LFIRST(i) starts from FFIRST rather than the previous phase's model; RSCLM, RSCLCM, RSCLX, RSCLZ, if positive, rescale to that mass, core mass (core helium burning only), $X$, $Z$; CMIXLA(i) is the mixing length to rescale to (or run with); LSENV0A(i) moves the outer fitting point to SENV0A(i), which the Control page calls the log of the fractional envelope mass ($10^{-4}$ standard, $10^{-7}$ thin), but which is $\log_{10}(m_\mathrm{fit}/M_\star)$ of the fitting point, a small negative number (as the User Guide says: $-10^{-4}$ standard, about $2\times10^{-4}$ of the mass outside the fitting point; $-10^{-7}$ thin; STARIN negates a positive value; STARIN's page, step 6); NMODLS(i) stops after that many models (two for a first rescaling is recommended, then an evolve run); ENDAGE, END_DCEN, END_XCEN, END_YCEN stop at an age or a central D, $X$ or $Y$.

    Question 6 (lines 586–591↗). SENV0A in the documentation. The Control page calls SENV0A(i) "Log of fractional envelope fitting point mass. 1e-4 standard, 1e-7 thin", which reads as $\log$ of $10^{-4}$; the code (STARIN: SENV = HS(M) - HSTOT) and the User Guide make it $\log_{10}(m_\mathrm{fit}/M_\star)$, a small negative number ($-10^{-4}$ puts $1 - 10^{-10^{-4}} \approx 2.3\times10^{-4}$ of the mass outside the fitting point). STARIN negates a positive value, so the Control page's numbers work, but their meaning is not the one it gives. Also, STARIN's floor is $-10^{-12}$, while the User Guide says $-10^{-11}$. From the user documentation (User Guide, Quick Start):

  • Reading the namelists. The two files are read in a fixed order, the first argument as CONTROL (unit ISTAND) and the second as PHYSICS (unit IRUN); the Python wrapper accepts them in either order, the program does not. They are opened by the names given, so a relative name is found from the working directory; the User Guide says both files should be in the executable's directory (userguide.md, line 23).

    Question 7 (lines 766–767↗). Where the namelists are looked for. PARMIN opens the two files by the names given (OPEN(UNIT=ISTAND, FILE=YREC1, …)), so they are found from the working directory, wherever the executable is. Should the User Guide say "the working directory" (or give paths), or is the executable's directory meant to be searched?

  • The output folder. PARMIN now creates the folder of FTRACK (mkdir -p) before any output is opened, while the Quick Start still tells the user to mkdir output by hand, or the run fails; the step is no longer needed (bug 4 for the case of a name without /).

Where Namelist Variables Live gives the reasons for the modules' split (on NMLBYPASS_MOD's page) and why CHARACTER variables are passed as arguments: in a COMMON block they force padding against numeric members, which compilers treat differently.

Change log

The changes since rp_1

Changed since rp_1. The namelists read into modules (NMLPAR_MOD, NMLBYPASS_MOD), where most defaults now are; the removed options are gone (the MHD and OPAL 1995/2001 equations of state, the OPAL92, Kurucz 1990, LAOL89 and Alexander 1995 opacities, Monte Carlo, isochrones), and with them 15 file-name arguments; YRECVER and GITHASH are new arguments, printed and written as a version line; file names may start with a placeholder (EXPAND_VALUE, new), and the output folder is created; the sound-speed file is opened here; the hand-written summary tables are replaced by namelist echoes after ISHORT is opened, with a new DERIVED namelist; TENV is no longer set (ENVINT computes it); the default CMIXL is removed and CMIXLA is checked; PMMM = 0.22 and C_2 = 0.0506 are now double-precision constants; LPMM, PMMWMAX, ZOPAL952 and ZALEX2 are no longer namelist entries. Settled: the namelist dump before OPEN(ISHORT), the printing slip in TRIDT, TRIDL and the stale "standard" values (old questions 1, 3, 4), and part of old question 6 (the unused entries; LSOLWIND now reaches MDOT).

Changed since 09c3b9b. The CONTROL namelist gains L_ZERODT_PREMS (in NMLPAR_MOD, used in main.f), so it is read and echoed to the .short file with the others.

Changed since a8a5950. Two new checks stop the run: LROT with LDIFAD (exit status 1), and a non-positive TRIDT or TRIDL (exit status 3; as the code's comment says, a zero size made SURFBC's reflection walk loop for ever). The stops on bad input (semiconvection with overshoot, a non-positive CMIXLA) now exit with status 3, the code for input errors (KNOWN_ISSUES.md, issue 38).

232def _value(token, like):
233    """Convert one namelist value to the type of the variable it sets."""
234
235    if isinstance(like, (bool, np.bool_)):
236        t = token.upper().lstrip('.')
237        return t.startswith('T')
238    if isinstance(like, str):
239        if token[:1] in "'\"":
240            return token[1:-1].replace(token[0] * 2, token[0])
241        return token
242    number = token.replace('d', 'e').replace('D', 'E')
243    if isinstance(like, (int, np.integer)):
244        return int(float(number))
245    return float(number)

248def _fortran_order(shape, start):
249    """The indices of an array (index 0 unused) from `start` on, in
250    Fortran's order: the first index varies fastest."""
251
252    idx = list(start)
253    while True:
254        yield tuple(idx)
255        for d in range(len(idx)):
256            idx[d] += 1
257            if idx[d] < shape[d]:
258                break
259            idx[d] = 1
260        else:
261            return

264def _read_namelist(path, group, members, owners):
265    """READ(UNIT, NML=group): a minimal reader for the namelist files YREC
266    uses (name = values, name(i) = values, repeat counts r*v, quoted
267    strings, logicals, D exponents, '!' comments). Each value is stored
268    where its variable lives."""
269
270    table = {name: (owners[where], name) for where, name in members}
271    with open(path) as f:
272        # Drop '!' comments, outside quoted strings.
273        text = ''.join(re.sub(r"^((?:[^'\"!]|'[^']*'|\"[^\"]*\")*)!.*",
274                              r"\1", line) for line in f)
275    start = re.search(r'[&$]' + group + r'\b', text, re.IGNORECASE)
276    if start is None:
277        raise SystemExit(f"namelist /{group}/ not found in {path}")
278    body = text[start.end():]
279    tokens = re.findall(r"'(?:[^']|'')*'|\"(?:[^\"]|\"\")*\"|"
280                        r"[A-Za-z_]\w*\s*(?:\([^)]*\))?\s*=|/|"
281                        r"[&$]END\b|[^\s,'\"/=]+", body, re.IGNORECASE)
282    target = None
283    for tok in tokens:
284        if tok == '/' or tok.upper().lstrip('&$') == 'END':
285            break
286        if tok.endswith('='):
287            m = re.match(r'(\w+)\s*(?:\(([^)]*)\))?', tok)
288            owner, attr = table[m.group(1).lower()]
289            current = getattr(owner, attr)
290            if m.group(2):
291                first = tuple(int(i) for i in m.group(2).split(','))
292            else:
293                first = None
294            if isinstance(current, np.ndarray):
295                place = _fortran_order(current.shape,
296                                       first or (1,) * current.ndim)
297            elif isinstance(current, list):
298                place = iter(range(first[0] if first else 1, len(current)))
299            else:
300                place = None
301            target = (owner, attr, current, place)
302            continue
303        owner, attr, current, place = target
304        count, _, item = tok.rpartition('*') if re.match(r'\d+\*', tok) \
305            else ('1', '', tok)
306        for _ in range(int(count)):
307            if place is None:
308                setattr(owner, attr, _value(item, current))
309            else:
310                where = next(place)
311                like = current[where]
312                current[where] = _value(item, like)

323def _write_namelist(unit, group, members, owners):
324    """WRITE(UNIT, NML=group): every member with its value (the layout
325    approximates the compiler's)."""
326
327    lines = [f"&{group}"]
328    for where, name in members:
329        v = getattr(owners[where], name)
330        if isinstance(v, np.ndarray):
331            sub = v[(slice(1, None),) * v.ndim].ravel(order='F')
332            text = ', '.join(_format_value(x) for x in sub)
333        elif isinstance(v, list):
334            text = ', '.join(_format_value(x) for x in v[1:])
335        else:
336            text = _format_value(v)
337        lines.append(f" {name.upper()}={text},")
338    lines.append("/")
339    iounits_mod.write(unit, "\n".join(lines))
