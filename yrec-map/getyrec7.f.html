Purpose

GETYREC7 reads a stellar model stored in the older YREC7 text format ("llp 4/16/03"; its header calls it GETY7) into memory. Since the YREC7 format lacks the physics flags of the newer Model2 format, it sets those to defaults ("?" strings, false flags).

How it fits

  • Who calls it: only STARIN, when the input model's first record starts with NMOD; Model2 files (MOD2) go to GETMODEL2, which returns the same arguments.
  • Who writes the format: PUTYREC7 (its formats match these), which nothing calls; so YREC7 files now come only from older codes.
  • Input: the file on unit IREAD, rewound before and after; ISHORT, the unit of its error messages (lines 140–141↗, line 249↗), so that, unlike in GETMODEL2, this argument is used.
  • Outputs (arguments): the header (MODEL, M, SMASS, TEFFL, BL, HSTOT, DAGE, DDAGE), LROT, LEXCOM, JCORE, JENV, CMIXL, the luminosities TLUMX (converted to solar units if above $10^{20}$), the envelope triangle (TRIT, TRIL, PS, TS, RS, CFENV, FTRI), the shells (HS, HR, HL, HP, HT, HD, LC), HCOMP and OMEGA; plus the Model2-only items, set to defaults: the strings ATM, EOS, HIK, ALOK = "?," COMPMIX = "AG93," all flags false, PDISK = 7.2722×10$^{-6}$ rad s$^{-1}$ (a 10-day period), TDISK = 0, WMAX = 3×10$^{-4}$ (lines 86–89↗). These three do not change the run's physics: STARIN receives them in its locals PDISK0, TDISK0, WMAX0 (starin.f, lines 280–285↗), which it never reads (unused?), and the namelist's PDISK, TDISK, WMAX are untouched (settled from the code, Nov 9, 2026).
  • Modules: CONSTANTS_MOD (formerly /CONST/), for $L_\odot$.

The format, as read.

  1. Each shell stores $X$ and $Z$ as integers in units of $10^{-6}$; $Y = 1 - X - Z - X(^3\mathrm{He})$ is recomputed. The run stops (exit status 3, an input error) if a shell's $\log m$ is negative or above the total.

    Question 1 (lines 148–149↗). Precision of $X$ and $Z$. The format keeps $X$ and $Z$ to $10^{-6}$. Is that enough when models with diffusion are restarted from this format?

  2. The other species (rows 4–11) are stored only from JCORE to JENV, the region between the convective core and envelope, and copied into the homogeneous core and envelope. With LEXCOM, the light elements (rows 12–15) follow the same pattern, two shells per record.

  3. With LROT, $\Omega$ is stored as $-\log_{10}\Omega$; values of 58.9 or more mean $\Omega = 0$. If those records are missing, $\Omega$ is set to zero with a message.

Suspected bugs, checked by running the code

Each bug is marked by what running the code showed: (changes results, large) or (small), the fix moving a run clearly beyond a null change; (stops the run); (wrong output), the fix changing only what is written; (harmless in the runs), within the noise; (never occurred), the code ran but the fault did not; (not reached); (cannot be reached), a guard prevents it; (withdrawn), the suspicion was wrong.

1. (not reached) The flags record is read one column late.

(lines 104–105↗; putyrec7.f, lines 65–66↗) PUTYREC7 writes the record as 2(L1,1X),'F F ',2I4,F7.3, four characters between the flags and JCORE, and the YREC7 starting models in startmodels/seed/ have the same layout (F T F F 1 1 1.735); GETYREC7 reads it as 2(L1,1X),5X,2I4,F7.3, skipping five. Each field is then read one column late: JCORE from columns 10–13, which hold its last three digits and the first column of JENV; JENV from columns 14–17, its last three digits and the first column of CMIXL. With blanks ignored, the values come out right while JCORE and JENV are below 1000 (all 41 YREC7 files in the repository have at most 391 shells); with a four-digit JENV (M may reach JSON = 5000) its first digit is appended to JCORE and lost from JENV.

10def _fields(line, spec):
11    """Read one record by a FORMAT, given as (kind, width[, decimals])
12    items: 'a' text, 'i' integer, 'f' real (F or E), 'l' logical, 'x'
13    skipped. Blanks inside numbers are ignored and a blank field reads as
14    0, as Fortran does by default; a real without a decimal point has its
15    last `decimals` digits taken as decimals. (The 1P scale factor of the
16    FORMATs only matters for fields without an exponent, and is not
17    applied.)"""
18
19    out, pos = [], 0
20    for item in spec:
21        kind, w = item[0], item[1]
22        text = line[pos:pos + w]
23        pos += w
24        if kind == 'x':
25            continue
26        if kind == 'a':
27            out.append(text.ljust(w))
28            continue
29        t = text.replace(' ', '')
30        if kind == 'l':
31            t = t.lstrip('.')
32            out.append(t[:1].upper() == 'T')
33        elif kind == 'i':
34            out.append(int(t) if t else 0)
35        else:
36            t = t.upper().replace('D', 'E')
37            if not t:
38                out.append(0.0)
39                continue
40            mant, sep, expo = t.partition('E')
41            value = float(mant)
42            if '.' not in mant:
43                value = value / 10.0 ** item[2]
44            if sep:
45                value = value * 10.0 ** int(expo)
46            out.append(value)
47    return out

50def _read_values(unit, n, spec):
51    """Read n values with a FORMAT that is reused for further records
52    (Fortran's format reversion); None at the end of the file."""
53
54    values = []
55    while len(values) < n:
56        line = iounits_mod.read(unit)
57        if line is None:
58            return None
59        values += _fields(line, spec)
60    return values[:n]
