Purpose

Reads the low-temperature opacity tables of Ferguson et al. (2005, ApJ 623, 585), called the "Alexander 2006" tables in the code, for all compositions at once.

How it fits

  • Who calls it: SETUPOPAC, when LALEX06 is true.
  • Input: the formatted file FALEX06 (its name passed through SETUPOPAC since the change "MHP 8/25"), opened on unit IALEX06 from IOUNITS_MOD (set in PARMIN).
  • Outputs, through modules:
  • ALOT06ALL_MOD: CAPTALEX06(143, 85, 19), all tables, read by ALEX06TAB;
  • GALOT06_MOD: the grids TGR06 ($\log T$), XXG06 ($X$), R0GR06 ($\log R$), ZZG06 ($Z$), initialized in the module itself and read here (to check the tables) and by ALEX06TAB and GETALEX06;
  • ALOT06_MOD: the table for one composition, CAPALEX06(85, 19), initialized here to the first table ($X = 0$, $Z = 0$), and the composition and starting indices (XE, ZE, IX, IT, ID, initialized in the module). ALEX06TAB rebuilds it for the envelope's composition, and GETALEX06 interpolates in it.

The tables. From the header comments: $X$ = 0, 0.1, 0.2, 0.35, 0.5, 0.7, 0.8, 0.9 and $1-Z$; 16 values of $Z$ from 0 to 0.1; 85 values of $\log T$ from 2.7 to 4.5 (0.05 dex steps, 0.01 dex between 2.9 and 3.5); 19 values of $\log R$ from $-8$ to 1, with

$$R = \frac{\rho}{T_6^{\,3}} .$$

The tables at $X = 1-Z$ exist for 15 values of $Z$ only (none for $Z = 0.1$), so there are $8 \times 16 + 15 = 143$ compositions (NUMXZ), stored at index $(i_X - 1)\cdot 16 + i_Z$ (line 82↗; line 121↗).

Question 1 (lines 58–61↗; lines 101–104↗). Stale comment. The comment on the storage index, repeated in both loops, speaks of "15 sets of metal abundance with 7 sets of hydrogen", while the code reads 16 values of $Z$ and 9 of $X$ (the ninth at $X = 1-Z$, with 15 tables). Should it be brought up to date?

The method

For each composition, the routine reads the header ($X$, $Z$) and checks it against the grid; reads the $\log R$ row and checks it; then reads the 85 temperature rows in descending order of $T$, checking each $\log T$ against TGR06. A mismatch prints an error (to the terminal only) and stops the run with exit status 3, the code for input errors, except for the check of $X$ and $Z$ in the first loop, whose STOP is commented out (bug 1).

Question 2 (lines 73–74↗; lines 114–115↗). Only 16 of 19 densities checked. Both loops check R0GRTAB(KK) for KK = 1, 16, not up to NUMD = 19, so the last three values of $\log R$ (0, 0.5, 1) are read but not checked. Is that on purpose (for example, for tables whose last columns differ), or should the loop run to NUMD? The $\log R$ rows of alexmol06gs98.tab would show whether the full check passes.

Question 3 (line 65↗; line 74↗; line 88↗; line 108↗; line 115↗; line 126↗). Exact comparisons of reals. The checks compare values read with F9.6, F7.3 or F5.3 against the grids' literals with .NE.. This works when the decimal strings in the file read to the same binary numbers as the literals (they do for values written with these formats, such as 0.350000 or -7.500), but a table written with a slightly different rounding would stop the run. Should the checks use a tolerance, such as $10^{-6}$?

Suspected bugs, by priority

(a) may give wrong results; (b) may crash; (c) misbehaves silently (a wrong message, an ignored setting); (d) fragile: correct today, but breaks on a change or an unusual input.

(lines 63–70↗) In the first loop (the eight values of $X$ below $1-Z$), the STOP after a mismatch of the header's $X$ or $Z$ is commented out (line 69), so the run goes on after printing "RUN STOPPED", and the table is stored under the composition the grid expects.
