Purpose

This file calibrates a track of another star (not the Sun) to a given radius and luminosity: it watches the track for the moment it crosses the target radius $R_*$, compares the luminosity there with the target $L_*$, and adjusts the hydrogen abundance $X$ (thus $Y$) for the next run until the track passes through $(R_*, L_*)$. Then it sets up a final run that stops at the age where the track reaches $R_*$.

How it fits

  • Inputs: the arguments BL ($\log L/L_\odot$), TEFFL ($\log T_\mathrm{eff}$), DAGE (age, Gyr), NK (kind card) and ALRI (the previous model's radius, kept by the main program and started by SETSCAL); in NMLPAR_MOD (set by PARMIN), the targets SR ($R_*/R_\odot$; computed by SETSCAL from STEFF when the option LTEFF gives the star's $T_\mathrm{eff}$ instead, so this routine needs only SR, settled from the code, Nov 9, 2026: lines 102–106↗), XLS ($L_*/L_\odot$) and the tolerance XLSTOL; the previous model's BLI, AGEI, local variables kept by SAVE.
  • Who calls it: the main program (main.f), for even kind cards, when the option LCALST is on and the star has not yet been found (LSTAR false), from the second model on (lines 1117–1123↗; the first model only sets TEFFI, which nothing reads: unused?).
  • Outputs: the arguments LPASSR (main.f then ends the run), LSTAR and ALRI; BLR, AGER, BLRP are saved locals; for the next kind cards, the new $X$ (RESCAL(2,·) in RUNLOOP_MOD, XENV0A in NMLPAR_MOD), or the stopping age (LENDAG in RUNLOOP_MOD, ENDAGE in NMLPAR_MOD). Lines to the screen and to ITRACK.

The method

  1. The radius from $L$ and $T_\mathrm{eff}$, in solar units: $$\frac{R}{R_\odot} = \frac{\sqrt{L/(4\pi\sigma)}}{T_\mathrm{eff}^2\,R_\odot}.$$ If the track has not crossed $R_*$ since the previous model, store $L$, the age and $R$, and return.

    Question 1 (lines 81–82↗; line 96↗). Linear or log radius. The comments call ALR and ALRI "log(R/Rsun)", but the code computes $R/R_\odot$ itself; SR is described as $R/R_\odot$, so the comparison is consistent and the interpolation is linear in $R$. Can the comments say $R/R_\odot$?

    Question 2 (lines 97–117↗). The first crossing only. The comment "Check if track has passed through Teff the right number of times" has no code behind it: The first crossing of $R_*$ (in either direction) is used. For tracks that cross $R_*$ more than once (pre-main sequence, then main sequence), is the first crossing the right one? 2. At the crossing, interpolate linearly in $R$ between the two models for $\log L$ and the age at $R_*$. 3. If $|L/L_\odot - L_*/L_\odot| \le$ XLSTOL, the star is found: the next two kind cards run with the same $X$ and stop at that age (in years, $10^9 \times$ Gyr). The test is in linear units, so XLSTOL is in $L_\odot$, while the secant step below works in $\log L$ (settled from the code, Nov 9, 2026: line 128↗, line 168↗). 4. Otherwise, at the first pass (NK = 2) lower $X$ by 0.01 ("Y=Y+0.01"); afterwards take a secant step in $X$ against $\log L$: $$X_\mathrm{new} = X + \frac{X - X_\mathrm{prev}}{\log L_R - \log L_{R,\mathrm{prev}}}\,\left(\log L_* - \log L_R\right).$$

Suspected bugs, by priority

(a) may give wrong results; (b) may crash; (c) misbehaves silently (a wrong message, an ignored setting); (d) fragile: correct today, but breaks on a change or an unusual input.

  1. (a) A false crossing at the start of a run that begins above $R_*$. (lines 97–103↗; line 107↗; lines 1119–1123↗) ALRI starts at 0 (line 107↗) and is not updated at a crossing (lines 118–178↗ leave it as it was), and main.f's first call of each run is at its second model (the first only sets TEFFI). If that model's radius is above $R_*$ (a pre-main-sequence start with $R_*$ on the main sequence, say), the test ALR.GT.SR.AND.ALRI.LE.SR (line 98↗) holds at once: LPASSR ends the run at its second model, and $L$ and the age "at $R_*$" are interpolated between this model and BLI, AGEI, which are unset in the first run (saved locals with no DATA). Since ALRI stays 0, every later run stops the same way, and the secant step works on these values. When the track starts below $R_*$, the first comparison of each later run is made against the previous run's last stored model rather than the run's own, which is harmless as long as every run starts on the same side of $R_*$. Only with LCALST (off by default, line 160↗) and a track that starts above $R_*$; a track that starts below $R_*$ and expands through it is not affected. Read from the code, not run.
