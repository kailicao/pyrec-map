Explanation

Purpose. INTPAR_MOD holds the settings of the Bulirsch–Stoer integration of the atmosphere and envelope, shared by PARMIN, ENVINT and BSSTEP. It replaces COMMON/INTPAR/ (MHP via Claude, 10/14/26), the first of the conversion's DATA migrations: the three defaults come from PARMIN's DATA STOLR0,IMAX,NUSE/1.0D-3,11,7/.

What its variables hold, who sets them, who reads them. All three are in the PHYSICS namelist read by PARMIN, so a run can change them; no routine assigns them.

  • STOLR0 (REAL*8, 1.0D-3): the integration tolerance. ENVINT uses it as such for the atmosphere and scales it by $|$SENV$|$ for the envelope.
  • IMAX (INTEGER*4, 11): the largest number of step subdivisions BSSTEP tries.
  • NUSE (INTEGER*4, 7): the number of points used in BSSTEP's extrapolation to zero step (passed to RATEXT), and the subdivision count that decides the next step.

Design. A blanket USE INTPAR_MOD.

Changed since rp_1. New file: COMMON/INTPAR/ as a module, with its defaults moved from PARMIN's DATA statement.

Imported with a blanket USE, the convention for the conversion.
All 3 files declared this block identically, so the USE
imports exactly the names the declaration already made global in
each scoping unit and cannot change meaning.

The types restate what the implicit rules supplied: L is
LOGICAL*4, I/J/K/M/N are INTEGER*4, everything else REAL*8.
SAVE is explicit rather than relying on module variables being
implicitly saved, which holds only from Fortran 2008 while ifort
Classic predates it.  That matches COMMON's semantics.

The initializers are the first DATA migration of the conversion.  They
carry over parmin.f's
DATA STOLR0,IMAX,NUSE/1.0D-3,11,7/
which had to move, because DATA on a USE-associated name is rejected
("Cannot change attributes of USE-associated symbol").

The semantics are unchanged.  All three are PHYSICS namelist variables:
the DATA statement supplied the default before the namelist read could
override it, and a module initializer is likewise applied once at load
time, before PARMIN runs.  It is also a standards improvement, since
DATA on a COMMON member outside BLOCK DATA is non-standard.
