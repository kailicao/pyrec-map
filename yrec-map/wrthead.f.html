Purpose

WRTHEAD writes the header lines of the output files at the start of each run of a job: a line describing the run in the main output, and the track file's column header.

How it fits

  • Inputs: the arguments, the stellar mass SMASS (solar masses), the mixing length CMIXL and the run index NK; and through modules: the run's kind IRESCA(NK) (RUNLOOP_MOD, formerly CKIND), its number of models NMODLS(NK) and LFIRST(NK) (NMLPAR_MOD, namelist settings), the initial $X$ and $Z$ (XENV0, ZENV0 in LABEL_MOD), the namelist switch LTRACK and the track format's version ITRVER (NMLPAR_MOD, ITRVER 1 by default; read by PARMIN), and the units IOWR, ITRACK (IOUNITS_MOD).
  • Who calls it: the main program, main.f, once per run.
  • Outputs: a line on IOWR ("RUN= … EVOLVE", "RESCALE" or "RESCALE&EVOLVE"); with LTRACK, for a run that reads its starting model (LFIRST(NK)), a version line and the column names on ITRACK. The data lines under these headers are written by WRTOUT, which must match them.

Design

The column names depend on ITRVER: 0, one long line of names (G. Somers 11/14); 1, a description in comment lines (except two lines of format 1505, " Neutrinos …" and ' " " cont: …', which do not start with #); 2, the same plus the rotation columns (whose line, format 1510, does not start with # either); 3, a short list. For ITRVER = 0 the 83 names of format 1504 match, in number and order, the 83 values that WRTOUT writes with format 1499; nothing in the code checks this, and the comment asks that ITRVER change whenever the track file does (lines 89–90↗) (settled from the code, Nov 9, 2026: lines 131–148↗; lines 558–568↗). The headers of versions 1–3 do not match their data (bug 1).

Question 1 (lines 112–114↗; lines 115–131↗). The comment and the active code. For ITRVER = 0, the comment says "Uncomment the following block if desired", but the block that follows is commented out and a second version (format 1504) is active. Which is current, and can the comment and the commented-out format go?

Question 2 (lines 131–148↗). The column line is not a comment. In format 1504, the line of column names does not start with #, unlike the lines around it, so a reader that skips # lines reads it as data. Is it intended, as a header row for readers that take the column names from the file?

For users (from YREC's User Guide). The track file is the run's history, one line per model with ITRVER = 0, the format recommended. The two lines of DESCRIP in the control namelist, the run's description, head the track file too, but PARMIN writes them, before this header.

From YREC's documentation

Control Options: ITRVER chooses the format of the .track file; 0 (one line per model) is strongly recommended, though the default is 1.

Suspected bugs, by priority

(a) may give wrong results; (b) may crash; (c) misbehaves silently (a wrong message, an ignored setting); (d) fragile: correct today, but breaks on a change or an unusual input.

  1. (c) The headers of track versions 1, 2, and 3 do not match the data. (lines 152–176↗; lines 570–641↗) For ITRVER = 1 (the default) and 2, WRTOUT writes for each model: a first line of 14 values whose last five are the base of the convection zone (CZsurf_R, CZsurf_T, CZsurf_D, CZsurf_P, CZsurf_O; lines 570–572↗), which format 1505 does not name; a central line whose ninth value is the total moment of inertia HITOT (lines 573–575↗), not named; a neutrino line of the Cl and Ga rates and 10 fluxes (lines 587–588↗), where the header names 8 fluxes and no rates; and a second surface line of H2, Li6, Li7, Be9, X, Y, Z, and Z/X (lines 591–593↗), where the header names the first four. For version 2 the rotation line has nine values (SJTOT, SKEROT, HITOT, HICZ, Ω at the surface and center, ROTP, ROTV, TAUCZ; lines 632–634↗), where format 1510 names four. For version 3 the tenth value is CZsurf_R (lines 639–641↗), where format 1515 says "% Grav Energy" (the line that computed it is commented out, lines 637–638↗). And three header lines do not start with # (lines 158–159↗; line 164↗; line 171↗), so a reader that skips # lines takes them for data. What follows: a user who reads a track of version 1, 2, or 3 by its header assigns columns wrongly; the run itself is not affected. On by default (LTRACK true and ITRVER 1: line 59↗; line 142↗), though the documentation recommends version 0. Read from the code, not run.
