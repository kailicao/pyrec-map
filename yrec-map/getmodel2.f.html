Purpose

GETMODEL2 reads a stellar model stored in the "Model2" text format ("llp 4/16/03") into memory: the header (model number, mass, $T_\mathrm{eff}$, $L$, age), the physics flags of the run that wrote it, the luminosities by source, the envelope fitting data and the shell-by-shell structure and composition.

How it fits

  • Who calls it: only STARIN, when the first record of the input model starts with MOD2; for the older YREC7 format (NMOD) it calls GETYREC7 instead.
  • Who writes the format: PUTMODEL2 (and the format is mentioned in PUTSTORE and WRTLST).
  • Input: the file on unit IREAD, rewound first.

  • Outputs (arguments): the header values (MODEL, M, SMASS, TEFFL, BL, HSTOT, DAGE, DDAGE); the flags and names of the input physics (EOS, ATM, ALOK, HIK, COMPMIX, LDIFY, LDIFZ, LROT, …, and the disk-locking TDISK, PDISK, WMAX); the luminosities TLUMX (the three pp chains, CNO, helium burning, neutrinos, gravitational; converted to solar units if they exceed $10^{20}$, that is, if they were written in erg s$^{-1}$); the envelope triangle TRIT, TRIL, PS, TS, RS, CFENV and its orientation FTRI (±1: SURFBC flips its sign each time it reflects a corner of the triangle, and uses it in its test of whether ($T_\mathrm{eff}$, $L$) lies inside; PUTMODEL2 writes the record numbers as −1, −2, −3 when it is negative, and GETMODEL2 reads the sign back); and per shell HS, HR, HL, HP, HT, HD, OMEGA, LC and 15 abundances HCOMP.

    Question 1 (lines 75–83↗). Units guessed from size. The luminosities are taken as erg s$^{-1}$ if any exceeds $10^{20}$, else as solar units. Could the format carry the unit instead?

  • Modules: CONSTANTS_MOD (formerly /CONST/), for $L_\odot$ (CLSUN).

1. (never occurred) The number of shells is not checked.

(lines 57–58↗, lines 103–106↗) The header record gives M and, in the same READ, stores HS(M); the loop over the shells then fills HS(1:M) and the other arrays of JSON = 5000 elements. Nothing checks that 1 ≤ M ≤ JSON, so a damaged file, or a model of more than 5000 shells, writes outside the arrays (the default build has no bounds checks, src/Makefile line 132; make devel adds them). A read error or an end of file, which has no END= or ERR=, stops the run with the compiler's run-time message, which does not name the file.

9def _fields(line, spec):
10    """Read one record by a FORMAT, given as (kind, width[, decimals])
11    items: 'a' text, 'i' integer, 'f' real (F or E), 'l' logical, 'x'
12    skipped. Blanks inside numbers are ignored and a blank field reads as
13    0, as Fortran does by default; a real without a decimal point has its
14    last `decimals` digits taken as decimals. (The 1P scale factor of the
15    FORMATs only matters for fields without an exponent, which PUTMODEL2
16    does not write, and is not applied.)"""
17
18    out, pos = [], 0
19    for item in spec:
20        kind, w = item[0], item[1]
21        text = line[pos:pos + w] if line is not None else ''
22        pos += w
23        if kind == 'x':
24            continue
25        if kind == 'a':
26            out.append(text.ljust(w))
27            continue
28        t = text.replace(' ', '')
29        if kind == 'l':
30            t = t.lstrip('.')
31            out.append(t[:1].upper() == 'T')
32        elif kind == 'i':
33            out.append(int(t) if t else 0)
34        else:
35            t = t.upper().replace('D', 'E')
36            if not t:
37                out.append(0.0)
38                continue
39            mant, sep, expo = t.partition('E')
40            value = float(mant)
41            if '.' not in mant:
42                value = value / 10.0 ** item[2]
43            if sep:
44                value = value * 10.0 ** int(expo)
45            out.append(value)
46    return out
