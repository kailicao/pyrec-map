Explanation

Purpose. GETMODEL2 reads a stellar model stored in the "Model2" text format ("llp 4/16/03") into memory: the header (model number, mass, $T_\mathrm{eff}$, $L$, age), the physics flags of the run that wrote it, the luminosities by source, the envelope fitting data and the shell-by-shell structure and composition.

How it fits.

  • Who calls it: only STARIN, when the first record of the input model starts with MOD2; for the older YREC7 format (NMOD) it calls GETYREC7 instead.
  • Who writes the format: PUTMODEL2 (and the format is mentioned in PUTSTORE and WRTLST).
  • Input: the file on unit IREAD, rewound first.
  • Outputs (arguments): the header values (MODEL, M, SMASS, TEFFL, BL, HSTOT, DAGE, DDAGE); the flags and names of the input physics (EOS, ATM, ALOK, HIK, COMPMIX, LDIFY, LDIFZ, LROT, …, and the disk-locking TDISK, PDISK, WMAX); the luminosities TLUMX (the three pp chains, CNO, helium burning, neutrinos, gravitational; converted to solar units if they exceed $10^{20}$, that is, if they were written in erg s$^{-1}$); the envelope triangle TRIT, TRIL, PS, TS, RS, CFENV and its orientation FTRI (±1: SURFBC flips its sign each time it reflects a corner of the triangle, and uses it in its test of whether ($T_\mathrm{eff}$, $L$) lies inside; PUTMODEL2 writes the record numbers as −1, −2, −3 when it is negative, and GETMODEL2 reads the sign back); and per shell HS, HR, HL, HP, HT, HD, OMEGA, LC and 15 abundances HCOMP.
  • Modules: CONSTANTS_MOD (formerly /CONST/), for $L_\odot$ (CLSUN).

KC's changes. The unused argument ISHORT was removed (2025-05-31).

Changed since rp_1. Declarations only: COMMON blocks to modules, IMPLICIT NONE.

Questions for the experts

  1. Units guessed from size. The luminosities are taken as erg s$^{-1}$ if any exceeds $10^{20}$, else as solar units. Could the format carry the unit instead?
  2. No checks. There is no check that M ≤ JSON (5000), although the header record already stores HS(M) as it reads M, nor on read errors. Add them?

Read one record by a FORMAT, given as (kind, width[, decimals])
items: 'a' text, 'i' integer, 'f' real (F or E), 'l' logical, 'x'
skipped. Blanks inside numbers are ignored and a blank field reads as
0, as Fortran does by default; a real without a decimal point has its
last `decimals` digits taken as decimals. (The 1P scale factor of the
FORMATs only matters for fields without an exponent, which PUTMODEL2
does not write, and is not applied.)
8def _fields(line, spec):
9    """Read one record by a FORMAT, given as (kind, width[, decimals])
10    items: 'a' text, 'i' integer, 'f' real (F or E), 'l' logical, 'x'
11    skipped. Blanks inside numbers are ignored and a blank field reads as
12    0, as Fortran does by default; a real without a decimal point has its
13    last `decimals` digits taken as decimals. (The 1P scale factor of the
14    FORMATs only matters for fields without an exponent, which PUTMODEL2
15    does not write, and is not applied.)"""
16    out, pos = [], 0
17    for item in spec:
18        kind, w = item[0], item[1]
19        text = line[pos:pos + w] if line is not None else ''
20        pos += w
21        if kind == 'x':
22            continue
23        if kind == 'a':
24            out.append(text.ljust(w))
25            continue
26        t = text.replace(' ', '')
27        if kind == 'l':
28            t = t.lstrip('.')
29            out.append(t[:1].upper() == 'T')
30        elif kind == 'i':
31            out.append(int(t) if t else 0)
32        else:
33            t = t.upper().replace('D', 'E')
34            if not t:
35                out.append(0.0)
36                continue
37            mant, sep, expo = t.partition('E')
38            value = float(mant)
39            if '.' not in mant:
40                value = value / 10.0 ** item[2]
41            if sep:
42                value = value * 10.0 ** int(expo)
43            out.append(value)
44    return out
Review (round 1)
  1. Question 2 answerable. "What does −1 mean for the fit, and who reads FTRI?" FTRI is the orientation of the envelope triangle: SURFBC sets it to +1 when it starts a triangle and flips its sign each time it reflects a corner (surfbc.f lines 102–119), using it in its test of whether ($T_\mathrm{eff}$, $L$) lies inside. PUTMODEL2 (called by WRTLST) and PUTYREC7 write the record numbers as negative when FTRI < 0 (putmodel2.f line 87), so that the sign survives a restart. Fix: state it under "Outputs" and drop the question.
  2. Missing (question 3). The header record reads HS(M) in the same statement that reads M, so a model with M > JSON writes out of bounds before any shell is read. Fix: add to the question.

Otherwise checked: the formats, the unit test on TLUMX (with $|L_\nu|$), the 15 abundances, the caller (MOD2 in STARIN) and /CONST/.
