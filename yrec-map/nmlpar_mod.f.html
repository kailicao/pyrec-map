Explanation

Purpose. NMLPAR_MOD holds the run's settings that the physics routines read: the 235 members of the CONTROL and PHYSICS namelists (and a few quantities PARMIN derives from them), shared by 103 routines. It replaces COMMON/NMLPAR/ (MHP via Claude, 10/14/26), which had gathered, in two steps, the 35 COMMON blocks whose members were all namelist variables (/ALATM03/, /BURNSCS/ … /WEAK/) and the namelist members of 27 blocks that also held working variables (such as /CTOL/, /DISK/, /DPMIX/, /DEBHU/, /NEWOPAC/, /CWIND/); those blocks keep only their other members, now in their own modules (such as CTOL_MOD). The derivation-only namelist variables went to NMLBYPASS_MOD instead.

What its variables hold, who sets them, who reads them. What each member means, with its default, is on YREC's Control and Physics namelist pages; this page groups the members by topic and says where they go. PARMIN reads the namelists into them (CONTROL from unit ISTAND, PHYSICS from IRUN); 203 members carry initial values, the namelists' defaults, moved from PARMIN's DATA statements. Each member's readers are on the routine pages, and the site's module list names the files that use the module. By topic:

  • Runs and output (CONTROL): the number of runs NUMRUN and, per run (arrays of 50), the models NMODLS, ages ENDAGE, steps SETDT, stopping values END_DCEN, END_XCEN, END_YCEN, compositions XENV0A, ZENV0A, CMIXLA, envelope fitting points LSENV0A, SENV0A, rescalings RSCLZC, RSCLZM1, RSCLZM2, LFIRST; the switch L_ZERODT_PREMS (default false), which lets a rescale card relax a pre-main-sequence model without ageing it (read by the main program); the output switches (LSTORE, LSTATM, LSTENV, LSTMOD, LSTPHYS, LSTROT, LSTCH, LTRACK, LMILNE, LPULSE, LPOUT, ITRVER, IPVER, NPRTMOD, NPRTPT, NPOINT); and the calibration to the Sun or a target (LCALS, LCALST, CALSOLZX, CALSOLAGE, TOLL, TOLR, TOLZ, XLS, XLSTOL, STEFF, SR, LTEFF), which SETCAL, SETSCAL, CHKCAL and CHKSCAL change between runs.
  • Numerics: the Henyey tolerances and iteration limits (HTOLER(5,2), FCORR0, FCORRI, NITER1–NITER4, LCORR), the mesh tolerances HPTTOL(12), the time-step controls ATIME(14), LPTIME, TRIDT, TRIDL, LNEWS, the integration of the atmosphere and envelope (ATMERR, ATMD0, ATMBEG, ATMMIN, ATMMAX, ENV…, ATMSTP, ENVSTP, TENV0, TENV1), the burning network (CMIN, ABSTOL, RELTOL, KEMMAX) and the temperature cuts TCUT(5), TSCUT, TGCUT.
  • Physics: the opacities (LOPAL95, LALEX06, LPUREZ, LCONDOPACP, ZOPAL951, TMOLMIN, TMOLMAX, OPTOL, TOLLAOL, LZRAMP), the equation of state (LOPALE06, LSCV, LNUMDERIV, LDH, ETADH0, ETADH1), the atmosphere (KTTAU, ALATM_FeH, ALATM_Alpha, LALTPTau100, SPOTF, SPOTX, LSDEPTH), nuclear rates (SSTANDARD(17), SLI6…SBE93, WEAKSCREENING, LSNU, LNULOS1), convection and overshoot (DPENV, ALPHAC, ALPHAE, ALPHAM, BETAC, LOVSTC, LOVSTE, LOVSTM, LSEMIC, LADOV, LOVMAX), diffusion and settling (LDIFY, LDIFZ, LDIFLI, LTHOUL, LTHOULFIT, LNEWDIF, FGRY, FGRZ, GRTOL, NITER_GS, DT_GS, XMIN, YMIN, ILAMBDA, CSTMIXING, CSTDIFFMIX), mass loss and accretion (LMDOT, DMDT0, FCZDMDT, FTOTDMDT, COMPACC(15), LREIMER, CREIM, LSOLWIND), the starting composition (VNEW(12), FRAC_C, FRAC_N, FRAC_O, R12_13, R16_18, XH2_INI…XBE9_INI), and the helium flash (LKUTHE).
  • Rotation: the switches LROT, LINSTB, LSOLID, IMPJMOD, LNOJ, LJDOT0, LDIFAD, LVFC, LWNEW, WNEW, WALPCZ, the transport factors (FW, FC, FES, FGSF, FMU, FSS, RCRIT, FESC, FSSC, FGSFC, IES, IGSF, IMU, CODM, LCODM), the diffusion steps (DTWIND, DTDIF, DJOK, ITDIF1, ITDIF2, LEXCOM, LTRIST), the moment of inertia (ACFPFT, ITFP1, ITFP2), disk locking (LDISK, TDISK, PDISK) and the wind laws (WMAX, PMMSOLP, PMMSOLW, PMMSOLTAU, LMWIND, LROSSBY, LBSCALE).
  • Derived by PARMIN (in no input namelist; written in its output-only DERIVED namelist): the wind law's exponents and factor (EXMD, EXW, EXTAU, EXR, EXM, EXL, EXPR, CONSTFACTOR, EXCEN), INEWCP, LREL, KTTAU0, LTTAU, LMIXTURE, LISOTOPE.
  • Changed during a run, despite being inputs: REMAP overwrites HPTTOL, ATIME, LPTIME, DTWIND, DTDIF (with LNEWVARS) and SSTANDARD (with LNEWNUC); the calibration routines the per-run arrays; CALCAD, STITCH, WRTMOD, GETNEWENV and STARIN the integration steps ATM…, ENV…; ENVINT and SURFBC KTTAU, LTTAU, LSTATM; MDOT LMDOT; MIX and ROTMIX LDIFY; CHECKJ ACFPFT (temporarily); STARIN MCORE, FCORE; the main program ITDIF1, LPULSE, END_DCEN, END_YCEN.

Members without an initial value. Where Namelist Variables Live describes the namelists' defaults as the module's initializers; 32 of the 235 members have none. 15 are derived by PARMIN (above); the other 17 are inputs: the per-run XENV0A, ZENV0A, CMIXLA (PARMIN stops the run if a CMIXLA it uses is not positive), the calibration targets XLS, XLSTOL, STEFF, SR, the output switches LSTATM, LSTENV, LSTMOD, LSTPHYS, LSTROT, the Allard atmosphere's ALATM_FeH, ALATM_Alpha, LALTPTau100, and the opacity settings LOPAL95, ZOPAL951. Unless the namelist sets them, they start at whatever the compiler gives a saved variable, in practice zero or false (see question 1). The module's header still counts "202 of the 234 members", from before L_ZERODT_PREMS.

Design. A blanket USE NMLPAR_MOD in each of the 103 routines, so every routine sees all 235 settings; the module makes the namelists global state by design. The header says the initializers' literals are copied verbatim from the DATA statements (single-precision ones such as CSTMIXING = 1.0 included), so that no stored value changes.

Changed since rp_1. New file: the namelist members of 62 COMMON blocks as one module, with their defaults moved from PARMIN's DATA statements.

Changed since 09c3b9b. One new CONTROL member, L_ZERODT_PREMS (now 235 members, 203 with initial values), read in main.f.

Questions for the experts

  1. Inputs without defaults. The 17 input members listed above (among them LOPAL95, which the documentation recommends, and the output switches LSTATM, LSTENV) have no initializer, so an unset one relies on the compiler zeroing static storage, which Fortran does not guarantee. Should they get explicit initializers (.FALSE., 0.0D0), as the documentation's description of the module implies, or are they meant to be required in every namelist?

Imported with a blanket USE, the convention for the conversion.
All 103 files declared this block identically, so the USE imports
exactly the names the declaration already made global in each
scoping unit and cannot change meaning.

The types restate what the implicit rules supplied: L is
LOGICAL*4, I/J/K/M/N are INTEGER*4, everything else REAL*8.
SAVE is explicit rather than relying on module variables being
implicitly saved, which holds only from Fortran 2008 while
ifort Classic predates it.  That matches COMMON's semantics.

202 of the 234 members carry an initializer, migrated
from parmin.f's DATA statements because DATA on a USE-associated
name is rejected.  The literal text is copied verbatim: these
are namelist variables whose DATA supplied a default the
namelist read could override, and a module initializer is
applied once at load time, before PARMIN runs, which is the
same thing.  Rewriting a literal such as 0.9828 as 0.9828D0
would change its stored value, so that is deliberately not
done here; see KNOWN_ISSUES.md issue 23.
