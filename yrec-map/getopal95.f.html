Purpose

GETOPAL95 is the driver for the OPAL 1995 opacity tables ("7/98 MHP"): given $\rho$, $T$, $X$, $Z$, it finds the interpolation stencil and weights in $T$, $R = \rho/T_6^3$, $X$ and $Z$, handles the table's empty corner at high density, and calls a 2D, 3D or 4D interpolator depending on how far the composition is from the tables already prepared.

How it fits

  • Who calls it: only GETOPAC, when LOPAL95 is set (with $Z$ = 0.1 in metal-rich helium-burning cores).
  • Inputs: DL, TL, X, Z.
  • What it calls: INTERP (four-point Lagrange weights with derivative weights, for $T$ and $R$; the file's header speaks of "CUBIC SPLINE INTERPLOATION", which is stale: Settled from the code, Nov 9, 2026: lines 1–2↗, lines 16–18↗), INTRP2 (weights only, for $X$ and $Z$), and one of OP952D (2D, in the table for the surface $X$ and $Z$), OP953D (3D, in the tables for the model's $Z$) or OP954D (4D, in the full set).
  • Outputs: O, OL, QOD, QOT, as from GETOPAC.
  • Modules (COMMON blocks until rp_1): the tables LLOT95A_MOD (the full set CAPPA2, indexed by a combined X–Z table number, and the grids TGR, R0GR, XXG, ZZG; read by LL95TBL), LLOT95_MOD (CAPPA at the model's $Z$, ZTAB, made by OP95ZTAB), LLOT95E_MOD (CAPPAE at the surface $X$, XOP95 (formerly XTAB), made by OP95XTAB); OP95INTERP_MOD, which merges the former /OP95INDX/ (indices), /OP95FACT/ (weights) and /OP95EXT/ (extrapolation flags), shared with the OP95*D routines, $\log R$ now named RHO_T63L (formerly RL, which clashed with the radius elsewhere) and its edge value RHO_T63LL (formerly RLL); ACDPTH_MOD for the flags LADON, LACOUT (acoustic-depth output; shared with CALCAD, ENVINT, WRTOUT); IOUNITS_MOD for ISHORT, the .short file that the stop reports to.

Why three interpolators. SETUPOPAC, through LL95TBL (which calls OP95ZTAB at ZOPAL951) and OP95XTAB (at XENV), interpolates the full table set ahead of time: CAPPA at one $Z$ for every $X$ node, and CAPPAE from it at the surface $X$. Most calls (the envelope, the atmosphere, and the outer convection zone, which share the surface composition) then need only the 2D interpolation in $T$ and $R$; the 3D path is needed where hydrogen burning has changed $X$, and the 4D path where $Z$ differs too, for example after settling or in a helium-burning core.

The method

  1. $\log R = \log\rho - 3(\log T - 6)$ (RHO_T63L). The run stops if $\log T$ is outside the table. Below the smallest $\log R$, the weights are computed at the table edge and the value is extrapolated linearly later (LEXTL).
  2. Stencils in $\log T$ (JT) and $\log R$ (JD), each starting from the last one found.
  3. Empty corner. Values of 9.9 or more mark missing entries. If the stencil's high-density, high-temperature corner is missing, each of the four temperatures gets its own density stencil (LSHIFT), and where even that is outside the data, its weights are computed at the last valid density and the value is extrapolated linearly (LEXH, RLH). The test reads the $X$ table JX(1,1) of the previous call, since the current $X$ stencil is found only later; this does not matter, since every table of a file has the same empty region: the last one to five densities of the temperatures from TGR(58) up, set to 9.999 by LL95TBL, and in the OP files of the recent mixtures also every density above $\log T = 8.0$ (bug 2). For the same reason the search for valid densities stops at the 14th density or above, so the start of a shifted stencil, JD(I) = J - 3, is at least 11 and never zero or negative; in a row with no data it finds nothing, and JD(I) keeps its old value (settled from the code, Nov 9, 2026: lines 177–209↗, lines 140–171↗). At low $X$ and the lowest temperatures (X < 0.2, JT ≤ 5) the comment postpones a check of the low-density, low-temperature empty region to the 2D, 3D or 4D branch, but no branch makes it, and the flag LCHK set there is unused? (lines 162–172↗; bug 1 below).
  4. Which interpolation. If $Z$ is within a relative $10^{-4}$ of the model table's $Z$: 2D if $X$ is within $10^{-4}$ of the surface table's $X$, else 3D in $X$, $T$, $R$. Otherwise 4D. The 4D path is forced when acoustic-depth output is on (LADON and LACOUT, "JVS 04/11").
  5. Missing high-$X$ tables. The $X$ nodes are 0, 0.1, 0.2, 0.35, 0.5, 0.7, 0.8, 0.9, 0.95, 1. For $X \ge 0.8$: if $0.04 \le Z < 0.1$, the $X = 0.95$ table is absent and the stencil is 0.7, 0.8, 0.9 and the last node, set to $1 - Z$; if $Z \ge 0.1$, the last two are absent and the stencil is 0.5, 0.7, 0.8, 0.9. (In 3D the test is on the model table's $Z$, in 4D on each $Z$ node. OP95ZTAB stops the run for $Z > 0.08$, so the 3D case $Z \ge 0.1$ is never reached; the 4D path can still meet the node $Z = 0.1$.)

Suspected bugs, by priority

(a) may give wrong results; (b) may crash; (c) misbehaves silently (a wrong message, an ignored setting); (d) fragile: correct today, but breaks on a change or an unusual input.

  1. (a) LSHIFT and LEXTH left over from the last call. (lines 167–176↗, line 214↗) When X < 0.2 and JT ≤ 5, GOTO 60 jumps past the lines that reset LSHIFT and LEXTH to false, so their values from the previous call (the routine has SAVE) decide the density stencil; on the very first call LSHIFT has no value at all. If the previous call was in the empty corner (LSHIFT true), the density weights are computed on the stencils JD(2..4) and with the flags LEXH of that call, at other temperatures, and the opacity is interpolated or extrapolated from the wrong densities. This needs a hydrogen-poor gas ($X$ < 0.2) at the table's first temperatures, which GETOPAC reaches only in the ramp between TMOLMIN and TMOLMAX (by default $\log T$ = 4.0 to 4.1), so a hydrogen-poor surface; hydrogen-rich runs do not take it. Read from the code, not run. A possible fix:

  2. (a) Empty temperatures in the OP tables above $\log T = 8.0$. (lines 113–131↗, lines 177–209↗; lines 39–67↗) In the OP tables of the recent mixtures (AAG2021zx0.0187.tab, Magg22_met_zx0.0226.tab, Magg22_phot_zx0.0225.tab, and the other AAG21*, Magg22* and Lodders25* files in input/opacity/atomic/op05/), the last four temperatures of every table ($\log T$ = 8.1, 8.3, 8.5, 8.7) hold 9.999 at all densities; GS98.OP17 has data there. From $\log T$ = 7.9 up, the $T$ stencil includes such a row. The empty-corner search finds no valid density in it, so its JD(I) keeps an old value, LEXH(I) is set, and the interpolators take $\log\kappa \approx 9.999$ at that temperature (the extrapolation adds nothing, since the slope of a constant row is zero). Between $\log T$ = 7.9 and 8.0 the Lagrange weight of the empty row is down to about $-0.064$, so $\log\kappa$ is too low by up to about 0.7 (and its $T$ derivative is off); above 8.0, with two or more empty rows in the stencil, the value is meaningless. The run neither stops nor warns, since the range check uses TGR(NUMT) = 8.7. The README of the tables says the hydrogen-burning tables are also required for helium-burning models (input/opacity/atomic/README, line 1), so a run with these tables reaches this path in a helium-burning core, and at the tip of the red giant branch; how much conduction hides it in degenerate cores is not traced. Read from the code and the tables, not run; the test suite uses these tables only in three solar models (Test_solarAAG21_dif, Test_solarM22M_dif, Test_solarM22M_difkur), which stay below this temperature, and GS98.OP17 in the others. A possible fix, a choice for the developers: stop with a message when the stencil's last temperature has no data (CAPPA(JX(1,1),JT+3,1) ≥ 9.9), or switch to another table above $\log T = 8.0$.

  3. (d) The wrong array in the empty-corner search. (lines 193–199↗) The search for valid densities at each temperature tests CAPPA2(IXX,ITT,J), with IXX = JX(1,1), an index into the $X$ tables of CAPPA, while the lines above it test CAPPA. CAPPA2's first index is the combined X–Z table number (LLOT95A_MOD; lines 56–64↗), so IXX picks the $Z = 0$ table with that $X$ index. The result is right today, since every table has the same empty corner (lines 140–171↗); a table set whose empty region depends on the composition would get the stencil of the wrong table. Changed since a8a5950. The stop for $\log T$ outside the table now writes its message to the .short file as well as the terminal (the routine now uses IOUNITS_MOD, for ISHORT), and exits with status 1, the code for run-time errors, instead of a bare STOP (KNOWN_ISSUES.md, issue 38, which this stop prompted).

33def _x_stencil(k, x, zz):
34    """The X stencil JX(K,1..4) and its weights BX(K,1..4) at the Z value zz.
35
36    The same block appears twice in the Fortran: for the 3D path (K = 1,
37    with ZZ = ZTAB, labels 70 and 80) and for each Z node of the 4D path
38    (labels 75 and 85). It is one helper here; the statements are those of
39    the Fortran.
40
41    """
42
43    jx = op95interp_mod.jx
44    xxg = llot95a_mod.xxg
45
46    # Stencil in X (Fortran lines 263–281, 366–384).
47    if x > xxg[jx[k, 1] + 2]:
48        for i in range(jx[k, 1] + 3, NUMX):         # I = JX(K,1)+3, NUMX-1
49            if x < xxg[i]:
50                jx[k, 1] = i - 2
51                break
52        else:
53            jx[k, 1] = NUMX - 3
54    else:
55        for i in range(jx[k, 1] + 1, 1, -1):        # I = JX(K,1)+1, 2, -1
56            if x >= xxg[i]:
57                jx[k, 1] = i - 1
58                break
59        else:
60            jx[k, 1] = 1
61
62    # Check for absent tables at high X (Fortran lines 283–309, 386–412).
63    if zz >= 0.04 and x >= 0.8:
64        if zz < 0.1:
65            # No table 9 (X = 0.95).
66            jx[k, 4] = NUMX
67            jx[k, 3] = NUMX - 2
68            jx[k, 2] = NUMX - 3
69            jx[k, 1] = NUMX - 4
70        else:
71            # No table 9 or table 10.
72            jx[k, 4] = NUMX - 2
73            jx[k, 3] = NUMX - 3
74            jx[k, 2] = NUMX - 4
75            jx[k, 1] = NUMX - 5
76    else:
77        jxx = jx[k, 1] - 1
78        for i in range(1, 5):
79            jx[k, i] = jxx + i
80
81    # X interpolation factors (Fortran lines 311–322, 414–425).
82    for i in range(1, 5):
83        a[i] = xxg[jx[k, i]]
84    if jx[k, 4] == NUMX:
85        a[4] = 1.0 - zz
86    intrp2(a, b, x)
87    for j in range(1, 5):
88        op95interp_mod.bx[k, j] = b[j]

91def getopal95(dl: float, tl: float, x: float, z: float, o: float, ol: float, qod: float, qot: float) -> tuple[float,
92              float, float, float]:
93    """Opacity from the OPAL 1995 tables, given rho, T, X and Z.
94
95    Finds the interpolation stencils and weights in T, R = rho/T6**3, X and
96    Z, handles the tables' empty high-density corner, and calls the 2D, 3D
97    or 4D interpolator.
98
99    Translates: getopal95.f#GETOPAL95 (7be4133)
100
101    Parameters
102    ----------
103    dl, tl : float
104        log10 density and log10 temperature.
105    x, z : float
106        Hydrogen and metal mass fractions.
107    o, ol, qod, qot : float
108        Set here (passed in with any value).
109
110    Returns
111    -------
112    o, ol, qod, qot
113        The opacity, its log10, and dlog(kappa)/dlog(rho) and
114        dlog(kappa)/dlog(T), as from the interpolators.
115
116    """
117
118    global lshift, lchk
119    im = op95interp_mod
120    tgr = llot95a_mod.tgr
121    r0gr = llot95a_mod.r0gr
122    zzg = llot95a_mod.zzg
123    cappa = llot95_mod.cappa
124    cappa2 = llot95a_mod.cappa2
125    jd = im.jd
126    jx = im.jx
127
128    # log R = log rho - 3 (log T - 6), and the check of T (Fortran lines 88–96).
129    im.rho_t63l = dl - 3.0 * (tl - 6.0)
130    if tl < tgr[1] or tl > tgr[NUMT]:
131        text = f" LOG T OF{tl:11.6f}OUT OF OPAL 95 TABLE RANGE"   # format 5
132        print(text)
133        iounits_mod.write(iounits_mod.ishort, text)
134        raise SystemExit(1)    # STOP 1, the run-time error code
135
136    # Extrapolation below the first density of the table? (Fortran lines 99–103.)
137    im.lextl = im.rho_t63l < r0gr[1]
138
139    # Stencil in T, starting from the last one (Fortran lines 113–131).
140    # Suspected bug (see the page): with the OP tables of the recent
141    # mixtures, the stencil reaches empty rows from log T = 7.9 up.
142    if tl >= tgr[im.jt + 2]:
143        for i in range(im.jt + 3, NUMT):
144            if tl < tgr[i]:
145                im.jt = i - 2
146                break                                   # label 10
147        else:
148            im.jt = NUMT - 3
149    else:
150        for i in range(im.jt + 1, 1, -1):
151            if tl > tgr[i]:
152                im.jt = i - 1
153                break                                   # label 20
154        else:
155            im.jt = 1
156    jt = im.jt
157
158    # T interpolation factors (Fortran lines 133–141).
159    for i in range(1, 5):
160        a[i] = tgr[jt + i - 1]
161    interp(a, b, c, tl)
162    for i in range(1, 5):
163        im.bt[i] = b[i]
164        im.btt[i] = c[i]
165
166    # Stencil in R (for the first temperature) (Fortran lines 143–161).
167    if im.rho_t63l >= r0gr[jd[1] + 2]:
168        for i in range(jd[1] + 3, NUMD):
169            if im.rho_t63l < r0gr[i]:
170                jd[1] = i - 2
171                break                                   # label 30
172        else:
173            jd[1] = NUMD - 3
174    else:
175        for i in range(jd[1] + 1, 1, -1):
176            if im.rho_t63l > r0gr[i]:
177                jd[1] = i - 1
178                break                                   # label 40
179        else:
180            jd[1] = 1
181
182    # The empty corner (Fortran lines 167–211). At low X and low T the check is
183    # postponed (and never made): GOTO 60 skips the reset of LSHIFT and LEXTH.
184    if x < 0.2 and jt <= 5:
185        # Suspected bug (see the page): LSHIFT and LEXTH keep their values
186        # from the last call on this path; LCHK is never used.
187        lchk = True
188    else:
189        lchk = False
190        lshift = False
191        im.lexth = False
192        if cappa[jx[1, 1], jt + 3, jd[1] + 3] >= 9.9:
193            lshift = True
194            for k in range(1, 5):
195                if cappa[jx[1, 1], jt + k - 1, jd[1] + 1] >= 9.9:
196                    im.lexth = True
197                    im.lexh[k] = True
198                else:
199                    im.lexh[k] = False
200            # The four nearest densities with data at each temperature.
201            ixx = jx[1, 1]
202            idd = jd[1]
203            for i in range(1, 5):
204                itt = jt + i - 1
205                if cappa[ixx, itt, idd + 3] > 9.9:
206                    for j in range(idd + 2, 0, -1):
207                        # Suspected bug (see the page): CAPPA2 here, CAPPA above.
208                        if cappa2[ixx, itt, j] <= 9.9:
209                            jd[i] = j - 3
210                            idd = j - 3
211                            break                       # label 50
212                else:
213                    jd[i] = idd
214    # label 60
215
216    # Weights in R for each of the four temperatures (Fortran lines 214–250).
217    if not lshift:
218        for i in range(1, 5):
219            a[i] = r0gr[jd[1] + i - 1]
220        if not im.lextl:
221            interp(a, b, c, im.rho_t63l)
222        else:

224            interp(a, b, c, im.rho_t63ll)
225        for j in range(1, 5):
226            jd[j] = jd[1]
227            for i in range(1, 5):
228                im.bd[j, i] = b[i]
229                im.bdd[j, i] = c[i]
230    else:
231        for j in range(1, 5):
232            for i in range(1, 5):
233                a[i] = r0gr[jd[j] + i - 1]
234            # Outside the data: weights at the edge, linear extrapolation
235            # later.
236            if not im.lexh[j]:
237                interp(a, b, c, im.rho_t63l)
238            else:
239                rr = r0gr[jd[j] + 3]
240                interp(a, b, c, rr)
241                im.rlh[j] = rr
242            for i in range(1, 5):
243                im.bd[j, i] = b[i]

246    # 2D, 3D or 4D? The 4D path is forced for acoustic-depth output (JVS 04/11)
247    # (Fortran lines 254–326).
248    if not (acdpth_mod.ladon and acdpth_mod.lacout):
249        ztab = llot95_mod.ztab
250        if abs(z - ztab) / max(ztab, 1.0e-6) <= 1.0e-4:
251            if abs(x - llot95e_mod.xop95) <= 1.0e-4:
252                # 2D in the surface table.
253                o, ol, qod, qot = op952d(o, ol, qod, qot)
254                return o, ol, qod, qot
255            # 3D in the table at fixed Z (X, T, rho).
256            _x_stencil(1, x, ztab)
257            o, ol, qod, qot = op953d(o, ol, qod, qot)
258            return o, ol, qod, qot
259
260    # label 153: 4D in Z, X, T, rho. Nearest tables in Z (Fortran lines 330–361).
261    if z > zzg[im.jz + 2]:
262        for i in range(im.jz + 3, NUMZ):  # up to NUMZ, a typo fixed (mhp 7/12)
263            if z < zzg[i]:
264                im.jz = i - 2
265                break                                   # label 110
266        else:
267            im.jz = NUMZ - 3
268    else:
269        for i in range(im.jz + 1, 1, -1):
270            if z >= zzg[i]:
271                im.jz = i - 1
272                break                                   # label 120
273        else:
274            im.jz = 1
275    im.jz = min(im.jz, NUMZ - 3)  # failsafe: four Z points (mhp 7/12)
276    for i in range(1, 5):
277        a[i] = zzg[im.jz + i - 1]
278    intrp2(a, b, z)
279    for i in range(1, 5):
280        im.bz[i] = b[i]
281
282    # Nearest tables in X at each value of Z, then the 4D interpolation
283    # (Fortran lines 363–427).
284    for k in range(1, 5):
285        _x_stencil(k, x, zzg[im.jz + k - 1])
286    o, ol, qod, qot = op954d(o, ol, qod, qot)
287    return o, ol, qod, qot
