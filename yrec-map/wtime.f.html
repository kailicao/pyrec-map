Purpose

WTIME limits the time step of a rotating model by the change of the angular velocity since the previous model: if $\Omega$ changed by more than the user's fraction DTWIND somewhere (the comment gives a default of 0.08; NMLPAR_MOD initializes it to 10), the step shrinks; if less, it grows. Which value a run uses: DTWIND is a namelist variable of PARMIN, initialized to 10; REMAP replaces it with TIME_DW_GLOBAL (initialized to 0.08 in NMLBYPASS_MOD) only when LNEWVARS is set, and LNEWVARS is .FALSE. by default. A run that sets neither thus has DTWIND = 10, a tenfold change of $\Omega$ in one step, so that rotation almost never limits the step; with LNEWVARS it is 0.08, and it often does.

How it fits

  • Inputs: the previous step DELTS, M, the current OMEGA; through modules, the previous model's rates WOLD (OLDROT_MOD, saved by STARIN and the rotation routines), DTWIND (NMLPAR_MOD, read from the namelist by PARMIN; REMAP may reset it) and the step-change limit ATIME(13) (NMLPAR_MOD).
  • Who calls it: only HTIMER, which takes the smallest of its candidate steps.
  • Outputs: DELTSW, the rotation-based step, and DWMAX, the largest relative change.

The method

The largest relative change over all shells, $$\delta_\mathrm{max} = \max_i \frac{2\,|\Omega_i - \Omega_i^\mathrm{old}|}{\Omega_i + \Omega_i^\mathrm{old}},$$ gives $f = \delta_\mathrm{max}/$DTWIND, limited to $1/a \le f \le a$ with $a$ = ATIME(13) (MHP 10/14), and $\Delta t_\Omega = \Delta t/f$. If nothing changed ($f = 0$), $\Delta t_\Omega = 10^{20}$, so that rotation does not limit the step. The shell of the largest change is found (IWMAX) but not returned or read (unused?). The comment before the limiter, "restrict change in timestep to no more than a factor of ATIME(14)%", describes the commented-out line below it; REMAP now sets ATIME(14) from TIME_DY_TOTAL, a helium-burning limit of YTIME, and the code uses ATIME(13) (settled from the code, Nov 9, 2026: lines 71–77↗; lines 276–277↗).

Suspected bugs, by priority

(a) may give wrong results; (b) may crash; (c) misbehaves silently (a wrong message, an ignored setting); (d) fragile: correct today, but breaks on a change or an unusual input.

  1. (d) 0/0 where $\Omega$ is zero. (lines 53–62↗) The relative change $2|\Omega_i - \Omega_i^\mathrm{old}|/(\Omega_i + \Omega_i^\mathrm{old})$ is 0/0 in a shell where both are zero. In the first shell it makes DWMAX a NaN, and since every comparison with a NaN is false, DWMAX stays NaN, and so do FAC and DELTSW (lines 63–78↗); HTIMER's test DELTSW.LT.1.0D0 does not catch it (line 131↗), and DWMAX goes on to the rotational-mixing routines, which set their number of substeps from it. In any other shell the NaN is skipped. This needs LROT (off by default) and a model with $\Omega = 0$ at the center in two successive models, such as a rotating run started without rotation; with a floating-point trap on invalid operations, the run stops there.
